- 0.11 확정 설계(2026-10-28): 사용자는 추가 제안의 방향을 승인하고 남은 개선을 정리하라고 요청했다. 당시 정면·측면·후면 바로보기와 치수 도식 포커스를 우선 추가하고, 오늘 지면 목차는 후속 탐색 개선, 사용자 등록 옷 사진 아카이브는 장기 확장으로 채택했다. 이후 바로보기는 0.12, 오늘 지면 목차는 0.14에서 취소했다. 상세는 5.10절, 검증은 12.7절, 현재 우선순위와 미구현 항목은 13절이다. 원단 스와치·재질 시각화는 제외하고 기존 디자인·모션은 유지한다.
- 0.12 범위 조정(2026-10-28): 사용자 요청으로 **정면·측면·후면 바로보기는 추가 범위에서 제외**한다. 기존 회전·확대·초기화는 그대로 유지한다. **화면·번역의 전체 검수와 출시 자료는 후순위**로 옮기고, 전환 최적화·기능 안정성·실제 날씨 검증을 우선한다. 기존 현지화 기능을 제거하거나 이번 변경에 직접 관련된 기본 회귀 확인을 생략한다는 뜻은 아니다.
- 0.13 구현(2026-10-28): 사용자 실행 승인에 따라 0.10의 핵심 전환 경로를 구현했다. 오늘·피팅룸은 준비된 신체·착장·네이티브 geometry를 재사용하고, 내 체형은 별도 준비 상태를 유지하면서 주 메뉴의 `SCNView` 하나를 공유한다. 신체 변형·법선·충돌 데이터 준비는 기존 actor로 옮기고 비동기 메시 생성을 사용한다. 실제 120ms 이상 대기에서만 다음 지면 예고를 표시하며 완료·취소·실패 시 해제한다. 기존 모션 상수·구도는 유지했다. 단위 테스트 28건과 메인 UI 여정 1건이 통과했으며, 검증 범위와 남은 실측은 12.6절에 구분한다.
- 0.14 범위 조정(2026-10-28): 사용자가 **오늘 지면 목차를 취소**했다. 구현 전 조사 단계에서 중단했으므로 추가된 앱 코드나 UI는 없다. 후순위로 남기지 않고 추가 범위에서 제외하며, 기존 스크롤·주 메뉴·디자인·모션은 유지한다.
- 0.15 구현(2026-10-28): 사용자가 후순위 항목을 제외한 안정화·날씨·치수 포커스를 승인했다. 메모리 경고에서 현재 장면은 유지하고 비활성 상태·분리된 네이티브 장면·계산 캐시를 해제한다. 좁은 화면 치수 편집은 시스템 sheet, 넓은 화면은 inspector로 분리하고 입력칸 여백 터치에도 포커스를 연결했다. 위치 요청은 사용자 입력으로만 시작하며 15초 위치 수신 제한·실패·재시도·권한 변경을 처리한다. 날씨는 최신 요청만 반영하고 실패 시 샘플 또는 마지막 수신값임을 구분하며 WeatherKit entitlement를 연결했다. 치수 도식 번호와 항목의 임시 선택을 양방향으로 연결했다. 고유 단위 55건·핵심 UI 여정 4건이 집중 실행에서 통과했다. 실기기는 연결되어 있었지만 사용자가 시뮬레이터만 선택했으므로 설치·실행·실제 날씨 수신·발열·햅틱 측정은 하지 않았다.
- 근거: 사용자가 공유한 디자인 레퍼런스와 매거진 UI/UX·모션 프롬프트, [현재 제품 개요](../README.md), 현재 화면·상태 관리 코드

## 0.16 현재 구현 · 조작하는 피팅 매거진

사용자가 2026-10-28 기존 버전의 확실한 백업을 전제로 **과감한 전체 디자인·모션 변경과 즉시 적용**을 승인했다. 0.10~0.15의 "기존 구도·모션 상수 보존"은 당시 전환 최적화의 경계였으며, 이번 재디자인을 금지하는 조건이 아니다. 아래 0.16 구현과 7·9절의 최신 수치를 우선하고 이전 버전의 구도·순서·수치는 변경 이력으로 읽는다.

- **복구 기준:** 저장소 밖 `Weashion-backups/2026-10-28_214851_pre-fitting-redesign`에 `.git`·미커밋·미추적·무시 파일을 포함한 전체 백업을 보관한다. 독립 복원 사본에서 3,779개 항목의 경로·파일 해시·메타데이터와 Git 상태를 대조했다. 한글 파일명 정규화 복구 도구와 [복원 안내](../../Weashion-backups/2026-10-28_214851_pre-fitting-redesign/RESTORE.md)를 포함하며 이번 작업으로 백업을 덮어쓰지 않는다. 같은 Mac의 로컬 백업이며 외장 매체 이중화는 아니다.
- **오늘:** 마네킹 뒤 큰 WEASHION 제호와 네 가지 날씨 판은 유지한다. 순서는 **조작형 표지 → 상품·S/M/L·미착용·치수 입력·피팅룸 CTA → 사이즈 노트 → 상세 날씨**다. 일반 글씨의 보통 세로 iPhone에서는 핵심 조작을 첫 화면에 두고, 큰 글씨·낮은 화면은 스크롤로 접근한다. 기온·상태·샘플/수신·체형 메타는 일반 글씨에서 표지 위에, 접근성 글씨에서는 표지 아래의 자연 높이 흐름에 배치해 모델을 덮거나 문구를 잘라내지 않는다. 큰 글씨의 상품 행에서는 장식용 영문 아이브로우를 생략한다.
- **피팅룸:** `Fit study.` 아래 상품·사이즈와 이전 선택 대비 총장·어깨너비·가슴단면의 입력 차이를 모은다. 일반 글씨의 비교 전 안내와 비교값 영역은 최소 104pt를 확보해 상태 교체가 마네킹을 밀지 않게 한다. 넓은 화면은 장면과 조작·치수 정보를 좌우로, 접근성 글씨는 세로로 배치한다. 측정 도식·근사값 한계·실패 안내는 유지한다.
- **디자인 시스템:** 잉크색 내비게이션과 버건디 선택면, 작은 모노 메타, 굵은 기능 산세리프와 큰 세리프 숫자의 대비를 강화했다. 내 체형·두 보관함·편집·설정·최초 설정에도 같은 위계를 적용한다. 스튜디오는 희미한 W·바닥 그림자·모서리 표시로 정리하며 렌더 표면을 복제하지 않는다.
- **모션·상태:** 제목 640ms/줄 간격 80ms, 제호 진입 800ms, 헤더 스윕 440ms, 사이즈 글자 280ms다. 버튼 100ms·0.97배, 선택 220ms, 피드백 160ms와 동작 줄이기 정책은 유지한다. 준비 중 이전 지면의 조작은 막되 주 메뉴의 최신 선택은 계속 받는다. 실제 표시 지면을 별도 접근성 식별자로 구분하며 애니메이션 종료를 기능 실행 조건으로 삼지 않는다.
- **보존 경계:** 신체·의류 계산, 메시 자산, 저장 형식·ID, 준비된 장면과 오늘↔피팅룸 시점 공유는 바꾸지 않는다. 실제 상품 복원·구매 사이즈 정답·착용 가능성을 보장하는 표현은 추가하지 않는다. 새 기능 문구 세 가지는 한국어·영어·일본어를 함께 제공한다.
- **검증 구분:** 수정한 레이아웃·대비·저장 모델·날씨 상태의 고유 단위 55건과 관련 UI 10건이 집중 실행에서 통과했다. 표지의 첫 화면 조작/실제 M·L/체형 복원, 두 보관함 연결, 시점/측정 포커스, 조작바, 입력/저장/취소/재실행/사용자 사이즈, 저장 안내, 가로 2열, 최대 접근성 글씨의 메타 분리와 편집을 확인했다. 같은 사례의 재실행과 과거 버전 수는 합산하지 않는다. 직접 확인 화면·보완 내용·남은 실측은 [작업 현황의 0.16 기록](progress-2026-10-27.md)을 기준으로 읽는다.

## 사용자 확정 디자인 기준 · 2026-10-28

사용자는 0.9의 매거진 감각을 긍정적으로 평가한 뒤, 0.16에서 피팅 기능이 더 드러나도록 전체 구도·모션을 적극적으로 바꾸는 것을 승인했다. 다음 기준은 현재 승인 범위이며 0.9의 모든 배치·시간값을 동결한다는 뜻은 아니다.

- **과감한 비대칭 매거진 구도:** 큰 타이포그래피, 크롭, 겹침, 세로 제목과 비대칭 여백을 유지한다. 무난한 카드·대시보드 UI로 되돌리지 않는다.
- **브랜드를 남기는 개편:** 마네킹 뒤 큰 WEASHION 제호와 서체의 역할은 유지하되 상품·사이즈·비교 행동이 가까워지도록 구도를 바꿀 수 있다. 버건디 선택면과 잉크색 내비게이션으로 대비를 강화하고 대부분의 지면은 종이색으로 남긴다.
- **확실히 체감되는 모션:** 진입·스크롤·선택의 움직임을 눈에 띄지 않을 정도로 약하게 되돌리지 않는다. 0.16에서는 강한 진입과 짧은 반복 비교의 리듬을 구분하며 후속 요소는 실제 노출 시점에 시작한다.
- **조작을 방해하지 않는 연출:** 입력·선택·저장을 애니메이션 완료까지 기다리게 하지 않는다. 위치·투명도·배율·마스크 등 국소적인 2D 연출을 우선하고, 장식 때문에 3D 렌더러를 복제하거나 장면 캡처·메시 재계산을 추가하지 않는다. 실기기 프레임 성능은 별도로 측정한다.
- **후속 변경의 기준:** 이번 전체 개편은 명시적으로 승인됐다. 이후에도 피팅 중심과 매거진 감각을 기준으로 개선하며 새로운 레퍼런스나 일반적인 UI 관행만으로 무난한 대시보드로 되돌리지 않는다.
- **전환 지연 개선의 경계:** 0.10은 기존 연출을 단축하거나 교체하는 재디자인이 아니다. 실제 준비 비용은 재사용·비동기 계산으로 줄이고, 남는 대기에만 작은 다음 지면 예고를 더한다. 보조 연출을 보여주기 위한 인위적인 최소 대기 시간은 두지 않는다.
- **재질 시각화 제외:** 사용자는 재질명만으로 실제 원단·착용감을 재현하기 어렵다는 설명 후 재질 표시 제안을 제외했다. 제안한 원단 스와치와 선택 재질에 따른 3D 텍스처·재질감 표현은 추가하지 않는다. 기존 의류 렌더링과 날씨 추천용 재질·두께 입력, 저장 및 텍스트 안내는 유지하며 실제 원단이 마네킹에 재현된다고 암시하지 않는다.
- **추가 확정 방향:** 치수 포커스는 유지하고 실제 옷 사진은 장기 확장으로 남긴다. 조작 위계는 개편하되 장면 복제나 미요청 기능 확장으로 구현하지 않는다. 정면·측면·후면 바로보기·오늘 지면 목차·원단 스와치/재질 시각화는 제외한다.
- **현재 우선순위:** 피팅 중심의 새 화면과 직접 관련된 입력·저장·취소·복원·시점·반응형을 확인한다. 실기기 사용은 사용자 선택으로 보류하며 전체 언어/반응형 검수·출시 자료도 후순위다. 기존 날씨·언어·저장 동작은 보존한다.

## 1. 문서 해석과 범위

### 1.1 상태 구분

| 표기 | 의미 |
| --- | --- |
| 유지 원칙 | 사용자가 정한 제품 컨셉과 기존 동작 중 디자인 변경으로 훼손하면 안 되는 조건 |
| 현재 구현 | 이번 승인 범위에서 코드에 반영한 상태. 실기기 시각·동작·성능 검증을 의미하지 않는다. |
| 개선 제안 | 아직 적용하지 않았거나 기기 관찰로 조정할 방향. 현재 구현과 구분한다. |
| 별도 승인 | 제품 기능·데이터 구조·자산 도입 등에 영향을 주므로 이 문서만으로 구현하지 않는 항목 |

아래의 크기, 간격, 시간, easing, 성능 목표는 별도 표시가 없으면 **개선 제안**이다. 이를 기존 구현값이나 이미 측정한 결과로 해석하지 않는다.

### 1.2 이번 방향에 포함하는 것

- 매거진다운 시각적 위계와 비대칭 지면 구성
- 동일한 개인 마네킹을 중심으로 하는 피팅·치수 경험
- 한글과 영문의 역할을 구분한 타이포그래피
- 사용자의 행동과 콘텐츠 관계를 설명하는 모션
- 작은 창, 큰 글씨, 키보드, 접근성 설정에서도 유지되는 기능 구조
- 상태·오류 표현과 실기기 확인 기준
- 최초 개인 체형 설정, 여러 체형의 보관과 활성 체형 하나의 선택
- 상품과 상품별 사이즈의 분리 저장, 기존 기록 이전, 현재 반팔 피팅과의 연결

### 1.3 자동으로 포함하지 않는 것

- 뉴스·기사 피드, CMS, 작가·구독·댓글 시스템
- 좋아요, 북마크, 비교 이력, 계정·클라우드 동기화
- 상품 URL에서 이미지·사이즈표·디자인을 자동 수집하는 기능
- 외부 이미지에서 의류 메시를 생성하거나 실제 상품을 복원하는 기능
- 구매 사이즈 추천 점수, 착용 가능 판정, 원단 물성의 정확성 보장
- 새로운 촬영 이미지, 유료 폰트, 외부 이미지 서비스 도입
- 긴팔·아우터·바지의 실제 피팅, 여러 겹 착장, 새로운 치수 변형·충돌 계산

원본 프롬프트의 기사·좋아요·북마크는 인터랙션 예시로 해석한다. WEASHION을 기사 앱이나 쇼핑몰로 바꾸라는 기능 요구로 확대하지 않는다. 실제 SwiftUI 구현은 11절의 소스에 연결한다. 컴파일한 코드를 실기기에서 동작 확인한 데모처럼 설명하지 않는다.

## 2. 제품 원칙과 시각적 방향

### 2.1 디자인이 지켜야 할 제품의 중심

1. **주인공은 사용자 자신의 한 마네킹이다.** 여러 모델을 나열하는 일반 패션 피드가 아니다.
2. **사이즈 비교 중 몸은 유지하고 옷의 치수를 바꾼다.** 몸이 옷에 맞춰 바뀌거나 연출 때문에 달라 보이지 않아야 한다.
3. **입력 치수와 착장 후 근사 결과를 구분한다.** 도식, 숫자, 3D 결과가 서로 다른 의미를 갖는다는 것을 설명한다.
4. **날씨는 피팅을 보완한다.** 날씨 연결 없이도 개인 마네킹과 상품 치수 기능을 사용할 수 있어야 한다.
5. **실제 데이터와 샘플을 구분한다.** 미연결 날씨, 샘플 의류, 직접 입력값, 추정 소재, 미적용 초안을 명시한다.
6. **장식보다 조작과 오류 안내가 우선이다.** 버튼·입력·경고를 숨기는 연출을 사용하지 않는다.
7. **마네킹의 동일성과 저장 의미를 보존한다.** 화면 연출만으로 체형·상품·저장값이 달라지지 않는다.

### 2.2 세 가지 디자인 방향의 역할

| 방향 | 적용 영역 | 구체적인 표현 | 제한 |
| --- | --- | --- | --- |
| High Fashion Editorial | 앱 전체의 기본 인상 | 큰 세리프·명조 제목, 여백, 직각 프레임, 정돈된 캡션 | 모든 섹션을 대형 표지로 만들지 않는다. |
| Avant-Garde Editorial | 메인 표지와 주요 지면 | 비대칭 정렬, 컷아웃 도식, 이미지와 제목의 제한적 겹침, 엇갈린 열 | 입력 필드·내비게이션·측정 숫자에는 실험적 배치를 강요하지 않는다. |
| Minimal Luxury | 기능·상태·반복 조작 | 제한된 색, 얇은 선, 작은 선택 피드백, 명확한 문구 | 정보까지 지나치게 작고 흐리게 만들지 않는다. |

**표지는 감상하게, 피팅룸은 비교하게, 편집 화면은 정확하게 입력하게 한다.**

화면마다 감상과 조작의 비중은 달라도 색·서체·정렬·캡션의 문법은 공유한다. 모든 화면을 똑같은 카드 배열로 통일하지 않는다.

### 2.3 레퍼런스에서 가져올 것과 가져오지 않을 것

| 레퍼런스 | 가져올 편집 원리 | 가져오지 않을 요소 |
| --- | --- | --- |
| Ralph Lauren 진입 화면 | 절제된 분위기, 화면을 채우는 배경, 하단 카피와 CTA, 간결한 진행 표시 | 로고·사진·문구·브랜드 자산, 불필요한 계정·쇼핑 구조 |
| Opal 메인 구성 | 중앙 피사체와 주변 정보, 주요 행동과 하단 내비게이션의 관계 | 둥근 카드·알약 버튼을 그대로 복제하는 외형 |
| 날씨 뒤의 개인 마네킹 구성 | 날씨와 오늘의 실루엣을 같은 장면으로 인식하게 하는 방식 | 날씨 추천 전체가 실제 착장에 적용됐다는 오해 |
| 3열 스타일링 지면 | 큰 문자·번호, 열별 비교, 선택지 사이의 리듬 | 현재 없는 세 가지 의상이나 코디를 만들어 표시하는 것 |
| 비대칭·컷아웃 지면 | 여백, 겹침, 크기 대비, 주석의 연결 | 기능 버튼을 읽기 어렵게 회전·중첩하는 것 |
| 사각 모델 프레임 지면 | 피사체의 선명한 경계, 얇은 선, 캡션과 본문의 연결 | 마네킹을 가리는 사진·장식 프레임 |
| 엇갈린 코트·치수 주석 지면 | 실루엣 간 리듬, 번호와 설명의 대응 | 도식을 실제 상품 사진이나 정확한 착장 비율로 표현하는 것 |

## 3. 현재 구현과 개선 과제

### 3.1 현재 확보한 기반

| 영역 | 현재 구현 | 다음 개선 과제 |
| --- | --- | --- |

| 매거진 표현 | 소프트 화이트·차콜·스톤, 선택용 버건디, 절제된 세리프·선·도식 | 실제 화면의 밀도와 읽기 순서 확인 |
| 메인 | 작은 브랜드·날짜, 낮은 채도의 날씨·마네킹, 현재 상품·사이즈와 주요 CTA 하나 | 실루엣과 주요 행동의 실제 가시성 확인 |

| 치수 편집 | 필수·선택 치수, 상품 메모, 소재, 검증, 미리보기 | 키보드·오류·미적용 상태에서도 입력 맥락 유지 |
| 반응형 | 700pt 기준 지면 전환, 큰 글씨에서 세로 구성, native inspector | 화면 폭·높이·글씨·패널 상태가 함께 바뀔 때의 사용성 확인 |
| 공통 모션 | 눌림 100ms, 전환 220ms, 제목 12pt·300ms·40ms 간격, 피드백 160ms, 배경 시차 ±6pt | 지연·반복·저성능 기기·접근성 설정의 실기기 확인 |
| 개인 데이터 | 체형 프로필 / 상품 / 사이즈 / 활성 선택 분리, 원자적 JSON 저장 | 실제 기기의 재실행·저장 실패·이전 데이터 확인 |
| 착장 상태 | 새 계산 중 이전 의류 숨김, 준비된 새 결과만 표시, 실패 안내 | 상태 안내와 연출이 충돌하지 않도록 유지·정리 |
| 접근성 | Reduce Motion 대응, 주요 버튼·치수의 접근성 정보 | 의미 있는 텍스트 크기, 읽기 순서, 초점, 실제 대비 확인 |

### 3.2 코드 구조에서 확인한 개선 후보

다음은 **실기기에서 확인된 결함 목록이 아니라**, 현재 구성을 바탕으로 한 설계 검토 항목이다.

- 메인의 큰 제호·어두운 카피 지면을 제거하고 마네킹과 현재 선택을 우선했다. 좁은 창은 세로, 넓은 창은 좌우로 구성하며 실제 기기에서 피사체·CTA가 충분히 드러나는지는 추가 확인한다.
- 공통 지면 제목과 반복 섹션 제목이 비슷하게 강조되면 시선의 우선순위가 약해질 수 있다. 대형 제목은 화면당 한 지배적인 그룹에 집중한다.
- 공통 작은 분류 라벨은 Dynamic Type을 따르는 caption 크기로 조정했다. 장식용 로고·폴리오와 사용에 필요한 상태의 실제 가독성을 따로 확인한다.
- 상품별 사이즈 도식은 같은 형태를 반복하므로 크기 차이를 과장하지 않는다. 도식이 아니라 수치와 실제 피팅 결과가 비교 근거다.
- 현재 탭 전환은 콘텐츠를 다시 구성한다. 한 화면 안의 사이즈 변경·폭 전환에서 지켜온 장면 안정성과, 서로 다른 탭 사이의 카메라 연속성은 별도 과제다.
- 마지막 디자인 변경에서 앱·단위 테스트·UI 테스트 번들의 실기기 대상 컴파일은 성공했다. 실제 레이아웃, 조작감, 프레임, 햅틱, 접근성 동작은 검증되지 않았다.

과거 [진행 기록](progress-2026-10-26.md)에 남아 있는 A/B 패널 설명은 해당 작업 시점의 기록이다. 이 설계의 현재 UX 기준은 한 마네킹에서 사이즈를 바꾸는 방식이며, 최신 [README](../README.md)와 현재 코드를 함께 참조한다.

### 3.3 이번에 반영한 범위와 남은 범위

- **반영:** 최초 설정 초안 복원, 체형 추가·편집·복사·활성화·삭제, 상품 정보와 사이즈별 치수 분리, 비교표·입혀보기, 저장 실패 안내, 이전 데이터 보존.
- **반영:** 공통 세리프 제목·선·여백·캡션, 주요 제목의 제한적 등장, 미세한 CTA 눌림, 헤더 축약 경계 안정화, 저장 성공에 연결한 피드백.
- **보존:** 기존 신체 변형, 실측 단위 변환, 의류 크기 조절, 착장·겹침 보정·소재·최신 요청 처리. 라이브러리는 기존 피팅 입력으로 변환해 연결하며 새 계산기를 만들지 않는다.
- **미구현:** 긴팔·아우터·바지·레이어링, 외부 상품 자동 가져오기, 독립 기사·소셜 기능, 탭 사이의 완전한 카메라 공유.
- **확인 수준:** 앱·단위/UI 테스트 번들의 실기기 대상 컴파일. 테스트 실행, 화면·햅틱·프레임·접근성 실기기 검증은 하지 않았다.

| 최초 설정·시트 | 좁은 화면에서 기준 선택을 먼저, 어두운 `You, first.` 지면은 그 아래. 모든 시트의 내비게이션 제목을 같은 서체로 |
| 상태 | 각주형: 가로 괘선 하나 + Bodoni 이탤릭 리드인(Saved — / Attention — / Error — / In progress —)이 문장으로 이어짐. 아이콘·측면 선·색 상자 없음. 표지는 계산 중 문구만, 주의·실패는 CTA 아래 |

- 모션: 제목 줄 단위 리빌 720ms·100ms 간격, 지면 전환 500ms(이전 지면 즉시 제거, 3D 중복 없음), 표지 프레임 1.04→1 배율·페이드 900ms, 구분선 그리기 500ms, 섹션 등장 24pt·700ms. 모두 감속 커브 `timingCurve(0.16, 1, 0.3, 1)`. 접근성 설정에서는 정적.
- 조작·상태는 3D 영역 밖에 두고 여백선에 정렬한다. 피팅 계산·저장 로직은 변경하지 않았다.

**확인 범위:** 사용자 허가 후 iOS 26.1 시뮬레이터에서 UI 테스트 3건과 디자인 단위 테스트 15건을 실행해 통과했고, 캡처한 표지·오늘·피팅룸·내 체형·최초 설정 화면을 보며 러닝헤드 겹침, 큰 글자와 아이브로우 충돌, 저장 안내가 지면을 밀어내던 레이아웃 결함을 수정했다. 실기기 대상 컴파일 성공. 실기기의 체감·햅틱·프레임과 나머지 UI 테스트는 미확인이다.

## 4. 정보 구조와 핵심 흐름

### 4.1 내비게이션

```text
앱 실행 -> 저장소 복원
  -> 오류: 기존 데이터 보존 + 다시 불러오기
  -> 활성 체형 없음: 기준 선택 -> 키·몸무게 -> 확인·저장
  -> 활성 체형 있음: 오늘 / 피팅룸 / 내 체형

오늘
  -> 현재 착장과 날씨
  -> 피팅룸 진입
  -> 선택 상품의 사이즈 노트 -> 해당 사이즈의 피팅룸
  -> 상품 관리

피팅룸
  -> 한 마네킹에서 선택 상품의 사이즈 또는 미착용 선택
  -> 의류 측정 도식과 현재 치수
  -> 외부 상품 치수 입력 -> 검증 -> 적용 또는 취소
  -> 상품 관리 -> 상품 상세 -> 사이즈 편집 / 입혀보기
  -> 근사 계산 상세와 원본 상품 링크

내 체형
  -> 기준 체형과 측정 출처
  -> 체형 편집 -> 완료 또는 취소
  -> 저장 체형 -> 생성 / 복사 / 수정 / 활성화 / 삭제
  -> 설정 -> 저장 체형 관리 / 저장·지원 범위 안내 / 브랜드 스토리
```

- 세 개의 주 탭을 유지한다. 새 콘텐츠 탭은 자동으로 추가하지 않는다.
- 장 번호는 위치를 돕는 장식이며 한글 탭명을 대체하지 않는다.
- 상품 노트, 피팅 결과, 체형 정보는 별개의 저장 의미를 갖는다. 같은 화면에 보인다고 같은 데이터로 취급하지 않는다.
- 여러 상품을 저장하지만 한 번에 피팅하는 것은 한 상품의 한 사이즈와 한 활성 체형이다. 목록을 여러 의상의 동시 착장처럼 표시하지 않는다.

### 4.2 데이터와 저장 수명

| 데이터 | 저장 내용 | 다른 데이터와의 관계 |
| --- | --- | --- |
| 체형 프로필 | ID, 이름, 기준 성별 모델, 신체 치수·조절값, 수정 시각 | 여러 개 보관하되 활성 ID는 하나 |
| 최초 설정 초안 | 선택한 기준, 입력 치수, 이름, 현재 단계 | 완성 체형과 분리하고 최초 저장 성공 후 정리 |
| 상품 | ID, 이름, 원본 URL, 메모, 의상 종류, 기준 템플릿 | 여러 사이즈를 소유 |
| 상품 사이즈 | ID, 자유로운 이름, 형식이 있는 치수·소재, 샘플 여부 | 같은 상품 안에서 이름 중복 방지; 다른 상품의 M과 독립 |
| 현재 선택 | 활성 체형 ID, 선택 상품 ID, 선택 사이즈 ID | 체형을 바꿔도 상품 치수·사이즈는 유지 |

- 기본 저장소는 앱의 Application Support 내부 `WEASHION/fitting-library.json`이다. 임시 파일을 이용한 원자적 쓰기가 성공한 뒤 상태와 성공 피드백을 갱신한다.
- 개인 마네킹은 매번 별도 생성 파일을 저장하지 않는다. 기존 기준 메시 위에 저장된 신체 설정을 다시 적용한다. 설정 저장 성공과 3D 계산 성공을 구분한다.
- 기존 `editorialFittingSession`은 체형·선택·실측값을 이전한다. 더 오래된 `primaryGarmentSizes`에는 체형이 없으므로 의류 기록만 이전하고 최초 체형 설정을 진행한다. 이전 키는 지우지 않는다.
- 기존 사용자 지정 슬롯을 이름·URL로 임의 병합하지 않는다. 각각 별도 상품으로 남기며 없는 모델·치수는 표시 불가 상태로 보존한다.
- 스키마·연결 정보·파일 복원에 문제가 있으면 기존 파일을 덮어쓰지 않는다. 새 저장소가 없는 경우에만 초기 샘플을 만든다.
- 선택 사이즈 삭제는 그 사이즈 선택만, 선택 상품 삭제는 상품·사이즈 선택을 해제한다. 활성 체형은 다른 체형을 먼저 활성화한 뒤 삭제한다.
- 앱 삭제 후 복원, 계정 동기화, 기기 간 이전은 보장하지 않는다.

### 4.3 원본 프롬프트의 ‘기사 상세’ 재해석

이번 범위에서는 **피팅룸 자체를 상세 에디토리얼 지면**으로 사용한다.

| 기사 구성 | 피팅 지면 구성 |
| --- | --- |
| 대표 이미지 | 동일한 내 체형 위의 선택 의류 |
| 제목·메타 정보 | 상품명, 사이즈명, 샘플/직접 입력 상태 |
| 기사 본문 | 어떤 치수를 보고 비교해야 하는지에 대한 안내 |
| 사진 캡션 | 측정 번호, 단위, 입력값과 계산값의 의미 |
| 관련 콘텐츠 | 다른 사이즈 선택과 원본 상품 확인 |

향후 독립적인 읽을거리 화면을 만들 경우에는 콘텐츠 공급 방식, 이미지 권리, 저장 기능, 탐색 구조를 별도로 결정한다. 현재 피팅 흐름을 유지하기 위해 기사 화면을 억지로 끼워 넣지 않는다.

## 5. 화면별 상세 개선 방향

### 5.1 오늘: 나의 실루엣을 표지로

**목적:** 사용자가 앱을 열자마자 ‘내 마네킹을 통해 옷을 보는 곳’임을 이해하고 피팅을 시작한다.

```text
WEASHION                                      내 체형
----------------------------------------------------
카테고리 / 오늘 날짜

      짧은 표지 제목
          [날씨 배경 + 나의 한 마네킹]
                       의도적인 비대칭 여백

선택 의류 / 사이즈               [피팅룸에서 보기]
날씨 상태 / 기온 / 연결 여부
----------------------------------------------------
선택 상품의 사이즈 노트: S / M / L 또는 직접 지정한 이름
날씨 상세와 짧은 스타일 안내
```

#### 구성 제안

- 브랜드 헤더와 별도의 대형 제목이 수직으로 중복되는 구조를 줄인다. 제목 일부를 표지 영역과 결합한다.
- 일반 글씨·충분한 높이의 iPhone 세로 화면에서 표지 영역은 사용 가능한 첫 화면 높이의 약 55~65%를 출발점으로 검토한다. 고정 비율이나 모든 기기의 합격 기준은 아니다.
- 첫 화면에서 마네킹의 주요 실루엣, 현재 선택, 피팅룸 진입 행동이 발견돼야 한다. 작은 화면에서는 장식과 부제부터 줄인다.
- 표지 제목은 피사체의 얼굴·어깨·가슴·밑단을 가리지 않는 여백에 배치한다. 한글 기능 설명은 별도로 제공한다.
- 기온을 피팅 행동보다 더 강한 시각 요소로 만들지 않는다. 자세한 예보·스타일 안내는 후속 지면으로 이동하는 안을 우선한다.
- 상품별 사이즈 노트는 시각적 비교와 바로 입혀보기의 연결점으로 사용한다. 샘플/직접 입력 상태를 유지한다.
- 화면 전체를 누르는 숨은 동작 대신 명시적인 피팅 CTA를 제공한다. 3D 영역의 드래그와 탐색 탭을 혼동하지 않게 한다.

#### 하지 않는 것

- 실제 상품 사진처럼 보이는 임의 이미지를 피팅 결과로 사용
- 날씨 연결이나 오프닝 종료 전까지 기능 잠금
- 큰 브랜드명, 큰 제목, 큰 장 번호, 큰 기온을 모두 같은 강도로 배치
- 마네킹의 자동 회전·확대를 스크롤 연출에 결합

### 5.2 피팅룸: 치수와 모습을 함께 읽는 지면

**목적:** 몸을 바꾸지 않고 의류 치수와 사이즈에 따른 차이를 비교한다.

```text
02 / 피팅룸                상품명 / 현재 사이즈

[동일한 내 마네킹]
계산 상태 / 기준 키·몸무게 / 회전·확대 조작

[선택 상품의 사이즈들] [미착용]
[외부 상품 치수 입력]
[상품 선택·관리]
----------------------------------------------------
측정 위치 도식              실제 입력 치수
1 총장 / 2 어깨 / 3 가슴단면 / 4 소매

단면과 둘레 설명
[착장 계산 상세]
원본 상품 링크 / 지원 범위와 한계
```

- 대형 감성 제목보다 마네킹·현재 선택·치수 입력 동작에 높은 우선순위를 부여한다.
- 작은 화면에서는 상품명·선택 상태를 간결하게, 넓은 화면에서는 왼쪽 마네킹과 오른쪽 치수·조작 영역으로 구성한다.
- 사이즈 선택과 치수 입력 버튼은 측정 설명의 긴 스크롤 뒤에 숨기지 않는 방향으로 재배치한다.
- 도식 번호와 입력 항목 번호를 일치시킨다. 단위와 단면/둘레 의미는 항상 함께 이해할 수 있어야 한다.
- 필수 제한 안내는 짧게 상시 표시하고, 계산 방식·상세 수치는 펼쳐 보기로 분리한다. 실패 원인과 미적용 상태는 접지 않는다.
- 새 사이즈를 선택하면 선택 표시는 즉시 바뀌되 계산 중임을 표시한다. 이전 의류를 새 결과처럼 보여주지 않는다.
- 미착용에서는 상품 치수 결과가 현재 착장처럼 남지 않게 한다. 다시 옷을 선택하는 동작은 유지한다.

### 5.3 내 체형: 나의 기준을 기록하는 페이지

**목적:** 개인 마네킹의 기준과 입력값의 출처를 이해하고 필요할 때 수정한다.

- ‘체형 평가’가 아니라 ‘개인 치수 기록’으로 표현한다. 이상적인 몸, 정상 체형 점수, 우열을 암시하지 않는다.
- 측정값마다 직접 측정 / 추정 / 기본값 / 조절값을 구분한다.
- 키·몸무게·주요 둘레·길이를 읽기 쉬운 표 형식으로 정리하고 장식 번호는 보조로 사용한다.
- 체형 수정 CTA는 찾기 쉽게 유지한다. 상세 부위 설정을 전부 프로필 메인에 노출하지 않는다.
- 긴 개인정보를 크게 노출하는 표지 연출보다, 필요한 수치를 읽는 차분한 지면을 우선한다.
- 데이터가 이 기기에 저장된다는 사실을 설명한다. 현재 없는 계정 동기화·클라우드 저장을 암시하지 않는다.
- 체형 단독 미리보기는 의류 선택 데이터를 해제하지 않는다. 피팅룸으로 돌아가면 같은 상품·사이즈를 다시 사용한다.
- 화면의 편집 대상은 활성 체형이다. 다른 체형의 편집·이름 변경·활성화는 저장 체형 목록에서 수행한다.

### 5.4 상품 치수 입력: 정확성이 가장 중요한 작업 지면

**목적:** 외부 사이트의 숫자를 잘못 해석하지 않고 입력·검토·적용한다.

1. 상품명·원본 URL·상품 사이즈명
2. 네 가지 기본 치수와 대응하는 측정 도식
3. 선택 치수: 모르면 미입력 유지
4. 추정 소재 특성
5. 현재 검증 상태와 적용/취소

상품 라이브러리에서는 상품 정보 편집과 사이즈 편집을 분리한다. 피팅룸에서 상품명·URL을 함께 수정하면 해당 상품의 모든 사이즈가 공유하는 정보가 바뀌고, 치수·소재는 선택 사이즈만 바뀐다는 점을 안내한다.

- 입력 중에는 장 번호와 제목보다 필드 이름·수치·단위·오류가 우선한다.
- 도식은 입력을 설명하는 보조 자료다. 작은 패널에서는 간결하게 표시해 필수 필드를 지나치게 밀어내지 않는다.
- cm와 입력 가능 범위를 명확히 표시한다. 가슴단면과 신체 가슴둘레를 같은 필드처럼 표현하지 않는다.
- 숫자를 입력할 때 자간·크기·자리 이동 애니메이션을 사용하지 않는다.
- 잘못된 값이 있으면 적용을 막고, 해당 필드로 이동하는 동작과 수정 이유를 제공한다.
- URL은 원본 확인용이라는 안내를 유지한다. URL 입력만으로 상품을 가져온 듯한 로딩·완료 연출을 사용하지 않는다.
- 마지막 유효값을 미리보기로 유지할 경우 ‘직전 유효 치수 표시’를 명시한다. 화면의 잘못된 입력이 3D에 반영됐다는 인상을 주지 않는다.
- 측면 패널의 유효 초안은 본문의 한 마네킹에 임시 반영한다. 저장 전 상태임을 패널과 관련 미리보기에서 이해할 수 있게 한다.
- 키보드가 열린 상태에서도 현재 필드와 오류 안내를 볼 수 있어야 한다. 적용 버튼의 고정 영역이 입력 내용을 덮지 않게 한다.

### 5.5 체형 편집: 몸을 정확히 조절하는 도구

- 기준 체형, 기본 정보, 주요 신체 치수, 시각 조절, 세부 부위를 구분한다.
- 실제 측정과 시각적 조절의 의미를 섞지 않는다. 슬라이더 값이 의학적 측정값처럼 보이지 않게 한다.
- 세부 부위는 필요한 그룹을 펼쳐 조절하며 기존 좌우 연동과 추정값 보존 정책을 유지한다.
- 번호는 장식적 분류로 사용하고 기능의 존재를 보장하는 연속 단계 번호처럼 읽히지 않게 한다. 조건부 항목이 없는 경우 빈 단계가 생긴 듯한 설명을 피한다.
- 숫자 변화는 즉시 전달한다. 신체 미리보기의 계산과 별도로 불필요한 탄성 애니메이션을 겹치지 않는다.
- 완료와 취소의 저장 의미를 명확히 유지한다. 계산 중이라는 이유로 취소할 수 없게 하지 않는다.

### 5.6 최초 설정: 바로 나의 마네킹 만들기

1. **기준 선택:** 남성/여성 중 사용자가 직접 선택한다. 미선택 상태에서는 다음으로 진행하지 않는다.
2. **기본 입력:** 키·몸무게를 실제 값으로 입력한다. 범위·단위·입력 완료 동작을 제공한다.
3. **확인·저장:** 한 미리보기, 체형 이름, 선택적인 상세 치수·커스터마이징, 시작 CTA를 제공한다.

- 초기 기준 모델은 설명용 미리보기이며 사용자의 실제 신체 정보가 아니다. 직접 입력·추정·기본값을 구분한다.
- 최초 설정 중 선택·숫자·단계를 초안으로 저장하고 다음 실행에서 이어간다. 저장 실패는 알리고 최종 프로필 저장이 실패하면 화면을 닫지 않는다.
- 잘못된 치수는 3D 계산에 새로 보내지 않고 직전 유효 체형 또는 기준 모델임을 표시한다. 유효한 설정 저장이 실제 메시 준비 완료까지 보증하지는 않는다.
- 기존 저장 체형이 있는 사용자는 이 절차를 다시 강제하지 않는다. 기준 성별은 이후 공통 체형 편집에서 변경할 수 있다.
- 브랜드 스토리·계정·위치 권한을 설정의 전제조건으로 삼지 않는다. 짧은 화면과 큰 글씨에서는 세로 스크롤로 진행 버튼을 유지한다.

### 5.7 저장 체형: 여러 기록, 하나의 피팅 기준

- 이름·기준 모델·키/몸무게·수정일·사용 중 표시를 보여주는 기록 목록을 사용한다. 행마다 별도 3D 마네킹을 만들지 않는다.
- 생성은 최초 설정과 같은 세 단계를 재사용한다. 복사는 기존 치수를 가진 별도 초안으로 확인 단계에 진입한다.
- 추가 체형은 `저장만` 또는 `저장 후 사용`을 선택한다. 취소하면 기존 프로필과 활성 체형을 바꾸지 않는다.
- 이름 변경·상세 치수·기준 성별 변경은 공통 편집 화면에서 명시적으로 저장한다.
- 활성화하면 저장된 상품·사이즈를 유지하고 기존 계산 경로로 착장을 다시 요청한다.
- 삭제 전 확인하며 사용 중인 프로필은 삭제할 수 없다. 먼저 다른 프로필을 사용하도록 안내한다.

### 5.8 상품과 사이즈: 같은 이름도 서로 다른 기록

- 상품 목록은 이름·종류·사이즈 요약·지원 상태를 보여준다. 등록 시 상품명·URL·메모와 현재 지원 템플릿을 저장한다.
- 상세는 상품 정보, 사이즈별 주요 치수, 숫자 비교표, 추가·수정·삭제·입혀보기로 구성한다.
- 사이즈명은 S/M/L, 95/100, 1/2, FREE 등 자유롭게 지정한다. 같은 상품 안에서는 앞뒤 공백·대소문자를 무시한 중복을 차단한다.
- 새 사이즈 또는 이전 기록의 치수가 없는 경우 편집 초기값이 M 샘플임을 명시한다. 실제 사이즈표를 확인하고 저장하기 전까지 실측값으로 취급하지 않는다.
- 치수가 없거나 지원 모델을 찾을 수 없으면 입혀보기를 비활성화하고 필요한 수정 경로를 보여준다. 빈 상품은 사이즈 추가 행동으로 연결한다.
- 현재 치수 자료형은 반팔 전용이며 긴팔·아우터·바지를 반팔로 변환하지 않는다. 향후 카테고리별 측정 계약, 기준 메시, 적용·검증 로직이 갖춰져야 해당 피팅을 활성화한다.

### 5.9 설정과 선택적인 브랜드 스토리

- 설정은 내 체형에서 진입하며 네 번째 주 탭으로 만들지 않는다.
- 저장 체형 관리, 로컬 저장·복원 한계, 지원 의상·피팅 한계, 날씨 권한 안내를 제공한다.
- 기존 어두운 3페이지 브랜드 소개는 선택적으로 열고 종료 후 설정으로 돌아간다. 개인 마네킹이나 상품 데이터를 바꾸지 않는다.
- 브랜드 주요 제목에는 같은 제한적 등장 효과를 사용하되 설명과 닫기·진행 버튼을 지연하지 않는다.

### 5.10 추가 방향과 제외: 치수 포커스·지면 목차·옷 사진 · 0.15 반영

**상태: 치수 포커스 구현·집중 검증 완료, 옷 사진은 장기·미구현, 바로보기·지면 목차는 제외.** 기존 표지·팔레트·서체·화면 전환·등장 모션은 유지한다. 추가 UI는 지면의 정보와 조작을 돕는 작은 요소로 제한한다.

#### A. 제외: 정면·측면·후면 바로보기

- 0.11의 제안은 사용자 요청으로 0.12에서 취소했다. 후순위 작업으로 남기거나 새 선택지·밑줄·방향 상태를 추가하지 않는다. 기존 회전·확대·초기화·제스처는 유지한다.

#### B. 치수 도식과 숫자의 연결 포커스 · 0.15 구현

- 기존 측정 번호·치수 항목을 선택하면 대응하는 도식 선과 숫자만 버건디·선 두께로 함께 강조한다. 도식과 치수 목록 양쪽에서 같은 선택을 바꾸며 다른 선은 읽을 수 있는 수준으로 남긴다.
- 총장·어깨너비·가슴단면·소매길이처럼 현재 지원하는 항목만 연결한다. 작은 번호의 시각 크기와 실제 터치 영역을 구분하고 인접 항목의 터치 영역이 겹치지 않게 한다.
- 설명용 옷 그림의 비율을 바꾸거나 몸·메시·카메라를 움직이지 않는다. 실제 상품 사진이나 정확한 옷 형태를 재현하는 기능이 아니라 측정 위치를 이해하도록 돕는 2D 선택이다.
- 포커스는 저장된 치수·선택 사이즈·계산 결과를 바꾸지 않는 일시적 UI 상태다. 치수가 없거나 지원하지 않는 상품에는 잘못된 연결선을 표시하지 않는다.
- 도식 번호는 44×44pt 터치 영역을 사용하고 선택은 접근성의 선택됨 상태로 제공한다. 피팅룸의 번호·치수 항목은 같은 선택을 공유한다. 치수 편집에서는 번호 선택이 대응 입력 행으로 이동하고, 입력 포커스도 도식 선택에 반영된다. 사용자 글씨 크기에 따른 기존 한 열·두 열 구분은 유지한다.

#### C. 제외: 오늘 화면의 작은 지면 목차

- `표지 / 날씨 / 착장 / 사이즈` 바로 이동 목차는 사용자 요청으로 0.14에서 취소했다. 구현 전 조사에서 중단했으며 후순위나 다음 빠른 작업으로 다시 제안하지 않는다.
- 기존 오늘 화면의 스크롤·리빌·주 메뉴는 그대로 유지한다. 이 결정은 기존 설정·보관함 등의 링크나 문서 자체의 목차를 제거한다는 뜻이 아니다.

#### D. 사용자 등록 옷 사진 아카이브 · 장기 확장

- 사용자가 직접 선택한 실제 옷 사진을 상품에 연결하고 사진·상품명을 비대칭으로 조판한다. 사진이 없으면 기존 도식을 유지하며 사진 등록을 상품·사이즈 저장의 필수 조건으로 만들지 않는다.
- 사진은 기록용 이미지다. 사진에서 3D 옷을 복원하거나 재질·정확한 치수·착용감을 자동 추정하는 기능은 포함하지 않는다. 외부 스톡 이미지를 사용자의 옷으로 대체하지 않는다.
- 네이티브 사진 선택과 로컬 보관을 출발점으로 삼는다. 자동 배경 제거·카메라 촬영·클라우드 전송은 이번 방향만으로 추가하지 않는다.
- 구현 전 이미지 연결·복구·교체·삭제의 저장 계약을 정하고, 사진 필드가 없는 기존 기록은 그대로 읽혀야 한다. 사용자 원본 사진은 삭제하지 않고 앱이 소유한 사본만 관리한다.
- 목록은 표시 크기에 맞춘 썸네일을 사용하고 디코딩·축소는 화면 반응과 분리한다. 읽기 실패는 알리되 사진 부재가 치수 입력이나 피팅 진입을 막지 않게 한다.

## 6. 반응형 레이아웃과 조작 규칙

### 6.1 판단 기준

**가로 지면 전환과 inspector 표시는 서로 다른 판단이다.**

- 지면의 좌우 배치는 실제 사용 가능한 콘텐츠 폭으로 판단한다.
- 편집 UI의 시트/패널 적응은 시스템 size class와 native inspector 동작을 따른다.
- 같은 iPad에서도 분할 화면·창 크기·패널 열림에 따라 본문이 좁아질 수 있다.
- 700pt는 현재 기준을 이어가는 초기 전환점이다. 기기 이름만으로 두 열을 강제하지 않는다.

| 조건 | 레이아웃 제안 | 우선 보존할 것 |
| --- | --- | --- |
| 콘텐츠 폭 700pt 미만 | 세로 지면 | 마네킹, 선택 상태, 핵심 CTA, 본문 읽기 |
| 콘텐츠 폭 700pt 이상 + 일반 글씨 | 마네킹과 정보를 좌우 배치 | 각 열의 충분한 너비, 공통 캡션 정렬 |
| 접근성 글씨 | 한 열, 겹침 제거, 필드 이름과 입력 행 분리 | 의미 있는 텍스트 전체, 단위, 오류, 조작 |
| 낮은 가로 창 | 장식·큰 번호 축소, 스크롤 허용, 필요 시 세로 흐름 | 입력 필드와 하단 행동 접근성 |
| 키보드 표시 | 활성 필드와 오류가 보이도록 스크롤 조정 | 초점, 작성 중 값, 취소/적용 의미 |
| 측면 inspector 표시 | 줄어든 본문 폭으로 재평가 | 한 마네킹의 임시 미리보기와 기존 카메라 상태 |

- 사이즈 노트는 최소 열 폭 150pt의 가변 그리드로 재편집한다. 작은 창에서 무조건 3열을 유지하지 않으며 접근성 글씨는 한 열이다. 상품 갤러리는 더 긴 상품명을 위해 최소 열 폭 230pt를 사용한다.
- 레이아웃 전환 시 같은 장면을 유지하는 구조를 우선한다. 두 열/한 열 분기를 위해 3D 장면을 각각 생성하지 않는다.
- 안전 영역과 시스템 내비게이션 영역을 콘텐츠가 덮지 않게 한다.
- 첫 화면의 감상 비율은 일반 글씨에서의 시각 목표일 뿐이다. 큰 글씨에서 모든 정보를 한 화면에 억지로 맞추지 않는다.

### 6.2 제스처 소유권

| 동작 | 대상 | 금지할 충돌 |
| --- | --- | --- |
| 세로 드래그 | 페이지 스크롤 | 마네킹이 세로 스크롤을 가로채는 것 |
| 마네킹의 가로 드래그 | 사용자가 의도한 회전 | 표지 전체를 넘기는 가로 페이지 제스처와 중복 |
| 마네킹의 핀치 | 사용자가 의도한 확대·축소 | 배경 패럴랙스나 장식 확대와 혼동 |
| 사이즈 노트 탭 | 해당 사이즈 선택 후 피팅룸 진입 | 스크롤 시작을 선택으로 처리 |
| 필드 탭·입력 | 초점과 값 편집 | 눌림 축소·지연 등장으로 커서나 터치 위치 변경 |

동등한 회전·확대 조작을 접근성 사용자도 사용할 수 있게 유지한다. 스크롤 스냅, 자동 스크롤, 종이 넘김 제스처는 이번 기본 방향에 포함하지 않는다.

## 7. 디자인 시스템

### 7.1 색상

현재 [공통 스타일](../weashion/weashion/Views/EditorialStyle.swift)에 적용한 sRGB 기준값이다.

| 토큰 | 기준 색 | 역할 |
| --- | --- | --- |
| Paper | `#FAF9F6` | 소프트 화이트 기본 바탕 |
| Ink | `#202B30` | 주요 텍스트·아이콘·중요 구분선 |
| Muted | `#626B67` | 밝은 바탕 위 보조 설명과 출처 |
| Accent | `#9F3548` | 버건디 주요 CTA·선택·입력 포커스 |
| Stock | `#EAE7E0` | 보조 면. 입력·치수 기록은 Paper 위 40% 불투명도로 사용 |
| Studio | `#ECEDEA` | 중립적인 3D 피팅 배경 |
| Warning | `#795117` | 주의 아이콘·문구. 피팅 적합성 판정색이 아님 |
| Error | `#A62920` | 입력 오류·표시 실패. 브랜드 선택색과 분리 |
| Rule | Ink의 약 18% | 장식용 경계선. 필수 조작 경계의 대비를 대신하지 않음 |
| Inverse | Paper + 어두운 배경 | 설정에서 여는 선택적 브랜드 스토리 |

- 색을 늘리기보다 명도와 면적 대비로 위계를 만든다.
- 날씨의 색은 배경에서 사용한다. 주요 조작부와 숫자의 색 의미를 날씨마다 바꾸지 않는다.
- 오류·선택·저장 완료는 아이콘·텍스트·테두리 또는 채움을 함께 사용한다. Accent 하나로 성공과 오류를 구분하지 않는다.
- 이미지·날씨 위 텍스트는 국소적인 단색 면이나 그라데이션으로 대비를 확보한다. 실제 배경 조합에서 확인한다.
- 기준 sRGB 산술 대비는 Paper 위 Ink 13.76:1, Muted 5.22:1, Accent 6.48:1이다. Muted를 불투명 Stock 위에 직접 쓰면 4.45:1이므로 피한다. 입력·기록 면의 40% Stock 위에서는 약 4.91:1이다. 주요 텍스트 조합은 4.5:1 이상이며 실기기 픽셀 측정 결과는 아니다.
- 앱 전체 다크 모드 확장은 별도 범위다. 기본 앱은 밝게, 어두운 분위기는 선택적 스토리에 제한한다.

#### 실제 폰트 선정 원칙

- 우선 시스템 폰트로 정보 구조를 정리하고 커스텀 폰트는 비교 후 결정한다.
- SwiftUI의 serif 지정만으로 원하는 한글 명조가 선택됐다고 간주하지 않는다.
- 한글 음절, 영문 대소문자, 숫자, cm·kg·온도 기호, 문장부호의 조합을 실제 렌더링으로 확인한다.
- 서체를 번들에 넣는 경우 앱 재배포·임베딩 권리, 라이선스 문서, 용량과 언어 커버리지를 확인한다.
- 한글 제목의 과도한 장평·자간 압축, 가는 획, 영문에 맞춘 불필요한 강제 줄바꿈을 피한다.
- 의미 있는 문구를 `minimumScaleFactor`로 계속 축소해 한 줄에 맞추지 않는다. 제한적 워드마크와 기능 텍스트를 구분한다.

#### 다국어 조판 · 0.7

- 소스 언어는 한국어이고 영어·일본어를 같은 레이아웃 위에 얹는다. 번역은 레이아웃이 허용하는 길이에 맞춰 다시 쓴다. 예: 탭·헤더의 `피팅룸`은 영어 `Fitting room`, 일본어 `試着室`(フィッティングルーム는 탭에서 두 줄이 된다), 날씨 선언문 `가볍게 / 겹쳐 입는 날.`은 영어 `Layer / lightly.`처럼 두 줄 안에 끝나는 짧은 문장으로 옮긴다.
- 영문 편집 요소(`WEASHION`, `FIG.`, `N°`, *Every size, a note.*, *Fitting notes.*)와 `한국어 · THE DAILY EDIT`식 러닝헤드의 영문 꼬리는 번역하지 않는다. 영어 러닝헤드는 중복을 피해 한쪽만 남긴다(`THE FITTING ROOM`).
- Helvetica Neue + Pretendard 캐스케이드에는 가나·한자가 없어 일본어 기능 텍스트는 시스템 일본어 서체(Hiragino Sans)로 떨어진다. 선언문·제목의 Pretendard Black 역시 일본어에서는 시스템 굵은 고딕으로 대체된다. 허용하되, 혼합 문장에서 굵기 차이가 거슬리면 Pretendard JP 번들을 검토한다.
- 툴바의 텍스트 버튼은 `EditorialToolbarButton`을 쓴다. 시스템 본문 서체로 측정하고 한 줄로 고정해 `閉じる`·`キャンセル`이 캡슐 안에서 꺾이지 않는다.
- 세그먼트 피커는 제목을 제자리에서 갱신하지 않으므로 언어 값으로 `.id`를 걸어 다시 만든다. 언어 전환 시 메인 지면은 다시 그리고(제목 리빌·장면 재적재가 한 번 발생), 설정 시트는 유지한다.
- 언어 이름(한국어·English·日本語)은 항상 그 언어로 표기한다. 사용자가 입력한 상품명·체형명은 번역하지 않는다.

## 8. 마네킹·이미지·편집 연출

### 8.1 시각 자산의 역할

| 날씨 배경 | 외출 환경과 분위기 | 실제 연결 여부와 날씨 기준을 명시 |
| 의류 컷아웃 도식 | 측정 위치·사이즈 노트의 편집 장치 | 실제 상품 사진·정확한 비율·착장 결과가 아님을 안내 |

### 8.2 피사체 보호 규칙

- 얼굴·목·어깨·가슴·소매·밑단 등 해석에 중요한 영역을 제목이나 버튼으로 가리지 않는다.
- 같은 사이즈를 비교할 때 카메라 시점·배율이 임의로 바뀌어 옷의 차이처럼 보이지 않게 한다.
- 편집 모션은 주로 배경·제목·캡션에 적용한다. 몸·의류의 실제 변형은 피팅 계산과 명시적인 사용자 조작만 담당한다.
- 사이즈 노트의 컷아웃은 같은 설명용 형태로 유지한다. S/M/L 그림을 임의 비율로 확대해 실제 치수 차이를 암시하지 않는다.
- 넓은 화면의 빈 영역을 채우기 위해 두 번째 마네킹을 추가하지 않는다.
- 장면을 공유하는 패널과 독립적인 시스템 시트의 표현을 구분한다. 편집 시트에서는 같은 체형의 미리보기를 사용하되, 배경 본문과 두 마네킹을 비교하는 구성으로 보이지 않게 한다.

### 8.3 이미지 사용이 추가될 경우

- 원본 비율을 보존하고 피사체별 crop 기준을 정의한다.
- 로딩 전에도 영역 크기를 확보해 텍스트와 버튼이 밀리지 않게 한다.
- 해상도를 표시 크기에 맞추고 실패 시 명시적인 대체 상태를 제공한다.
- 임의의 스톡 사진을 실제 입력 상품으로 대체하지 않는다.
- 이미지 부재를 이유로 필수 치수 입력이나 피팅룸 진입을 막지 않는다.

## 9. 모션 명세

### 9.1 공통 원칙

1. 모션은 **행동, 콘텐츠 관계, 정보 위계, 상태** 중 하나를 설명해야 한다.
2. 조작은 즉시 처리한다. 애니메이션 종료를 기다려 상태를 변경하거나 기능을 잠그지 않는다.
3. 하나의 속성에는 하나의 모션 소유자를 둔다. 상위 화면·하위 컴포넌트의 중복 애니메이션을 피한다.
4. 같은 영역에서 동시에 크게 움직이는 주요 연출은 최대 두 요소를 초기 기준으로 한다. 입력 화면은 더 줄인다.
5. 반복 작업에는 진입 연출을 재생하지 않는다. 오류·저장·선택 상태는 모션이 끝난 뒤에도 이해돼야 한다.
6. Reduce Motion에서는 사용자 정의 이동·확대·회전·마스크 연출을 끈다. 즉시 최종 상태를 기본 대체로 사용한다.
7. 장식 모션이 실패하거나 생략돼도 기능·정보는 즉시 나타나야 한다. 종료 콜백에 필수 로직을 의존하지 않는다.

### 9.2 시간과 easing 어휘

| 구분 | 기준 | 사용 |
| --- | --- | --- |
| 즉시 | 인위적 대기 0ms | 선택 데이터 변경, 계산 중 이전 결과 숨김, 오류 상태 확정 |
| Fast | 100ms | 눌림과 해제 |
| Feedback | 160ms | 저장 안내·계산 상태 교체 |
| Standard | 220ms | 선택선·배경, 펼침, 섹션 등장 |
| Editorial | 440~800ms | 지면 스윕 440, 제목 줄 리빌 640, 표지 제호 진입 800 |
| Glyph | 280ms | 선택 사이즈 글자의 상하 교체 |
| Stagger | 80ms | 제목 줄 사이의 시작 간격 |
| Scroll-linked | 정해진 시간이 없음 | 손가락의 스크롤 위치에 직접 연결되는 시차·축약 |

- 눌림과 등장은 `easeOut`, 양방향 상태 변화는 `easeInOut`을 기본으로 한다.
- 스크롤 연동값에 별도의 지연 애니메이션을 매번 걸지 않는다.
- 바운스·회전·스프링을 일반 규칙으로 사용하지 않는다.
- 시간은 0.16 공통 상수이며 시스템 프레임 스케줄에 따라 실제 표시가 달라질 수 있다.

### 9.4 상세 모션 표

아래는 0.9에서 도입한 연출에 0.16의 현재 시간값을 반영한 표다. 이동량은 pt, 시간은 ms, 배율은 시각적 scale 기준이다. M05는 후보이며, 표지 캡션의 측면 진입은 별도로 반영했다.

**0.8 → 0.9 변경:** 보이는 장면에만 적용되던 정지 이미지 연결 전환은 제거했다. 동기식 `SCNView.snapshot()`, 장면 좌표 preference, 숨겨진 렌더 표면과 지면 전체 이동·페이드를 사용하지 않는다. 공유 상태에는 회전·확대·초점만 남기며 모든 탭에서 헤더의 가벼운 2D 버건디 스윕과 개별 제목 진입을 사용한다. 연속 선택은 즉시 최신 상태를 적용하고 장식의 종료를 기다리지 않는다.

**현재 반영 구분:** M01은 독립 버튼·선택에 0.97배·100ms 눌림을 사용한다. M04는 각 줄의 마스크 안에서 1.15em 아래로부터 640ms·80ms 간격으로 리빌한다. 날씨 선언문은 각 줄 자체의 노출 시점에 시작하며 다른 제목은 진입 시 시작한다. 제목은 VoiceOver·접근성 글씨·Reduce Motion에서 정적이다. M03은 제호·캡션만 움직이고 M06은 모든 탭의 헤더 스윕이다. M02는 선택선·배경에 더해 큰 사이즈 글자의 280ms 상하 교체를 사용한다. M07은 개별 숫자·행·도식·하늘판 단위로 적용해 화면에 도착하기 전에 끝나지 않게 한다. M11의 실제 저장 성공 의미와 M12의 최신 착장 결과 원칙은 유지하며 3D 렌더 하위 트리의 암시적 애니메이션 차단도 유지한다.

#### 적용 제한

- M01: 텍스트 필드, 슬라이더, 시스템 내비게이션에는 축소를 적용하지 않는다. 기존 명도 피드백만 유지하는 안을 기본으로 비교한다.
- M03: 제호와 캡션만 움직인다. 마네킹·전체 표지를 확대하거나 배경에 반복 애니메이션을 추가하지 않는다.
- M04: 제목 레이아웃을 먼저 확보하고 그 안에서만 드러낸다. 접근성 글씨·VoiceOver에서는 전체 제목을 즉시 읽을 수 있게 한다.
- M06: 3D 마네킹을 `matchedGeometryEffect`용으로 복제하거나 장면을 캡처하지 않는다. 헤더 스윕은 hit testing을 끄고 빠른 탭도 즉시 반영한다.
- M07: 상태·오류·필수 조작은 등장 임계값을 기다리지 않는다. 스크롤 왕복 때 반복하지 않는다.
- M08: 줄 수와 배치 높이를 프레임마다 다시 바꾸지 않는다. 예약된 영역에서 시각적 축약을 우선하며 헤더 재배치로 스크롤 값이 흔들리는 루프를 피한다.
- M09: 배경에 필요한 잘림 여유를 확보하고 가장자리 빈틈이 생기지 않게 한다. 같은 뷰에 배율·시차 애니메이션을 중복 적용하지 않는다.
- M11: ‘선택함’, ‘저장됨’, ‘착장 계산 완료’를 서로 다른 상태로 다룬다. 저장 완료는 피팅 성공을 의미하지 않는다.
- M12: 이전 결과와 새 결과를 겹쳐 디졸브하지 않는다. 새 몸이나 옷을 시각적으로 부풀려 계산을 흉내 내지 않는다.

### 9.5 주요 시나리오

#### A. 메인 진입

1. 내비게이션, 피팅 행동, 현재 데이터 또는 로딩 상태를 즉시 제공한다.
2. 날씨와 마네킹의 준비 상태를 각각 처리한다. 날씨 미연결은 피팅 사용을 막지 않는다.
3. 세션의 첫 메인 노출에서만 M04·M05를 선택적으로 사용한다.
4. 다른 탭에서 돌아오거나 저장 후 복귀할 때는 긴 표지 연출을 다시 시작하지 않는다.
5. 사용자가 곧바로 스크롤하면 남은 지연 연출을 생략하고 읽을 수 있는 최종 상태로 정리한다.

#### B. 사이즈 노트에서 피팅룸

1. 탭 입력과 함께 상품 슬롯·사이즈 선택을 갱신한다.
2. 피팅룸 진입과 계산 중 상태를 지체하지 않는다.
3. 동일한 2D 표식이 있으면 짧게 연결하고, 마네킹 장면 복제로 연속성을 흉내 내지 않는다.
4. 몸의 기준값은 그대로 유지한다. 시점 연속성을 추가할 경우 별도의 카메라 상태 보존 설계로 처리한다.
5. 계산 결과가 늦어도 전환을 반복하거나 화면을 잠그지 않는다.

#### C. 상품 치수 입력과 적용

1. 패널/시트가 열리면 원본 저장값으로 초안을 시작한다.
2. 유효한 초안만 미리보기에 반영하고 미적용임을 표시한다.
3. 검증 오류는 해당 필드와 수정 동작으로 연결한다.
4. 적용 시 저장 결과를 확인한 후 M11을 표시한다. 저장 실패 시 성공 모션이나 강제 닫기로 오류를 숨기지 않는다.
5. 저장 후 착장 계산이 진행 중이면 별도 진행 상태를 유지한다.
6. 취소하면 초안을 폐기하고 저장된 기준을 복원한다.

### 9.6 재생·중단·접근성 정책

- 일반 재렌더링, 계산 완료, 앱 활성화 복귀만으로 제목 연출을 재생하지 않는다.
- 소개의 다음/이전 페이지 선택은 해당 페이지 전환으로 처리하되, 빠른 연속 선택 시 오래된 지연 작업을 취소한다.
- Reduce Motion을 실행 중 켜도 즉시 이동·확대를 종료하고 최종 정적 상태를 표시한다.
- VoiceOver 읽기 순서와 제목 의미는 시각적 등장 순서와 분리한다.
- 햅틱은 실제 선택 변경과 성공한 적용에만 한 번 사용한다. 자동 복원·실패·레이아웃 변경에 성공 햅틱을 주지 않는다.
- 시스템 시트·키보드·진행 표시의 접근성 동작은 플랫폼에 맡긴다.
- 좋아요·북마크 모션은 기능 자체가 별도 승인되기 전까지 구현 목록에서 제외한다.

### 9.7 전환 지연을 설명하는 다음 지면 예고 · 0.10 확정 설계

**상태: 0.13에서 핵심 구현·단위 검증 완료.** 기존 제호·캡션·줄별 리빌·스크롤 시차·사이즈 글자·눌림·탭 선택선·500ms 헤더 스윕의 모양, 위치, 시간과 easing은 변경하지 않았다. 보조 연출은 기존 전환을 대체하지 않고, 실제 화면 교체 전의 대기 구간에만 추가한다. 느린 준비·최신 요청·취소·오류는 단위 테스트로 확인했으며, 모든 실기기·접근성 환경의 시각 검수가 끝났다는 뜻은 아니다.

```text
메뉴 입력
  -> 즉시 선택 피드백 + 최신 이동 요청 기록
  -> 준비된 화면이면 바로 기존 전환
  -> 준비가 늦으면 기존 화면 위에 작은 다음 지면 예고
  -> 표시 가능한 시점에 예고 해제 + 기존 전환·등장 모션 시작
```

#### 표현과 시간

- **위치:** 하단 메뉴 바로 위에 종이색의 얇은 띠를 임시로 겹친다. 본문·스크롤·3D 영역의 레이아웃을 밀거나 전체 화면을 덮지 않는다. 메뉴·저장 안내와 겹치지 않게 배치하고 보조 레이어는 터치를 가로채지 않는다.
- **내용:** 다음 지면의 버건디 번호와 기존 편집형 이름을 표시한다. 예: `02 / THE FITTING ROOM`. 기존 현지화 체계를 유지하고 새 상태 설명은 한국어 소스로 관리한다. 추가 번역·전체 언어 검수는 0.12의 후순위 단계에서 마무리한다.
- **움직임:** 띠 아래 얇은 버건디 선의 위치·투명도만 변화시킨다. 기존 헤더 스윕을 늘리거나 반복하는 것이 아니라, 대기 구간 전용으로 분리한 국소적인 2D 연출이다. 퍼센트·완료율처럼 보이는 채움은 사용하지 않는다.
- **표시 기준:** 탭 선택의 기존 피드백은 즉시 시작한다. 다음 지면이 아직 표시되지 않은 상태가 120ms 지속될 때만 예고를 표시한다. 120ms는 깜빡임을 피하기 위한 초기 설계값이며 측정 결과가 아니다. 그 전에 전환이 가능하면 표시 예약을 취소하고 바로 이동한다.
- **종료 기준:** 최소 노출 시간이나 선의 한 주기를 채우기 위한 대기를 두지 않는다. 다음 지면을 표시할 수 있으면 즉시 예고를 제거하고 기존 모션을 시작한다. 기존 진입 모션이 가림막 뒤에서 미리 끝나거나 예고 해제 후 두 번 재생되지 않게 한다.
- **장기 대기·실패:** 1초 이상 계속되면 실제 준비 중임을 알리는 짧은 정적 안내를 함께 제공한다. 준비 실패는 명시적으로 알리고 다시 시도할 수 있게 한다. 실패를 무한 선 애니메이션이나 성공처럼 보이는 화면으로 감추지 않는다.
- **동작 줄이기:** 움직이는 선 대신 정적인 번호·화면 이름·준비 상태만 표시한다. 대기 여부를 장식의 움직임만으로 전달하지 않는다.

#### 입력과 전환 정책

- 이동 요청과 실제 표시 지면을 구분한다. 준비 중에도 현재 지면·스크롤 위치를 유지하고 메뉴는 계속 누를 수 있다. 화면의 제목·본문은 실제 표시 지면 기준이며, 예고만 다음 목적지를 가리킨다.
- 연속 탭은 마지막 요청만 채택한다. 표시 중인 메뉴로 돌아오면 대기·표시 예약을 취소하고 현재 지면을 그대로 유지한다. 이미 요청한 같은 메뉴를 다시 누르면 작업을 중복 생성하지 않는다.
- 준비 중 현재 지면에서 체형·사이즈가 변경되면 최신 데이터로 준비 요청을 갱신한다. 편집 시트나 inspector를 열면 대기 중 이동을 취소해 작성 도중 화면이 뒤늦게 바뀌지 않게 한다. 현재의 편집 중 메뉴 비활성화 규칙은 유지한다.
- **화면 전환 준비와 착장 계산 완료는 별개다.** 새 지면을 비차단 방식으로 표시할 수 있으면 의류 계산 완료까지 메뉴 이동을 붙잡지 않는다. 필요한 경우 기존의 착장 계산 중·실패 표시를 새 지면에서 계속 제공하며 이전 의류를 새 결과인 것처럼 표시하지 않는다.

## 10. 상태·오류·저장 경험

### 10.1 상태를 분리한다

```text
선택 상태: 어떤 체형·상품·사이즈를 선택했는가
편집 상태: 저장된 값인가, 유효한 초안인가, 잘못된 입력인가
저장 상태: 적용되지 않음 / 저장 성공 / 저장 실패
착장 상태: 미착용 / 계산 중 / 최신 결과 / 표시 불가
날씨 상태: 미연결 / 요청 중 / 수신 / 실패
```

단일 ‘완료’ 표식으로 여러 상태를 합치지 않는다. 예를 들어 치수 저장은 성공했지만 착장 계산은 실패할 수 있다.

### 10.2 상태별 사용자 표현

| 상태 | 보여줄 정보 | 가능한 행동 | 피할 표현 |
| --- | --- | --- | --- |
| 샘플 날씨 | ‘미리보기 날씨 · 실제 위치 미연결’ | 피팅 사용, 날씨 연결 | 현재 위치의 실제 날씨처럼 표시 |
| 위치·날씨 실패 | 실패 사실과 수정/재시도 안내 | 피팅 계속 사용, 권한 확인 또는 재시도 | 빈 공간이나 무한 로딩 |
| 샘플 의류 | 반팔 샘플과 S/M/L 출처 | 선택, 직접 치수 입력 | 실제 사용자가 고른 상품 디자인이라는 암시 |
| 유효 초안 | ‘미적용 치수 미리보기’ | 적용, 취소, 계속 입력 | 저장 완료 체크 |
| 잘못된 입력 | 필드·범위·비율 오류, 미리보기의 기준 | 해당 필드로 이동, 수정, 취소 | 잘못된 값을 자동으로 정상값처럼 교체 |
| 착장 계산 중 | 예: ‘L 사이즈 착장 계산 중’과 이전 의류 숨김 안내 | 허용된 회전·탐색, 새로운 선택 | 이전 옷을 최신 결과로 표시 |
| 표시된 착장의 주의 사항 | 경고 아이콘·주의색과 원래 메시지 | 치수·계산 상세 확인, 새 선택 | 경고를 계산 실패나 정확한 핏 판정으로 대체 |
| 저장 성공 | 스크롤 밖 상단 체크·실제 변경 문구·성공 햅틱 한 번 | 안내 닫기, 계속 사용 | 선택·계산 완료를 저장 완료와 혼동 |
| 최신 결과 | 대응하는 입력값·몸 기준·근사 안내 | 비교, 상세 확인 | 정확한 실제 핏 보장 |
| 착장 표시 불가 | ‘이 치수의 착장을 표시하지 못했어요’와 구체적 이유 | 치수·소재·기준 확인 | 계산 실패를 ‘입을 수 없는 옷’으로 단정 |
| 저장 실패 | 실패 사실, 초안 보존과 다음 행동 | 수정·재시도·취소 | 성공 햅틱, 성공 문구, 오류를 숨기는 닫기 |
| 의류 미착용 | 미착용 상태 | 사이즈 선택 | 이전 상품 결과를 현재 착장처럼 유지 |
| 카탈로그 없음 | 샘플 의류를 사용할 수 없다는 안내 | 체형·날씨 이용 등 가능한 행동 | 다른 의류를 성공한 것처럼 대신 표시 |
| 최초 설정 미완료 | 선택·입력 단계와 저장된 초안 | 이어 입력하고 체형 저장 | 임의 남성 기본값을 개인 설정 완료로 취급 |
| 저장소 복원 실패 | 읽기/형식 오류와 기존 파일 보존 | 다시 불러오기 | 빈 저장소로 조용히 덮어쓰기 |
| 사이즈 없는 상품 | 상품 정보와 사이즈 추가 안내 | 사이즈 입력·상품 수정/삭제 | 임의 M을 해당 상품 실측처럼 자동 착장 |
| 지원 모델 없는 이전 기록 | 보존된 정보와 피팅 불가 이유 | 상품의 지원 템플릿·치수 확인 | 기록 삭제·무관한 모델 대체 |

현재 API로 제공할 수 없는 재시도·복원 행동은 버튼만 먼저 만들지 않는다. 행동이 없는 오류 화면에도 가능한 다음 단계를 설명한다.

### 10.3 최신 요청만 반영

- 몸 기준, 상품·사이즈 ID, 치수, 소재의 변경은 해당 계산 요청과 연결한다.
- 빠르게 S -> M -> L을 선택해도 늦게 도착한 S나 M 결과가 L 표시를 덮지 않아야 한다.
- 취소·탭 이동·편집 종료 이후의 지연 작업이 폐기된 화면에 상태를 다시 적용하지 않아야 한다.
- 모션용 지연과 실제 계산 지연을 분리한다. 네트워크·피팅 진행률을 임의로 만들어 표시하지 않는다.
- 기존 계산기와 요청 취소 정책을 재사용한다. 저장은 새 라이브러리의 원자적 쓰기로 확장했지만 디자인 컴포넌트에 별도 피팅 로직을 만들지 않는다.

### 11.2 논리적인 컴포넌트 구성

```text
앱 셸: 저장소 복원 -> 최초 체형 설정 또는 주 탭
  + 공통 헤더와 내비게이션
  + 화면별 지면
      + 표지: 배경 / 한 마네킹 / 제목 / 메타 / CTA
      + 피팅: 한 마네킹 / 선택 / 상태 / 도식 / 설명
      + 체형: 기준 미리보기 / 기록 / 편집 행동
  + 편집 시트 또는 inspector
  + 저장 체형 / 상품·사이즈 / 설정

공통 표현: 타이포그래피 / 선 / 캡션 / 버튼 / 선택 표시
모션 정책: Reduce Motion / 재생 여부 / 취소 / 시간 토큰
도메인 상태: 프로필 / 상품 / 사이즈 / 선택 / 초안 / 저장
기존 계산: 신체 변형 / 치수 적용 / 착장·충돌 / 최신 요청
```

이는 책임 구조이며 동일한 이름의 새 파일을 모두 만들라는 뜻이 아니다. 반복과 상태 결합 문제가 실제로 있는 부분만 추출한다.

### 11.3 API 선택 기준

현재 [프로젝트 설정](../weashion/weashion.xcodeproj/project.pbxproj)은 iOS 배포 대상 26.1이다. 이 기준에서 필요한 API를 사용하되 배포 대상을 변경하는 작업은 포함하지 않는다.

| 기능 | 우선 접근 | 주의점 |
| --- | --- | --- |
| 눌림 | 기존 `ButtonStyle`과 공통 피드백 | 필드와 시스템 조작에 전역 축소 적용 금지 |
| 제목 등장 | 예약된 레이아웃 + `mask` + 제한된 offset | 줄별 뷰가 접근성에서 여러 제목으로 중복되지 않게 함 |
| 선택선 | 기존 `matchedGeometryEffect` | 같은 의미의 2D 요소만 연결, 3D 장면 복제 금지 |
| 스크롤 표현 | `visualEffect`·`scrollTransition` 등 필요한 하나의 경로 | 프레임마다 전체 화면 상태 갱신·비동기 작업 생성 금지 |
| 폭 전환 | 동일 identity를 유지하는 `AnyLayout` | 장면·초점·작성 중 값을 보존 |
| 상태 아이콘 | 텍스트·아이콘 교체, 필요 시 `symbolEffect` | 선택·성공·실패 의미가 애니메이션에만 있지 않게 함 |
| 다단계 연출 | 필요성이 입증된 경우에만 `keyframeAnimator` | 기본 전환을 위해 복잡한 키프레임 시스템을 만들지 않음 |
| 시트·패널 | native inspector와 시스템 presentation | 키보드·size class·접근성 동작 보존 |

### 11.4 3D 장면과 모션의 경계

- 공통 화면 애니메이션이 실제 치수 계산이나 몸 변형을 보간하도록 연결하지 않는다.
- 같은 화면 안의 사이즈 변경과 반응형 전환은 기존 장면 identity를 유지한다.
- 오늘과 피팅룸 사이의 회전·확대·초점 공유는 0.9 구현을 유지한다. 0.10에서는 아래 11.5절의 제한으로 준비된 장면과 렌더 표면의 재사용까지 확장한다.
- 체형 기준 미리보기와 착장 미리보기의 의미는 구분한다. 재사용을 이유로 서로 다른 계산 결과나 시점을 같은 것으로 취급하지 않는다.
- 전환용 스냅샷이나 중복 3D 렌더러를 먼저 만드는 접근을 피한다. 비활성 화면의 렌더 비용도 함께 확인한다.
- 연출 취소 시 오래된 작업이 다시 상태를 변경하지 않도록 화면 수명과 작업을 연결한다.

### 11.5 전환 세션·3D 재사용·계산 분리 · 0.10 확정 설계

**상태: 0.13에서 핵심 구현·집중 검증 완료.** 기존에는 탭 지면을 교체할 때 신체·의류 컨트롤러와 렌더 표면을 다시 준비했고, 동기 신체 준비 1회가 단위 계측에서 약 1.456초 걸렸다. 현재는 메뉴보다 오래 사는 준비 상태와 주 메뉴용 `SCNView` 하나를 사용한다. `BodyPreviewRenderer` actor가 신체 변형·법선·충돌 데이터를 준비하고 비동기 메시 생성 후 장면에 부착한다. 본체·의류의 변경 revision과 시점을 UIKit 표면에 명시적으로 전달해 비동기 완료도 반영한다. 최초 네이티브 geometry 변환·GPU 준비는 여전히 별도 측정 대상이며 모두 백그라운드화한 것은 아니다.

아래는 유지할 설계 계약이다. 모드별 최신 상태 두 개와 최신 fitting 결과 하나로 보관 범위를 제한한다. **0.15에서 메모리 경고에 따른 비활성 자원 해제를 구현했다.** 대기 이동을 취소하고 현재 모드를 보존하며 비활성 상태를 교체한다. 분리된 표면의 이전 장면 참조와 actor 계산 캐시도 해제한다. 표면이 실제 표시 중인 상태는 해제하지 않으며 재방문 때 필요한 결과를 다시 준비한다.

#### A. 메뉴보다 오래 사는 준비 상태

- 주 화면 상위에 하나의 전환·3D 세션을 두고, 가벼운 지면 뷰의 수명과 완성된 모델의 수명을 분리한다. 기존 저장 모델·ID·피팅 수식은 변경하지 않는다. 책임을 분리한다는 뜻이지 모든 역할별로 새 파일·범용 관리자를 추가한다는 뜻은 아니다.
- 오늘 ↔ 피팅룸은 같은 체형·상품·사이즈라면 준비된 신체, 착장, 결과 설명과 네이티브 장면을 재사용한다. 단순 메뉴 이동은 신체 변형·메시 생성·의류 settling을 새로 요청하는 이유가 되지 않는다.
- 주 메뉴용 렌더 표면은 세션이 보유하고 활성 지면의 표시 슬롯에서만 사용한다. 장면의 실제 부착·분리는 메인 스레드에서 처리한다. 한 `SCNView`를 동시에 두 부모에 붙이지 않으며, 전환용 스냅샷이나 숨겨진 탭별 실시간 렌더러 세 개를 만들지 않는다.
- 체형 기준과 착장 모드는 결과 의미를 구분해 각각 현재 요청에 필요한 준비 상태만 보존한다. 오늘·피팅룸의 공유 시점과 내 체형·편집의 시점을 임의로 합치지 않는다. 비활성 모드에는 렌더 루프나 반복 업데이트를 유지하지 않는다.
- 레이아웃·캡션·조작부는 지면별로 기존 상태를 유지한다. 표지와 스튜디오의 높이·크롬 차이를 재계산 사유로 삼지 않고, 표시 슬롯에 맞춰 카메라·표면 배치만 적용한다. 크기 변경 때도 기존 구도·줌 동작을 보존한다.

#### B. 정확한 재사용 키와 무효화

- 신체 준비 키는 기준 모델, 실제 치수, 부위 조절값·형상 프로필, 필요한 계산 모드·알고리즘 버전을 포함한다. 신체 렌더 표면만이 아니라 의류 충돌 메시·앵커·핏 프로필도 같은 요청에 대응해야 한다.
- 착장 준비 키는 신체 키, 의류 패턴·치수·물성·계산 버전을 사용한다. 표시 이름·색상 등의 변화는 계산과 표시 갱신을 구분하고, 저장하지 않은 유효한 편집 초안도 정식 저장값과 혼동하지 않는다.
- 위 물성은 기존 의류 계산 템플릿의 설정을 뜻한다. 날씨 추천용으로 사용자가 선택한 재질명·두께를 새로 3D 물성에 연결하지 않으며, 이 메타데이터만 바뀌었다고 신체·착장을 재계산하지 않는다.
- 기존 `BodyPreviewRenderer`의 actor 기반 준비와 `GarmentDraper`의 메모리 제한 캐시·취소 규칙을 우선 활용한다. 새 계산 경로나 중복된 무제한 캐시를 만들지 않는다.
- 같은 요청의 진행 중 작업은 중복 시작하지 않는다. 마지막 이동 요청을 토큰으로 구분해 오래된 준비 완료·오류·타이머가 현재 지면을 바꾸지 못하게 한다. 이동 취소가 다른 유효한 소비자의 공유 작업까지 잘못 취소하지 않게 한다.
- 앱 세션에서 현재 모드별 최신 결과와 필요한 진행 작업만 유지한다. 메모리 경고에서는 비활성 자원을 먼저 해제하고, 현재 표시 결과를 갑자기 없애거나 저장 파일을 캐시 용도로 바꾸지 않는다.

#### C. 메인 스레드와 작업 actor의 경계

- 신체 에셋 읽기·변형·법선·충돌 데이터·SceneKit용 버퍼 준비처럼 순수 데이터 계산은 작업 actor로 옮긴다. actor 사이에는 `Sendable` 준비 데이터만 전달한다.
- `Entity`, UIKit·SceneKit 뷰와 공유 가변 장면은 작업 actor에서 직접 수정하지 않는다. 지원되는 비동기 메시 생성 API와 기존 `BodySurfaceMesh.Prepared` 패턴을 사용하고, 최종 장면 부착·짧은 상태 반영만 메인 스레드에 남긴다.
- 남는 네이티브 geometry 생성·GPU 준비는 재사용으로 빈도를 줄이고 별도 측정한다. `Task {}`로 감싸거나 `main.async`·`Task.yield()`로 한 번 미루는 것만으로 메인 스레드 분리가 끝났다고 보지 않는다.
- 보조 연출을 시작한 직후 같은 스레드에서 동기식 모델 생성을 실행하지 않는다. 렌더 표면 부착 비용도 함께 확인해 예고 선 자체가 준비 중 멈추는 일을 막는다. 반복 선은 작은 합성 레이어에서 처리하고 매 프레임 큰 화면 상태를 갱신하지 않는다.

#### D. 실제 화면 교체 시점

- 전환 완료는 애니메이션 종료가 아니라 최신 요청의 지면을 표시할 수 있는 시점으로 정한다. 캐시 적중은 즉시 기존 전환을 시작하고, 준비가 필요한 경우에만 9.7절의 예고를 허용한다.
- 다음 지면의 레이아웃과 비차단 3D 표시 경로가 준비되면 실제 표시 탭을 갱신한다. 그때 기존 헤더 스윕·제호·제목 등의 진입을 원래 시간과 강도로 재생한다. 의류 계산 완료나 보조 선의 주기를 기다리지 않는다.
- 준비 실패는 해당 요청의 명시적 오류 상태로 처리하고 예고의 무한 반복을 끝낸다. 현재 지면과 데이터를 보존하며 재시도를 제공한다. 더 최신 요청이 있으면 오래된 실패가 현재 화면에 표시되지 않게 한다.

### 12.4 접근성 수용 기준

- [ ] 모든 조작 영역이 최소 44×44pt이며 겹치는 터치 영역 때문에 다른 행동이 실행되지 않는다.

### 12.5 성능 목표와 측정 방법

| 항목 | 초기 목표 / 확인 방법 | 실패 시 조정 순서 |
| --- | --- | --- |
| 터치 반응 | 활성 버튼의 시각적 반응이 통상 100ms 안에 시작하는지 확인. 연출을 위한 입력 대기 0ms | 지연 제거 -> 메인 스레드 작업 분리 -> 장식 축소 |
| 스크롤·전환 | 60Hz에서 프레임 예산 약 16.7ms를 기본 목표로 프로파일링. 120Hz 유지가 목표인 구간은 약 8.3ms 조건도 별도 확인 | 배경 효과 -> 마스크 범위 -> 레이아웃 무효화 순으로 점검 |
| 심한 끊김 | 자산 준비 후 30초 왕복 스크롤 시 100ms 이상 정지 구간 0회를 초기 목표로 기록 | 중첩 효과·동기 작업·반복 디코딩 제거 |

| 연속 사이즈 변경 | 마지막 선택과 결과의 대응, 조작·스크롤 반응 유지 | 장식 우선 중지, 계산 취소·최신 요청 처리 점검 |

- 숫자는 제품 목표이며 현재 실측 결과가 아니다. 가변 주사율·발열·저전력 모드 등 실제 조건을 기록한다.
- 표시 주사율과 CPU/GPU 작업 시간을 혼동하지 않는다. 화면 녹화만으로 정확한 프레임 성능을 통과 처리하지 않는다.
- 필수 계산 품질이나 실패 안내를 숨겨 성능 목표를 맞추지 않는다. 장식 효과를 먼저 줄인다.
- 과도한 블러, 다중 그림자, 전체 화면 마스크, 고해상도 이미지 중복 디코딩을 피한다.
- 결과 기록은 기기/OS, 창 크기, 글씨·접근성 설정, 조작 순서, 관찰 결과, 미해결 항목으로 남긴다.

#### 0.13 집중 검증 결과

- 관련 단위 테스트 **28건**, 메인 UI 여정 **1건** 통과. 초기 표지의 실제 착장 표시, 내 체형 진입, 오늘·피팅룸 왕복과 시점 유지, S → L 최신 치수 차이를 확인했다. 단위 테스트는 같은 요청 20회 재사용 때 신체·착장 재계산과 네이티브 geometry 추가 생성이 없고 주 메뉴 표면 생성이 1회임을 내부 카운터로 확인한다. 이는 실기기 20회 왕복 메모리 프로파일링을 대체하지 않는다.
- 빠른 준비의 예고 생략, 느린 준비의 예고·최신 선택, 현재 메뉴로 복귀 취소, 준비 실패 시 기존 지면 유지·명시적 오류를 단위 테스트로 검증했다. 실제 의류 계산 완료까지 메뉴 이동을 기다리지 않는다.
- 녹화·중간 프레임과 완료 이미지를 확인해 제호·제목 진입, 기존 지면 구성과 준비된 마네킹 표시가 유지됨을 확인했다. 초기 준비·착장 계산 중에는 표지와 접근성 값에도 실제 준비 상태를 제공한다.
- 변경 전 동기 신체 준비는 약 **1.456초**, 변경 후 신체 준비 중 메인 actor 응답 확인은 마지막 실행에서 약 **0.227ms**였다. 서로 다른 측정 대상이므로 속도 향상률로 나누지 않는다. 캐시 영향을 받는 비동기 준비 시간·합성 재사용 루프·전체 UI 테스트 시간도 실제 탭 지연으로 보고하지 않는다.
- **후속 반영:** 0.15에서 메모리 경고 해제, 재현된 입력 포커스 문제, 저장·취소·복원 핵심 경로와 날씨 상태 처리를 보강·집중 검증했다. **여전히 미측정:** 입력 → 지면 표시 → 3D 첫 프레임의 실기기 시간, 프레임·메모리·발열·햅틱 프로파일링, 실제 위치·WeatherKit 수신. 전체 언어·반응형 검수와 출시 자료는 후순위로 유지한다.

| 2 | 3D 재사용 + 메인 스레드 계산 분리 | 핵심 구현·내부 카운터 검증 완료. 0.15에서 메모리 경고 해제·현재 상태 보존·재준비도 단위 검증. 실기기 프로파일링은 사용자 선택으로 보류 |
| 3 | 대기 구간 전용 다음 지면 예고 | 구현·단위 검증 완료. 120ms 이상 실제 대기에만 표시하고 준비 즉시 제거. 기존 모션과 의류 계산의 비차단 정책 유지 |
| 4 | 안정화·날씨 처리와 회귀 검증 | 고유 단위 55건·핵심 UI 여정 4건 통과. 입력·저장·취소·복원과 위치·날씨 상태 처리 보강. 실제 WeatherKit 수신·실기기 성능 측정은 남음 |
| 5 | 치수 도식 연결 포커스 | 구현·단위/UI 검증 완료. 측정 번호·목록·선의 2D 강조만 연결하고 계산·저장값은 변경하지 않음 |
| 6 | 사용자 옷 사진 아카이브 | 장기 방향 확정·미구현. 로컬 이미지 저장 계약·이전 데이터 호환·썸네일 처리를 갖춘 뒤 추가 |

2~3은 같은 전환 흐름으로 설계하되 원인을 구분해 측정한다. 치수 포커스는 독립적으로 추가·검증했다. 사진 기능을 먼저 끼워 넣거나 추가 효과로 성능 미달을 가리지 않는다. 정면·측면·후면 바로보기와 오늘 지면 목차는 이 목록에서 제외했다.

### 13.3 현재 안정화와 후순위 검증

**현재 우선**

- 실기기 전환·스크롤·초기 메시 준비·메모리·발열·햅틱은 사용자 선택으로 보류했다. 시뮬레이터 영상으로 60fps·무지연을 보장하지 않는다.
- 재현한 입력 포커스·편집 취소·저장·재실행 복원·연속 선택은 0.15에서 통과했고 0.16 개편 후 관련 UI 10건으로 변경 경로를 집중 확인했다. 새 실패가 생기면 해당 경로만 재현하고 전체 테스트를 무조건 반복하지 않는다.
- 위치·날씨의 권한·시간 제한·실패·재시도·최신 응답은 단위 검증했다. 실제 위치 수신·WeatherKit 서명과 네트워크 수신 검증은 남아 있으며 샘플 날씨와 마지막 수신 데이터를 구분한다.

**사용자 요청으로 후순위 이관**

- 한국어·영어·일본어 번역·용어 감수와 iPad·좁은 창·큰 글씨·키보드 등의 전체 화면·배치 검수. 기존 언어 기능은 유지하며, 변경 코드에 직접 관련된 필수 입력·표시 확인과는 구분한다.
- 출시용 앱 아이콘·세 언어 스크린샷·스토어 설명·위치 정보 사용 범위와 개인정보 안내 준비. 사진 기능을 출시 범위에 넣을 경우 사진 보관·삭제 안내도 함께 준비한다.

### 13.4 별도 제품 확장과 제외 항목

- **별도 기능 확장:** 긴팔·니트·아우터·바지·신발의 3D 메시와 종류별 치수 계약 → 레이어링·충돌 검증 → 날씨 추천 옷을 실제로 입은 표지 순으로 검토한다. 현재의 코튼 반팔 외 종류는 기록·날씨 추천용이며, 지원 플래그만 바꿔 3D 착장을 제공하지 않는다.
- **추가 옷장 후보:** 종류별 필터, 추천에 쓰인 상품 표시, 샘플 추천에서 상품 추가로 가는 연결은 후속 후보이며 이번 확정 요소의 자동 구현 범위가 아니다.
- **제외:** 정면·측면·후면 바로보기, 오늘 지면 목차, 원단 스와치·선택 재질의 3D 시각화·실제 착용감 재현 약속, 전환용 스냅샷, 중복 실시간 마네킹, 로딩을 위한 강제 대기, 기존 모션 약화.
- **미채택 후보:** 미니 치수 자·종이 질감은 이번 0.11 확정 범위에 포함하지 않는다. 사진 등록만으로 3D 복원·재질 판정·자동 치수 추정을 제공하지 않는다.

### 13.5 추가·유지한 회귀 코드와 남은 검증

- [EditorialDesignTests.swift](../weashion/weashionTests/EditorialDesignTests.swift): 치수 변환, URL·날씨, 모션 정책, 제목의 접근성 모션 제외, 700pt 경계·장면 높이 상하한, 계산 중 오래된 의류 숨김
- [FittingLibraryTests.swift](../weashion/weashionTests/FittingLibraryTests.swift): 최초 설정·체형 관리·상품별 사이즈·중복/범위 검증·삭제·이전 데이터·손상/지원하지 않는 형식·쓰기 실패
- [weashionUITests.swift](../weashion/weashionUITests/weashionUITests.swift): 최초 설정·재실행, 상품과 자유 사이즈의 피팅 연결, 체형 추가, 표지→스튜디오→상품/체형 아카이브 연결과 실제 기록 수, 기존 단일 마네킹·입력·탐색 회귀

- 새 모션의 반복·중단·큰 글씨·접근성 동작은 필요한 회귀 사례를 추가하되, 테스트 번들 컴파일과 테스트 실행 결과를 구분한다.
- 문서만 수정하는 단계에는 앱 빌드나 테스트 실행이 필요하지 않다.

## 14. 추가 결정 사항과 최종 원칙

### 14.1 구현 전에 별도 결정할 항목

| 항목 | 권장 출발점 | 별도 결정이 필요한 이유 |
| --- | --- | --- |
| 추가 서체·서체 교체 | 현재 승인된 번들 서체와 언어별 역할 유지 | 기존 조판 영향·대체 글리프·임베딩 권리 |
| 외부 패션 사진 | 사용자 등록 옷 사진은 5.10절의 장기 확정 방향이며 외부 스톡 사진은 별도 | 라이선스·출처·사용자의 상품으로 오인 가능성 |
| 독립 기사 화면 | 이번 범위에서 추가하지 않음 | 콘텐츠 공급과 내비게이션 확장 |
| 좋아요·북마크·비교 이력 | 현재 범위에서 추가하지 않음 | 단순 상품/사이즈 보관과 다른 기능·데이터 의미 |
| 추가 화면의 3D 공유 범위 | 주 메뉴의 재사용은 11.5절로 확정, 편집·다중 비교까지 무조건 확장하지 않음 | 장면 수명·메모리·복귀 동작 영향 |
| 추가 장식적 배경 확대 | 기존 배경 시차를 유지하고 새 확대는 자동 추가하지 않음 | 기존 승인 모션 보존·성능·산만함 |
| 기존 모션·구도 변경 | 0.16의 적극적인 전체 개편은 백업 후 실행하도록 승인됨. 이후 추가 방향 변경은 별도 구분 | 기능·데이터·3D 재사용을 지키고 승인된 재디자인과 성능 결함 수정을 혼동하지 않음 |

### 14.2 하지 않을 디자인

- 고급스럽게 보이기 위해 모든 정보를 작고 흐리게 만드는 디자인
- 큰 제목과 장 번호가 마네킹·치수·버튼을 밀어내는 디자인
- 모든 화면에 같은 카드와 같은 모션을 반복하는 디자인
- 사이즈 차이를 몸의 확대·축소나 가짜 상품 이미지로 표현하는 디자인
- 오류를 숨기고 보기 좋은 결과만 남기는 디자인
- 소개·전환이 끝날 때까지 사용자가 기다려야 하는 디자인
- 화면 사이의 연결을 위해 동일 마네킹을 여러 개 겹쳐 표시하는 디자인
- 사용자가 요청하지 않은 기사·쇼핑·소셜 기능을 매거진 분위기 때문에 추가하는 디자인

### 14.3 최종 판단 기준

> 매거진처럼 보이기 위해 기능을 희생하지 않는다.
>
> 감상은 풍부하게, 비교는 일관되게, 입력은 정확하게 만든다.
>
> 모션은 장식의 양이 아니라 행동과 정보의 관계를 설명하는 품질로 판단한다.
>
> 중심에는 언제나 사용자의 한 몸과 그 위에서 비교하는 의류가 있어야 한다.
