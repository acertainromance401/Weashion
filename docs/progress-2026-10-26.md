# WEASHION 컨셉 및 현재 구현

- 기준일: 2026-10-26
- 범위: 개인 마네킹 기반 가상 피팅 컨셉, 최신 몸체 상태, 의상 재구성·치수 입력·비교·확인 결과
- 상태: 코드와 번들 리소스 연결 및 직접 타입 확인 완료. 실제 계산과 Blender 렌더를 확인했으며, 이번 의상 작업에서 앱 전체 빌드·설치·실기기 실행은 하지 않았다.

## 1. 제품 컨셉

> 고정된 내 개인용 마네킹에 쇼핑몰에서 본 옷의 사이즈를 가상 피팅해서 내가 입으면 어떨지 상상해본다.

신체를 먼저 설정하고, 비교 중에는 같은 몸을 유지한 채 의상 치수와 사이즈를 바꾼다. 상품의 기준 치수와 착장 후 보정된 표면의 치수를 구분한다. 목표는 숫자로 된 사이즈표를 개인 체형의 시각적 비교로 연결하는 것이며, 현재 정확한 구매 사이즈나 실제 착용 가능 여부를 판정하지 않는다.

```text
신체 치수·체형 설정 → 동일한 개인 마네킹 유지
→ 준비된 의상 선택 → 상품 사이즈 또는 실측 치수 입력
→ 옷 자체의 크기 변경 → 착장 및 정적 겹침 보정
→ A/B 모습·가슴 여유·입력 치수·착장 후 근사 치수 비교
```

날씨와 Outfit 추천은 이 경험을 보완하는 기능이다. 쇼핑몰 상품 자동 수집, 임의의 이미지에서 의상 생성, 앱 내 GLB/Blender 직접 가져오기는 아직 제공하지 않는다.

## 2. 현재 몸체

| 앱용 메시 | 정점 | 삼각형 |
| --- | ---: | ---: |
| 남성 | 12,082 | 24,192 |
| 여성 | 15,991 | 31,986 |

- 고밀도 Blender 원본은 보존한다. 앱은 [남성 JSON](../weashion/weashion/Resources/male_body_40k.json)과 [여성 JSON](../weashion/weashion/Resources/female_body_40k.json)을 읽는다. `40k`는 파일명 호환용이며 현재 삼각형 수가 아니다.
- [MannequinMesh](../weashion/weashion/Models/MannequinMesh.swift)가 키·인심·어깨너비·가슴/허리/엉덩이 둘레·팔다리 굵기·발 길이를 보정한다. 표시 정점에서 의류 단면과 충돌 밴드를 함께 계산한다.
- [BodyAnatomy](../weashion/weashion/Models/BodyAnatomy.swift)는 36개 부위와 23개 표면 추정 기준점을 사용한다. 편집 화면에는 좌우를 함께 조절하는 22개 세부 슬라이더가 있다. 실제 골격 관절을 측정하거나 외부 모델에 리깅한 것은 아니다.
- 남성은 마름·보통·지방형·근육형 프리셋과 BMI 기반 시각적 분포 변화를 제공한다. 가슴·허리·엉덩이 자동 추정과 수동값을 구분하고 수동값을 보존한다. 여성에는 이 프리셋을 적용하지 않는다. 체지방률·근육량 추정의 의학적 정확도를 의미하지 않는다.
- [BodyPreviewRenderer](../weashion/weashion/Models/BodyPreviewRenderer.swift)는 actor에서 계산하고 기본 표면·부위 변위를 캐시한다. 최신 요청을 합치고 약 40ms 간격으로 처리를 제한한다. 실기기 FPS나 발열을 측정한 결과는 아니다.
- 기존 생성형 몸체의 단면·충돌 유틸리티는 재사용하지만 기존 관절 스켈레톤이 외부 메시를 구동하지는 않는다. 정확한 인체 복원·자유 포즈·IK는 현재 범위가 아니다.

## 3. 의상 원본과 최종 리소스

| 구분 | 정점 | 삼각형 | 용도 |
| --- | ---: | ---: | --- |
| Meshy 그레이 티셔츠 원본 | 343,758 | 687,781 | 보존된 외형·주름 참고 원본 |
| 최종 착장용 메시 | 3,038 | 5,952 | 앱에서 치수 변경 및 착장 계산 |

- [원본 Blender](../Meshy_AI_Gray_T_Shirt_1026125442_generate.blend)는 변경하지 않았다.
- 단순 감량·입체 변환 후보에서 앞뒤 면과 연결 문제가 발생했다. 최종본은 안정적인 티셔츠 연결 구조에 원본의 주요 앞뒤 주름을 전사한 재구성 메시다. 원본 정점·토폴로지를 그대로 줄였다고 설명하지 않는다.
- [편집용 Blender](../weashion/Cotton_TShirt_Optimized.blend)와 [앱용 JSON](../weashion/weashion/Resources/meshy_cotton_tshirt.json)을 사용한다. 목·양쪽 소매·밑단은 열린 구조이며, 최종 생성 시 과다 연결 변 0과 퇴화 면 검사를 확인했다. 자체 교차가 전혀 없다는 증명은 아니다.
- 기존 파란 95·110 샘플은 [카탈로그](../weashion/weashion/Resources/garments.json)에서 제거했고, 절차적 티셔츠 생성 파일과 로더 분기도 삭제했다. 현재 카탈로그는 그레이 한 디자인의 S·M·L이며 `pattern.source: mesh`만 사용한다.

## 4. 상품 치수의 의미

제공된 사이즈표와 측정 도식 기준이다. 단위는 cm다.

| 사이즈 | 1 총장 | 2 어깨너비 | 3 가슴단면 | 4 소매길이 | 5 밑단단면 | 6 소매부리단면 | 7 암홀 |
| --- | ---: | ---: | ---: | ---: | --- | --- | --- |
| S | 61 | 51 | 52 | 18 | 미제공 | 미제공 | 미제공 |
| M | 63 | 53 | 54.5 | 19 | 미제공 | 미제공 | 미제공 |
| L | 65 | 55 | 56 | 20 | 미제공 | 미제공 | 미제공 |

- 총장: 현재 메시의 상단부터 밑단까지의 세로 범위.
- 어깨너비: 양쪽 어깨 봉제점 사이의 폭.
- 가슴단면: 펼친 의상의 가슴 폭. 내부에서는 두 배의 둘레를 미터로 변환한다. M의 54.5cm는 기준 가슴둘레 109cm이며, 입체 착장 정면 폭이 54.5cm라는 의미가 아니다.
- 소매길이: 어깨 봉제점부터 바깥 소매 끝까지. 중심축을 기준으로 삼아 약 5~6mm 짧게 적용되던 계산을 수정했다.
- 밑단단면·소매부리단면: 펼친 폭으로 입력하고 내부에서는 두 배의 둘레로 변환한다. 미입력 값은 원본 비율이며 상품 실측값으로 간주하지 않는다.
- 암홀: 선택 입력 시 어깨와 겨드랑이 기준 높이 사이의 깊이를 조절한다. 봉제선의 전체 곡선 길이를 측정하는 기능은 아니다.

[GarmentSizing](../weashion/weashion/Models/GarmentSizing.swift)이 치수 입력과 미터 변환, 부위별 정점 변형을 수행한다. 현재 기준 메시의 실제 범위로 총장을 맞추며, 소매길이는 바깥쪽 측정점에 맞춘다. 의상 입력이 마네킹 치수를 수정하지 않는다.

## 5. 편집·착장·비교

- [GarmentEditorView](../weashion/weashion/Views/GarmentEditorView.swift)는 S·M·L 선택, 4개 기본 치수, 3개 선택 치수, 적용 전 착장 미리보기와 취소·적용을 제공한다.
- 메인 A/B는 같은 신체 데이터를 사용한다. 기본 의상 선택은 S/M이며 각 패널의 선택과 치수를 독립적으로 조절한다. 치수는 패널별 `AppStorage`에 저장한다. 여러 상품 등록·비교 이력 저장까지 구현한 것은 아니다.
- [GarmentFit](../weashion/weashion/Models/GarmentFit.swift)은 단면의 폭·깊이, 어깨와 소매 배치를 보정한다. 현재 `sizing` 경로는 옷이 작다는 이유로 목표 단면 둘레를 몸 크기까지 자동 확대하지 않는다. 다만 이후 충돌 보정은 정점을 이동하고 원래 변 길이를 늘릴 수 있다.
- [GarmentDraper](../weashion/weashion/Services/GarmentDraper.swift)는 Swift actor에서 준비·착장과 C++/Bullet 기반 정적 겹침 보정을 수행한다. 패턴/치수와 신체 식별자·리비전·기준점·계산기 버전으로 결과를 캐시한다. 준비 메시 16MB, 결과 8MB의 메모리 캐시는 앱 종료 시 사라진다.
- 표시 결과는 입력 총장·어깨·가슴단면·소매길이, 가슴 여유, 어깨 차이, 착장 가슴둘레(볼록 단면 근사), 착장 총장(수직), 최대 표면 늘어남이다. 단면 차이는 전체 옷의 모든 부위별 피부 간격이 아니다.
- 메시 형식은 `vertices`, `indices`, `trims`, 선택적인 `fitting`·`sizing`이다. 외부 메시의 `dimensions` 변형에는 유효한 `fitting`·`sizing`이 필요하다. 입력 한도는 12,000정점·40,000삼각형·JSON 16MB이며 실시간 성능 보장이 아니다.

## 6. 실제 확인 범위

### 의상 자체 치수

입력값 재출력이 아니라 변형 후 메시의 끝점·봉제점·가슴 단면을 확인했다.

| 사이즈 | 총장 | 어깨너비 | 가슴단면 근사 | 바깥 소매길이 |
| --- | ---: | ---: | ---: | ---: |
| S | 61.0 | 51.0 | 51.982 | 18.0 |
| M | 63.0 | 53.0 | 54.481 | 19.0 |
| L | 65.0 | 55.0 | 55.981 | 20.0 |

단위는 cm이며 가슴단면 기준값 대비 최대 차이는 약 0.2mm다. 이 결과는 현재 메시의 계산 일치도이며, 실제 상품 제작 오차나 실착 정확도 검증은 아니다. 미제공 3개 치수를 실측 기준으로 검증했다고 주장하지 않는다.

### 착장 계산과 렌더

남성 기본 175cm/70kg, 어깨 45cm, 가슴 98cm, 허리 82cm, 엉덩이 98cm, 인심 82cm, 팔·다리 배율 1을 사용해 실제 Swift·C++ 계산을 실행했다. 같은 체형의 S·M·L 착장 위치를 Blender에서 비교 렌더링했다.

- 한 실행에서 검사 지점의 잔여 겹침은 0mm였지만 최대 표면 늘어남은 약 78~98%였다. 이는 변 길이 기반의 시각적 변형 지표이며 실제 면 원단이 그만큼 늘어날 수 있다는 뜻이 아니다.
- 겨드랑이·연결부 보정량과 외형 차이가 남아 있다. 샘플 지점의 겹침 0은 모든 삼각형의 관통 없음이나 정확한 착용 가능 여부를 증명하지 않는다.
- 이후 소매 측정 기준을 보정하고 자체 치수와 관련 Swift 코드 타입을 다시 확인했다. 78~98%는 해당 보정 이전 착장 실행의 관찰 범위이며 최종 소매 보정 후 모든 착장을 다시 측정한 수치가 아니다.
- iOS SDK 직접 타입 확인은 통과했다. 이번 의상 작업에서 앱 전체 빌드·설치·시뮬레이터·실기기 화면 및 성능 확인은 하지 않았다. 임시 macOS 계산·Blender 렌더와 실기기 앱 검증을 구분한다.

## 7. 남은 한계와 우선 과제

- 소재 정보는 면뿐이며 조직·두께·혼용률·방향별 신축률은 미확인이다. `maximumStrain: 0.05`는 경고 기준이지 실측 면 신축률이나 물리적 변형 상한이 아니다.
- 현재 계산은 정적 겹침 보정이다. 중력·동적 주름·실제 봉제·천 자기충돌·실측 원단 물성 기반 피팅은 구현하지 않았다.
- 우선 과제는 큰 연결부 변형을 줄이고 실제 상품·착용 사진·원단 정보와 대조하는 것이다. 그 전에는 구매 판정이나 정밀 가상 피팅으로 표현하지 않는다.
- 여성 착장, 전체 치수 조합, 여러 겹 착장, 다양한 의상 종류, 실기기 품질·속도·메모리·발열은 이번 확인 범위에 포함하지 않는다.

[2026-10-07 기록](progress-2026-10-07.md)의 메시 수·파란 샘플·당시 미확인 상태는 해당 시점의 이력이다. 현재 상태는 이 문서와 [README](../README.md)를 기준으로 한다.
