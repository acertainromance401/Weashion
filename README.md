# WEASHION

> Weather + Fashion

## 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 서비스 | 날씨와 사용자의 신체 특성을 결합한 개인 맞춤형 패션 앱 |
| 핵심 경험 | 나와 유사한 3D Avatar가 오늘의 날씨와 Outfit을 보여줌 |
| 사용자 입력 | 키, 몸무게, 체형 및 세부 신체 치수 |
| 주요 기능 | 3D Avatar 생성, 체형 커스터마이징, 날씨 분석, Outfit 추천 |
| 플랫폼 | iOS / iPadOS |
| 핵심 기술 | SwiftUI, RealityKit, WeatherKit, Core Location, SwiftData |

### 핵심 가치

**ME** 개인화된 3D Avatar · **WEATHER** 현재 지역의 실제 날씨 · **FASHION** 날씨와 사용자 조건에 맞는 Outfit

### 사용자 경험

```text
신체 정보 입력 → 3D Avatar 생성 → 체형 조정
→ 위치 기반 날씨 확인 → Outfit 추천 → 날씨 환경과 함께 확인
```

### 개발 우선순위

1. 3D Avatar와 체형 커스터마이징
2. 기본 의상 적용 및 Outfit 구성
3. 위치 기반 날씨 연동
4. Rule-based Outfit 추천
5. 날씨별 3D 환경과 애니메이션

### 현재 몸체 구현

2026-10-07 기준으로 생성형 마네킹 표시를 외부 전신 에셋 기반으로 전환했다. 작업 수치, 데이터 형식, 수정 이력 및 확인 범위는 [상세 진행 기록](docs/progress-2026-10-07.md)에 정리했다.

- 남녀 Blender 원본은 보존하고 각각 40,000삼각형으로 경량화했다. 남성은 19,994정점, 여성은 20,002정점이며, 경량화 사본은 각각 약 1.1MB다.
- 앱은 Blender 파일을 직접 읽지 않는다. [남성 JSON](weashion/weashion/Resources/male_body_40k.json)과 [여성 JSON](weashion/weashion/Resources/female_body_40k.json)을 번들에서 읽고 [MannequinMesh](weashion/weashion/Models/MannequinMesh.swift)가 체형을 보정한다. 좌표는 미터 단위, `+Y` 위쪽, `+Z` 앞쪽이며 발바닥 높이는 0이다.
- [WEASHIONMannequin](weashion/weashion/Views/WEASHIONMannequin.swift)은 남녀 선택에 따라 전신 메시를 교체한다. 별도 머리·귀·손가락·엄지·손발톱을 생성하던 표시 코드는 제거했다. 원본에 합쳐져 있는 속옷 형태는 유지한다.
- 키·인심·어깨너비·가슴/허리/엉덩이 둘레와 팔다리 굵기를 CPU에서 보정한다. 몸무게는 팔다리 굵기에 제한적으로 반영한다. 단면은 볼록 외곽선을 사용하며, 팔 경계 가중치를 12회 평활화하고 팔 간격 보정은 허리·엉덩이 높이에만 적용한다.
- 화면에 표시할 정점에서 의류 피팅 프로필과 충돌 밴드를 함께 계산한다. [ParametricBody](weashion/weashion/Models/ParametricBody.swift)의 측정 타입과 단면·충돌 유틸리티를 재사용하지만 기존 생성형 몸체나 [BodySkeleton](weashion/weashion/Models/BodySkeleton.swift)의 관절 스키닝이 새 에셋을 구동하는 것은 아니다. 기존 생성기·스켈레톤 및 관련 테스트 코드는 남아 있다.
- 새 에셋에는 리깅, Shape Key, UV 맵, 이미지 텍스처가 없다. 체형 보정은 부위별 근사 변형이며 인체 스캔, 정확한 체형 복원, 자유 포즈·IK·애니메이션을 제공하지 않는다. 어깨너비 등은 모델에 지정한 기준점에 의존하므로 실측 정확도를 보장하지 않는다.
- 전체 앱 소스의 iOS SDK 직접 타입 검사, 실제 Swift 변형 코드 실행 및 결과 메시의 Blender 정면·측면·후면 비교를 완료했다. 새 에셋으로 앱 전체 빌드·실기기 실행·의류 착장·전체 치수 범위를 확인한 것은 아니다. 기존 생성형 몸체의 테스트 결과를 새 에셋의 검증 결과로 간주하지 않는다.

### 현재 착장 구현

의류 사양은 [샘플 카탈로그](weashion/weashion/Resources/garments.json)에 있고, 데이터 형식은 [GarmentDefinition](weashion/weashion/Models/GarmentDefinition.swift)이 정의한다.

```text
카탈로그 → 원본 메시 → 부위별 여유분·변형 → 신체 겹침 보정 → 공통 렌더러
```

- `pattern.source: cottonTShirt`: `dimensions`의 치수로 티셔츠를 생성한다. 단위는 미터이며 신체 크기에 맞춰 기준 치수를 변경하지 않는다.
- 티셔츠는 `chestCircumference`, `waistCircumference`, `hipCircumference`에 맞는 원본 단면을 만든다. 허리·엉덩이 둘레를 생략하면 가슴둘레를 사용한다. 현재 두 샘플은 각 부위 둘레가 같은 스트레이트 형태다.
- 몸의 가슴·허리·엉덩이는 변형 후 단면을 측정해 입력 둘레로 보정하며, 같은 보정 표면에서 충돌 형상을 만든다. 새 에셋의 기준 높이는 원본 신장의 73.5%, 62.5%, 53.5%이며, 키·인심 변경에 따라 함께 변환한다. 이는 앱 내부 기준점이며 의류 브랜드의 실측 기준을 검증한 것은 아니다.
- [GarmentFit](weashion/weashion/Models/GarmentFit.swift)은 원본 단면과 몸 단면의 여유분으로 부위별 변형을 계산한다. 여유가 있으면 단면 둘레를 유지하며 폭·깊이 배분과 처짐을 조절하고, 부족하면 해당 단면을 확장한다. 실제 변형된 팔 단면에서 몸통과의 간격을 구해 겨드랑이 분기 높이와 소매 끝을 배치하고, 옆선이 팔 내부에서 시작하지 않도록 조절한다. 새 마네킹은 남성의 내린 팔과 여성의 A 포즈를 기초로 하며, 체형 보정 중 팔 위치가 바뀔 수 있다. 전체 옷의 Scale 변경은 적용하지 않는다. 티셔츠 템플릿의 기준 체형은 키 175cm, 가슴 98cm, 허리 82cm, 엉덩이 98cm다.
- `pattern.source: mesh`: `meshResource` 이름의 번들 JSON을 읽는다. 확장자를 제외한 리소스 이름을 지정하고, 메시를 변경하면 `pattern.version`도 변경한다.
- 메시 JSON은 `vertices`(정점별 `[x,y,z]`), `indices`(삼각형 정점 인덱스), `trims`를 가진다. 각 마감은 `vertices`(연결된 정점 인덱스), `radius`, `ribbonWidth`로 정의하며 마감이 없으면 `trims`는 빈 배열이다.
- 선택적인 `fitting`은 원본 단면, 기준 둘레, 정점별 가중치를 저장한다. `regions`의 순서는 엉덩이·허리·가슴·어깨이며 합은 1이다. `sleeveProgress`는 소매 부착점에서 끝까지의 영향 비율이다. 이 데이터가 없는 외부 메시는 기존 충돌 보정만 적용한다.
- 메시 좌표는 선택한 신체 기준점에 대한 미터 단위이며 `+Y`가 위, `+Z`가 앞이다. `pattern.anchor`는 `shoulders`(기본값) 또는 `waist`다. 준비된 메시는 봉제 연결과 원단의 기준 길이를 이미 반영해야 한다.
- 현재 의류 자산 입력 한도는 12,000정점, 40,000삼각형, 메시 JSON 16MB다. 신체 에셋 로더와는 별도의 한도다. 의류의 퇴화 삼각형과 면에 연결되지 않은 정점은 허용하지 않는다. 이 한도는 실시간 성능 보장이 아니다.
- [GarmentDraper](weashion/weashion/Services/GarmentDraper.swift)는 메시 생성·로드·버퍼 준비·신체 겹침 보정을 화면 처리와 분리한다. 준비된 메시와 착장 결과의 캐시는 데이터 용량 기준 각각 16MB, 8MB이며, 메모리 내 캐시로 앱 종료 시 사라진다.
- 착장 결과 키에는 패턴·신체 식별자/리비전·배치 기준점·계산기 버전이 포함된다. 색상이나 경고 기준만 바뀌면 보정 결과를 공유하고, 신체 충돌 환경은 가장 최근 체형 하나를 재사용한다.
- 현재는 중력·주름·자기충돌 시뮬레이션 대신 체형별 볼록 충돌체의 평면식을 미리 계산해 재사용한다. 높이별 인덱스와 경계 상자로 후보를 줄이고, 여러 방향의 광선과 평면식으로 겹친 충돌체의 합집합을 빠져나가는 이동을 선택한다. 이는 후보 방향 중의 근사이며 정확한 최단 거리 계산은 아니다. 정점과 삼각형의 변 중점·중심을 검사하고, 형태 보정을 최대 12회 수행한 뒤 초기 위치로 되당기지 않는 접촉 정리를 최대 8회 수행한다.
- 연속 체형 입력은 120ms 동안 묶고, 반복 계산 내부에서도 취소를 확인한다. 새 모델이 준비되면 기존 옷과 교체하며, 실패 시에는 이전 옷을 새 결과로 오인하지 않도록 제거한다. 초기 착장과 단순 의류 선택에는 입력 대기를 추가하지 않는다.
- 보정량이 크거나 검사 지점에 겹침이 남아도 옷은 표시하고 경고한다. `material`에는 보정 경고 기준인 `maximumStrain`만 남겨 두며, 사용하지 않는 원단 물성 필드는 제거했다. 검사 지점 사이의 모든 면 충돌을 보장하지 않으며, 기기에서 표시 품질이나 속도 개선율을 측정하지 않았다.
- 늘어남은 핏 변형 전 원본 변 길이를 기준으로 계산한다. 처짐과 방향별 변형은 시각적 근사이며 실제 장력이나 원단 거동의 물리적 예측이 아니다. 체형·의류 변경 시에만 계산하며 의류 자체에는 주름 시뮬레이션이나 관절 스키닝을 적용하지 않는다.
- 에셋 전환 이전의 생성형 마네킹에서는 기본 175cm 남녀 체형의 95·110 샘플을 시뮬레이터에서 정면·측면·후면으로 확인한 기록이 있다. 해당 네 착장의 표면 샘플 잔여 보정 거리는 최대 약 0.05mm였지만, 일부 변의 늘어남은 원단 경고 기준을 초과해 경고를 유지했다. 이 기록은 새 외부 에셋의 착장 검증 결과가 아니며, 새 남녀 모델의 착장은 실기기에서 재확인해야 한다.

현재는 단일 의류의 정적 미리보기 구조이며 실제 제품의 착용 가능 여부나 정확한 핏을 판정하지 않는다. 계산용/표시용 메시 분리, 여러 겹 착장, 원격 상품 배포 및 원단별 실측 물성 보정은 아직 포함하지 않는다. 다른 준비된 메시를 읽는 경로는 제공하지만, 옷 종류별 착장 품질이 검증된 것은 아니다.

## 1. 프로젝트 개요

이하 내용은 제품 기획과 목표 구조를 포함한다. 모든 기능의 구현 완료를 의미하지 않으며, 현재 구현 및 확인 범위는 문서 상단과 날짜별 진행 기록을 기준으로 한다.

### 1.1 프로젝트명

WEASHION

### 1.2 프로젝트명 의미

WEASHION은 **Weather + Fashion**을 결합한 이름으로, 사용자가 위치한 지역의 날씨와 신체 특성을 기반으로 개인화된 패션을 제공하는 애플리케이션이다.

### 1.3 프로젝트 목적

WEASHION은 날씨 정보와 텍스트 추천을 넘어 다음의 경험을 제공한다.

- 사용자의 신체 데이터를 바탕으로 개인화된 3D 캐릭터를 생성한다.
- 게임의 캐릭터 커스터마이징처럼 사용자가 체형을 직접 조절한다.
- 현재 위치의 날씨를 분석해 외출에 적합한 Outfit을 구성한다.
- 추천 의상을 3D 캐릭터에게 적용하고 날씨 환경과 함께 보여준다.

사용자는 숫자와 텍스트가 아니라 자신의 캐릭터를 통해 오늘 외출할 때 어떤 옷을 입으면 좋을지 직관적으로 확인할 수 있다.

## 2. 핵심 컨셉

> 나와 유사한 3D 캐릭터가 오늘의 날씨 속에서 오늘 입을 옷을 입고 있는 모습을 보여준다.

기본적인 서비스 흐름은 다음과 같다.

```text
사용자 신체 데이터 입력
→ 개인화된 3D 캐릭터 생성
→ 캐릭터 세부 커스터마이징
→ 사용자 위치 확인
→ 해당 지역의 날씨 정보 획득
→ 날씨 데이터 분석
→ 외출에 적합한 의상 선정
→ 3D 캐릭터에게 의상 적용
→ 날씨에 맞는 3D 배경 및 애니메이션 적용
→ 오늘의 외출 모습을 사용자에게 제공
```

## 3. 서비스의 핵심 구성 요소

WEASHION은 다음 네 가지 요소로 구성된다.

1. **Personal Avatar**
2. **Weather Analysis**
3. **Fashion Recommendation**
4. **Weather Visualization**

### 3.1 Personal Avatar

사용자의 신체 데이터를 기반으로 생성되는 개인화된 3D 캐릭터이다.

사용자의 사진을 이용하여 신체를 스캔하지 않는다. 사용자가 직접 입력한 수치 데이터를 기반으로 기본적인 신체 형태를 생성하고, 이후 사용자가 직접 캐릭터의 세부적인 신체 형태를 조절할 수 있도록 한다.

### 3.2 Weather Analysis

사용자의 현재 위치를 기반으로 해당 지역의 날씨 정보를 가져온다. 현재 기온뿐 아니라 다음과 같은 환경 정보를 함께 활용한다.

- 현재 기온
- 최고 기온
- 최저 기온
- 체감온도
- 강수확률
- 강수량
- 습도
- 풍속
- 풍향
- 날씨 상태
- 일출 및 일몰

### 3.3 Fashion Recommendation

날씨 데이터를 기반으로 사용자가 외출할 때 적합한 의상을 결정한다. 기온, 체감온도, 강수확률, 강수량, 습도, 풍속, 시간대를 함께 고려하여 상의, 하의, 아우터, 신발 및 액세서리로 하나의 Outfit을 구성한다.

### 3.4 Weather Visualization

현재 날씨를 단순한 아이콘이나 텍스트가 아니라 3D 환경과 애니메이션으로 표현한다. 예를 들어 비가 오는 날에는 캐릭터 주변에 비가 내리고, 눈이 오는 날에는 눈이 내리는 환경을 구성한다.

## 5. 개인화 3D 캐릭터

### 5.1 기본 캐릭터 생성

사전에 제작된 기본 Human 3D Model에 사용자 데이터를 적용하여 개인화된 캐릭터를 생성한다.

```text
Base Human Model
→ 사용자 신체 데이터
→ Body Parameters
→ Mesh Deformation
→ Personalized Avatar
```

### 5.2 신체 데이터와 캐릭터의 관계

예를 들어 다음과 같은 사용자가 있다고 가정한다.

| 항목 | 값 |
| --- | --- |
| 키 | 175cm |
| 몸무게 | 75kg |
| 어깨 너비 | 46cm |
| 가슴 둘레 | 100cm |
| 허리 둘레 | 82cm |
| 다리 길이 | 82cm |

이 데이터를 Body Parameter로 변환하여 각 신체 부위에 적용한다. 목표는 단순히 키만 다른 캐릭터가 아니라 사용자의 전체적인 신체 비율을 반영하는 것이다.

## 6. 캐릭터 커스터마이징

입력 데이터만으로 생성된 캐릭터가 실제 체형과 완전히 일치하지 않을 수 있으므로, 사용자가 직접 캐릭터를 수정할 수 있는 기능을 제공한다. 게임 캐릭터 커스터마이징과 유사하게 Slider를 사용한다.

- 키
- 어깨 너비
- 가슴
- 허리
- 팔 굵기
- 다리 굵기
- 다리 길이

슬라이더를 변경하면 3D 캐릭터가 실시간으로 변화한다.

## 7. 3D Body Morphing

캐릭터의 세부적인 체형 조절에는 Blend Shape 또는 Morph Target 방식을 사용할 수 있다. 기본 캐릭터를 기준으로 다양한 신체 형태의 변형 데이터를 제작하고, 여러 Parameter를 조합하여 최종 체형을 생성한다.

예시 Parameter:

- Height
- Shoulder Width
- Chest Size
- Waist Size
- Hip Size
- Arm Size
- Leg Size
- Neck Size
- Body Proportion

각 Parameter에는 0~1 또는 별도의 범위 값을 적용한다.

```text
Shoulder Width = 0.75
Chest Size = 0.65
Waist Size = 0.40
Arm Size = 0.55
Leg Size = 0.80
```

- Temperature

이 데이터를 종합하여 현재 또는 특정 시간대에 적합한 의상을 결정한다.

## 10. 날씨 기반 의상 추천

초기 버전에서는 Rule-based Recommendation System을 사용한다.

| 조건 | 추천 방향 |
| --- | --- |
| 기온이 매우 낮음 | 두꺼운 아우터 + 니트 + 긴바지 |
| 기온이 낮음 | 재킷 또는 코트 + 긴팔 + 긴바지 |
| 기온이 적당함 | 셔츠 또는 긴팔 + 긴바지 |
| 기온이 높음 | 반팔 + 반바지 또는 얇은 긴바지 |
| 기온이 높고 습도가 높음 | 통풍이 좋은 가벼운 의상 |
| 강수확률이 높음 | 방수 아우터 또는 우산 고려 |
| 바람이 강함 | 바람을 막을 수 있는 아우터 고려 |

## 18. 개발 단계

### Phase 1. 3D Avatar

**목표:** 사용자가 신체 정보를 입력하면 개인화된 3D 캐릭터를 생성한다.

- 기본 Human Model 제작 또는 확보
- 신체 Parameter 설계
- Body Morphing 구현
- 신체 데이터 입력 UI
- 3D Avatar 표시
- 캐릭터 회전 및 확대/축소
- 캐릭터 커스터마이징

### Phase 2. 3D Clothing

**목표:** 3D Avatar에게 다양한 의상을 착용시킨다.

- 상의
- 하의
- 아우터
- 신발
- 액세서리
- 의상 교체
- 의상 조합

### Phase 3. Weather System

**목표:** 사용자의 위치를 기반으로 실제 날씨를 가져온다.

- Core Location
- WeatherKit

- 시간대별 날씨
- 기온
- 체감온도
- 강수
- 습도
- 바람

### Phase 4. Outfit Recommendation

**목표:** 날씨 데이터를 기반으로 적절한 Outfit을 결정한다.

### Phase 5. Weather Environment

- 흐림

- 바람
- 안개

### Phase 6. WEASHION Main Scene

최종적으로 사용자 Avatar, Today's Outfit, Current Weather, Weather Animation, Weather Information을 하나의 Scene으로 통합한다.

## 21. 최종 서비스 정의

WEASHION은 사용자의 신체 데이터를 기반으로 개인화된 3D Avatar를 생성하고, 사용자의 위치를 기반으로 실제 날씨 데이터를 수집하여 날씨에 적합한 의상을 추천하는 개인 맞춤형 패션 애플리케이션이다.

추천된 의상은 단순한 텍스트나 이미지가 아니라 사용자의 3D Avatar에게 직접 적용된다. 또한 Avatar 주변의 3D 환경과 애니메이션을 현재 날씨에 맞게 변화시켜 사용자가 자신의 캐릭터를 통해 오늘의 외출 환경과 의상을 직관적으로 확인할 수 있도록 한다.

궁극적으로 WEASHION은 다음 세 가지 요소를 하나의 경험으로 통합한다.

### ME

사용자의 신체 특성을 반영한 개인화 3D Avatar

### WEATHER

사용자의 현재 지역을 기반으로 한 실제 날씨

### FASHION

현재 날씨와 사용자의 조건을 고려한 개인화된 Outfit

즉, WEASHION의 최종 목표는 단순히 오늘 어떤 옷을 입을지 알려주는 앱이 아니라 다음을 구현하는 것이다.

> **오늘의 나를 3D로 보여주는 날씨 기반 개인 패션 서비스**
