# WEASHION 작업 현황과 남은 개선 사항

- 기준일: 2026-10-27
- 범위: 매거진 재디자인(0.5~0.6) 이후 추가한 옷장 데이터 모델, 날씨별 표지 판, 한국어·영어·일본어 현지화와 앱 내 언어 설정, 그리고 다음 단계의 우선순위
- 상태: 시뮬레이터(iOS 26.1, iPhone)에서 디자인 단위 테스트 20건과 UI 테스트 7건이 통과했고, 실기기 대상 iOS 컴파일(서명 제외)이 성공했다. 실기기 화면·성능·실제 WeatherKit 수신은 확인하지 않았다. 신체 변형·치수 변환·드레이핑·저장 형식과 ID는 이번 작업에서 변경하지 않았다.

## 2026-10-28 추가: 피팅 중심 전체 디자인 개편 (0.16)

- **승인·백업:** 사용자는 과감한 디자인·모션 변경과 즉시 적용을 승인하면서 기존 버전의 완전한 백업을 먼저 요구했다. 저장소 밖 `Weashion-backups/2026-10-28_214851_pre-fitting-redesign`에 `.git`·미커밋·미추적·무시 파일까지 보관했다. 실제 독립 복원 사본에서 3,779개 항목의 경로·해시·메타데이터·Git 상태를 검증했고 한글 파일명 정규화 복구도 확인했다. [복원 안내](../../Weashion-backups/2026-10-28_214851_pre-fitting-redesign/RESTORE.md)를 포함하며 백업은 그대로 보존한다. 로컬 디스크 보관이지 외장 매체 이중화는 아니다.
- **오늘:** 보는 표지에서 조작하는 피팅 표지로 바꿨다. 큰 WEASHION 제호·날씨 판·같은 체형을 유지하면서 상품·S/M/L·미착용·치수 입력·피팅룸 CTA를 바로 연결한다. 일반 글씨의 보통 세로 iPhone에서는 스크롤 없이 핵심 행동을 찾게 하고 상세 날씨·옷차림 추천은 사이즈 노트 뒤로 보냈다. 기온·상태·샘플/수신 구분은 표지에 남긴다.
- **피팅룸·공통 화면:** 상품·사이즈·입력 차이와 마네킹을 모으고 반복되는 큰 선언문·중복 치수 버튼을 줄였다. 비교 영역 최소 높이로 일반 글씨에서 상태 교체에 따른 마네킹 밀림을 없앴다. 잉크색 내비게이션·버건디 선택면·기능 산세리프와 세리프 숫자·작은 모노 메타를 내 체형·두 보관함·편집·설정·최초 설정에 이어 적용했다.
- **모션:** 제목 640ms/줄 간격 80ms, 제호 진입 800ms, 헤더 스윕 440ms, 사이즈 글자 280ms로 리듬을 조정했다. 동작 줄이기·VoiceOver 제한과 실제 노출 시점 리빌은 유지한다. 준비 중 이전 화면의 조작은 막고 주 메뉴는 최신 선택을 계속 받는다. 애니메이션·가짜 완료를 기능 실행 조건으로 삼지 않는다.
- **검증(2026-10-28~29):** 시뮬레이터 빌드와 고유 단위 **55건**(디자인/수명 31, 저장 모델 13, 위치/날씨 11), 관련 UI 여정 **10건**이 통과했다. 분리된 집중 실행의 최신 완료 결과를 모은 고유 사례 수이며 같은 사례의 재실행·이전 버전 수를 합산하지 않는다.
  - UI 범위: 조작형 표지의 첫 화면 44pt 조작·실제 M/L 준비·선택/체형 복원, 표지↔피팅룸↔두 보관함 연결, 확대/시점 유지와 측정 번호↔치수 선택, 렌더 표면 밖 조작/상태와 크기 보존, 상품명/URL/치수 검증·저장·재실행, 상품/체형 편집 취소, 사용자 지정 상품/소수 치수/사이즈 복원, 스크롤 위치와 무관한 저장 안내·닫기, 가로 2열 배치, 최대 접근성 글씨의 세로 선택·치수 편집.
  - 일반 글씨의 주요 조작이 하단 메뉴 위에 있고, 비교 상태 교체 전후 마네킹 Y 차이가 0.5pt 이내임을 실제 프레임으로 확인했다. 가로는 화면 폭>높이와 장면 왼쪽/치수 조작 오른쪽 관계, 큰 글씨는 표지 메타가 렌더 표면 아래에 놓이는 관계를 검증했다.
- **직접 확인·보완:** 표지·피팅룸·내 체형·두 보관함·편집·측정 포커스·가로·최대 접근성 글씨 이미지와 녹화 중간 프레임을 열어 확인했다. 일반 표지의 세로 러닝헤드와 날씨 겹침을 줄였고, 큰 글씨에서는 계산/날씨/체형 안내를 모델 밖의 자연 높이 흐름으로 분리했다. 장식용 상품 아이브로우도 큰 글씨에서 생략한다. 자동 테스트가 통과했어도 실제 캡처에서 발견한 겹침은 별도로 수정했다.
- **검증 도구 보완:** 선택된 메뉴와 실제 표시 지면을 구분해 기다리고, 잘린 버튼의 중앙이 하단 메뉴를 누르거나 큰 스와이프가 도식을 지나치지 않게 테스트를 보강했다. 확대 한도·시점·측정 선택·저장값 검증을 완화하지 않았다. 가로 이미지는 앱 요소의 잘못된 크롭 대신 전체 화면을 캡처하고 기기 방향에 맞춰 확인했다.
- **보존·한계:** 계산 수식·메시 자산·저장 형식·ID·준비된 3D 재사용은 변경하지 않았다. 외부 레퍼런스의 사진·서체·코드를 복제하지 않았다. 실기기 설치·실행·실제 위치/WeatherKit 수신·FPS/발열/햅틱은 검증하지 않았으며 전체 언어/반응형 감사·옷 사진·출시 자료는 후순위다. 지면 목차·바로보기·재질 시각화는 제외 상태다.

## 2026-10-28 이전 추가: 안정화·날씨 처리·치수 포커스 (0.15)

- 사용자는 후순위 항목을 제외한 전환·메모리, 입력·저장, 위치·날씨 처리, 치수 도식 포커스 진행을 승인했다. 단계 시작 전에 작업 내용을 안내했다. 연결된 실기기 사용은 별도 확인에서 **시뮬레이터만** 선택했으므로 기기에 설치·실행하거나 실제 위치를 수집하지 않았다.
- **자원 수명:** 메모리 경고 때 대기 이동을 취소하고 비활성 3D 상태·분리된 네이티브 참조·actor 계산 캐시를 해제한다. 현재 표시 상태와 저장 데이터는 유지하며 재방문에서는 다시 준비한다. 활성 상태 보존과 재준비·해제를 단위 검증했다.
- **입력·저장:** 좁은 화면 치수 편집은 시스템 sheet, 넓은 화면은 inspector로 연결한다. 입력칸의 장식 여백 터치에도 포커스를 받고, 테스트에서는 화면에 일부만 노출된 필드를 눌러 실패하던 좌표를 구분해 보강했다. 상품명·URL 검증/재입력·소수 치수, 저장·재실행, 상품/체형 편집 취소, 사용자 지정 상품·사이즈 선택·복원 경로가 통과했다.
- **위치·날씨:** 사용자 요청 때만 위치를 요청하며 권한 허용·거부·회수와 잘못된 위치·15초 수신 제한·재시도를 처리한다. 같은 좌표도 새 요청으로 새로고침한다. 날씨는 최신 요청만 반영하고 취소를 네트워크 오류로 표시하지 않는다. 최초 실패는 샘플, 갱신 실패는 마지막 수신값과 명시적 안내를 사용한다. WeatherKit entitlement와 빌드 설정을 연결했다. Apple Developer의 App ID capability·서명 프로파일 및 실제 수신은 미검증이다.
- **치수 포커스:** 총장·어깨너비·가슴단면·소매길이의 번호와 항목을 누르면 대응 측정선·숫자만 함께 강조한다. 번호의 터치 영역은 44×44pt이며 접근성 선택 상태를 제공한다. 편집 입력의 포커스와 도식 선택도 연결한다. 임시 선택만 바꾸며 저장값·선택 사이즈·3D 계산·기존 모션 상수는 변경하지 않는다.
- **검증:** 고유 단위 **55건**(디자인/수명 31, 저장 모델 13, 위치/날씨 11)과 핵심 UI 여정 **4건** 통과. 별도 집중 실행의 최신 통과 사례를 모은 수치이며 같은 테스트 재실행·과거 버전과 합산하지 않는다. 최종 표지와 치수 포커스 스크린샷도 직접 확인했다. 위치·날씨 단위 테스트는 주입한 응답을 쓰며 서버 실수신을 의미하지 않는다.
- **남은 항목:** 사용자 선택으로 실기기 시간·프레임·메모리·발열·햅틱 및 실제 위치·WeatherKit 수신은 확인하지 않았다. 옷 사진·전체 언어/반응형 검수·출시 자료는 미착수, 지면 목차·바로보기·재질 시각화는 제외 상태다.

## 2026-10-28 이전 추가: 전환 최적화 (0.13 구현·0.14 범위 반영)

아래는 0.13 당시의 기록이다. 입력·메모리·치수 포커스 등의 최신 상태는 위 0.15 기록을 기준으로 읽는다.

**전환 최적화 핵심 구현과 시뮬레이터 집중 검증을 완료했다.** 기존 표지·비대칭 지면·서체·버건디와 0.9 모션 상수는 유지했다. 현재 우선순위의 상세 기준은 [디자인 문서 13절](editorial-design-direction.md#roadmap)에 있다. 치수 포커스·사진은 이번에 구현하지 않았다. 오늘 지면 목차는 사용자 요청으로 0.14에서 제외했다.

- 오늘·피팅룸은 준비된 신체·착장·네이티브 geometry를 재사용한다. 내 체형은 별도 준비 상태·시점을 유지하며, 주 메뉴용 `SCNView` 하나를 활성 지면으로 옮겨 사용한다.
- 신체 변형·법선·충돌 데이터 준비는 기존 `BodyPreviewRenderer` actor로 이동하고 메시 생성은 비동기 API를 사용한다. 최초 네이티브 geometry 변환·최종 부착은 메인 스레드에 남으며 재방문에서는 캐시를 사용한다.
- 메뉴 선택은 즉시 반응하고 실제 120ms 이상 준비 대기에만 종이색 띠·다음 지면 번호/이름·버건디 선을 표시한다. 준비 즉시 제거하며 최소 노출 시간은 없다. 최신 이동만 반영하고 취소·실패 시 예고를 종료한다. 의류 계산 완료까지 메뉴 이동을 붙잡지 않는다.
- 본체·의류의 비동기 변경 revision을 재사용 UIKit 표면에 전달한다. 초기 표지의 준비·착장 계산 상태도 표시하고 접근성 값에 반영한다.
- 검증: 관련 단위 **28건**, 메인 UI 여정 **1건** 통과. 내부 카운터로 동일 요청 20회 재사용 시 추가 신체·착장 계산·네이티브 geometry 생성 0회, 주 메뉴 표면 생성 1회를 확인했다. 빠른 준비·지연·최신 선택·취소·실패와 치수 변경 무효화도 단위 검증했다. 녹화·중간 프레임·완료 이미지에서 기존 제호·제목 진입, 초기 표지 착장, 내 체형, 시점 유지·최신 사이즈 표시를 확인했다. 이전 버전 결과나 같은 여정 재실행을 합산하지 않는다.
- 계측: 변경 전 동기 신체 준비 약 **1.456초**, 변경 후 준비 중 메인 actor 응답 확인 약 **0.227ms**. 서로 다른 대상을 측정했으므로 향상률로 비교하지 않는다. 캐시 영향을 받는 준비 시간·합성 재사용 루프·UI 여정 전체 시간은 실제 탭 → 첫 프레임 지연이 아니다.
- 남은 한계: 실기기 전환·프레임·메모리·발열·햅틱, 메모리 경고 때 비활성 자원 해제, 전체 저장·취소·복원 회귀와 기존 입력 포커스·커서 문제, 실제 위치·WeatherKit 수신은 아직 확인·완료하지 않았다. 모드별 최신 상태로 보관 수는 제한하지만 메모리 실측을 대신하지 않는다.

| 우선순위 | 남은 작업 | 확정 범위 |
| --- | --- | --- |
| 최우선 | 구현한 전환 최적화의 실기기 측정과 안정화 | 재사용·actor 분리·대기 예고의 핵심 구현·시뮬레이터 검증 완료. 실제 전환·프레임·자원 측정과 저장·취소·복원·날씨 검증은 남음 |
| 다음 | 치수 도식 연결 포커스 | 측정 번호·치수 항목·해당 도식 선을 함께 강조. 실제 옷 비율·저장값·3D 계산은 변경하지 않음 |
| 장기 | 사용자 옷 사진 아카이브 | 로컬 사진과 상품 기록 연결·썸네일. 사진 없는 기존 데이터 호환을 유지하며 3D 복원·재질·치수 자동 추정은 제외 |

- 재질 표시는 원단 스와치와 선택 재질의 3D 시각화를 제외한다는 결정이다. 날씨 추천용 재질·두께 입력·저장·기존 텍스트 안내는 유지하며, 해당 메타데이터만 바뀌었다고 3D를 재계산하지 않는다.
- 정면·측면·후면 바로보기는 0.11 제안 후 사용자 요청으로 0.12에서 취소했다. 후순위가 아니라 추가 범위에서 제외하며, 기존 회전·확대·초기화·제스처는 유지한다.
- 오늘 지면 목차는 빠른 작업 후보로 조사했으나 사용자 요청으로 0.14에서 취소했다. 앱 코드 수정 전 중단해 추가된 UI는 없으며, 후순위가 아니라 제외 항목으로 유지한다. 기존 스크롤·주 메뉴·모션은 변경하지 않았다.
- 현재 우선 안정화: 실기기 전환·프레임·메모리·발열·햅틱, 저장·취소·복원·최신 요청 회귀, 실제 WeatherKit 권한·수신 검증, 기존 시트 입력 포커스·커서 문제.
- 후순위 이관: 세 언어 번역·용어 감수와 iPad·큰 글씨·키보드 등의 전체 화면 검수, 출시용 아이콘·이미지·설명·개인정보 안내. 기존 현지화와 변경 범위의 기본 기능은 보존하며 전체 검수와 구분한다.
- 의류 종류별 3D 메시·측정 계약 → 레이어링 → 날씨 추천 착장의 표지 자동 적용은 별도 제품 확장이다. 아래 2026-10-27의 장기 후보를 이번 전환 최적화보다 먼저 진행한다는 뜻은 아니다.

## 2026-10-28 추가: 눈에 보이는 모션 강화 (0.9)

- 승인된 제호·마네킹 구도와 버건디 팔레트는 유지했다. 제호의 110~160pt 마스크 진입·850ms, 캡션의 160ms 시간차, 모든 탭의 500ms 헤더 스윕으로 화면 진입을 분명하게 했다.
- 날씨 숫자·각 측정 행·하늘판·선언문 각 줄·옷차림은 해당 요소가 실제로 약 18% 보일 때 한 번 움직인다. 지면 전체의 노출값 하나로 아래 요소까지 먼저 끝나던 문제를 제거했다. 체형 수치·치수 행·사이즈 노트·보관함 도식에도 개별 리빌을 연결했다.
- 버튼·선택은 100ms·0.97배 눌림, 큰 사이즈 글자는 320ms 상하 교체를 사용한다. 선택·저장·계산을 완료 콜백으로 지연하지 않으며 이전 착장을 새 결과로 표시하지 않는다.
- 0.8의 동기식 장면 캡처·좌표 추적·정지 이미지 이동·전체 3D 지면 페이드는 제거했다. 공유 회전·확대·초점은 유지한다. 배경 시차는 `.visualEffect` 내부에 한정하고 반복 장식·실시간 블러·렌더러 복제·메시 장식 변형을 추가하지 않았다.
- 검증: 시뮬레이터 빌드 성공. 단위 테스트 23건과 메인 여정 UI 테스트 1건 통과(탭 전환, 회전·확대 유지, 단일 렌더 표면, S → L 최신 입력 차이). 아래 0.8·0.7 검증은 당시 기록이며 현재 결과와 합산하지 않는다.
- 시각 확인: 같은 메인 여정을 녹화한 별도 1회도 통과했다. 완료 스크린샷뿐 아니라 녹화의 중간 프레임에서 제호가 비어 있는 상태 → 마스크 진입 → 최종 위치, 스크롤 중 날씨 선언문의 첫 줄 → 다음 줄 리빌을 확인했다. 이는 시뮬레이터의 연출 확인이며 실기기 프레임 측정이 아니다.
- 남은 확인: 실기기 60fps 목표 측정·햅틱·iPad·큰 글씨·다국어 전체 UI 회귀. 오래된 시트 입력 포커스 문제는 이번 범위가 아니다.

## 2026-10-28 추가: 지면 연결과 버건디 포인트 (0.8, 이전 방식)

- 마네킹 + WEASHION 제호의 표지 구도는 유지했다.
- 상품 추가는 종류 → 재질·두께 → 날씨 제안으로 정보를 펼친다. URL·메모·기준 모델은 선택 정보로 묶고 보온·비 대응·계절은 제안 뒤에 조정한다. 기존 상품 수정은 재질과 날씨 정보를 바로 보여준다. 재질 미선택 시 기본 기준을 표시하고, 저장 영역은 스크롤과 분리해 단계 버튼을 덮지 않도록 했다.
- 날씨 지면은 기온·측정값 → 하늘판·선언문 → 옷차림을 100ms 간격으로 한 번 나타낸다. 사이즈 변경은 이전 선택과 총장·어깨너비·가슴단면의 입력 차이를 부호 있는 cm로 표시한다.
- 오늘 ↔ 피팅룸은 기존 3D 표면의 정지 이미지 하나를 500ms 동안 다음 장면으로 연결한다. 두 렌더러를 겹치지 않고 회전·확대·초점을 유지하며, 선택 치수가 바뀌어 캡처 대상과 요청이 다르거나 장면이 화면 밖이면 기본 전환을 쓴다. 실제 옷·몸·계산 결과는 애니메이션으로 보간하지 않는다.
- 버건디를 주요 CTA·선택 사이즈·측정 번호·세로 제목·강수 숫자에 추가했다. 새 기능 문구 8개는 한국어·영어·일본어를 함께 제공한다.
- 검증: 관련 단위 테스트 22건 통과. 옷 추가 UI 테스트 1건 통과(단계 펼침, 하단 저장 영역과의 비겹침, 재질·두께 기반 제안 갱신, 상품명 미입력 저장 차단). 회전·확대 유지·단일 렌더 표면·사이즈 차이는 통합 여정의 앞 구간에서 통과했다. 그 통합 테스트 전체는 초기 옷 추가 단계에서 실패했으므로 전체 통과로 집계하지 않았다.
- 남은 확인: 실기기 타이밍·프레임, 다국어·iPad·큰 글씨의 새 단계 배치, 전체 UI 회귀. 이전에 실패한 시트 입력 필드의 포커스·커서 테스트는 이번에 재실행하거나 해결하지 않았다.
- 아래 0.7 검증·저장 공간 내용은 2026-10-27 당시의 기록이다.

## 1. 이번에 끝낸 것

### 1.1 메인 화면 재배치와 보조 기능 정리 (0.6)

- `오늘`은 사용자 여정 순서로 내려간다: 표지(제호 뒤 마네킹, 세로 러닝헤드, FIG. 캡션) → 날씨 지면(기온 숫자가 표지 아래로 겹치고, 하늘 사진판이 오른쪽 가장자리 밖으로 잘리며, 굵은 선언문이 그 모서리를 덮는다) → 현재 착장(오른쪽으로 잘리는 버건디 사이즈 글자, CTA 하나) → 잉크색 사이즈 지면(세로로 세운 *Every size, a note.*).
- 사용자가 마음에 든다고 확인한 표지 구성은 그대로 유지했다.
- 설명 문단과 중복 아카이브 링크는 설정 화면의 "How to fit."으로 옮겼고, 설정은 헤더의 톱니 하나로 연다.

### 1.2 날씨별 표지 판

- 맑음(푸른 하늘·작은 해), 흐림(해 없는 회색), 비(짙은 슬레이트 하늘에 제호·러닝헤드가 종이색으로 반전되는 다크 커버), 눈(거의 흰 하늘과 드문 눈송이) 네 판을 [WeatherBackdrop](../weashion/weashion/Views/WeatherBackdrop.swift)이 그린다.
- 개발 빌드의 설정 맨 아래 "미리보기 날씨" 스위치 또는 `-previewWeatherMood <clear|cloud|rain|snow>` 실행 인자로 비교한다. 실제 날씨가 연결되면 무시된다.
- 조건 문자열에서 분위기를 판정하는 [WeatherInfo.mood](../weashion/weashion/Models/WeatherInfo.swift)는 영어·한국어에 더해 일본어(雪·雨·曇·霧) 표현을 인식한다.

### 1.3 옷장 데이터 모델 (날씨 추천의 기반)

- [GarmentKind](../weashion/weashion/Models/FittingLibrary.swift): 반팔 티셔츠·긴팔 상의·니트·아우터·긴바지·반바지·신발. `slot`(상의/아우터/하의/신발)과 `supportsFitting`(현재 반팔만 `true`)을 가진다.
- [GarmentClimate](../weashion/weashion/Models/GarmentClimate.swift): 재질(코튼·린넨·울·폴리에스터·나일론·데님·가죽·플리스·다운), 두께(얇음·보통·두꺼움), 보온 등급 1~5, 비 대응(없음·발수·방수), 계절. 재질·두께를 고르면 보온·비 대응·계절 제안값을 계산하고 사용자가 수정한다. `GarmentProduct.climate`는 선택 사항이라 기존 저장 파일을 그대로 읽는다.
- [ClosetRecommendation](../weashion/weashion/Models/GarmentClimate.swift): 체감온도에서 목표 보온을 정하고, 슬롯별로 사용자 옷장에서 보온 차이가 한 단계 이내인 옷을 고른다(비 오는 날은 비 대응 없는 아우터를 감점). 해당 슬롯에 옷이 없으면 일반 샘플 추천을 보여주고 "보관함에 추가된 옷 없음 · 샘플 추천"이라고 작게 표시한다.
- 상품 편집에 종류 선택과 `climateFields`(재질·두께 피커, 보온 ●○ 세그먼트, 비 대응, 계절)를 추가했다. 3D 착장을 지원하지 않는 종류는 치수 없이 사이즈명만 기록한다.

### 1.4 현지화와 앱 내 언어 설정 (0.7)

- 소스 언어는 한국어다. 코드의 사용자 노출 문자열 611개 키 중 한국어 579개에 영어·일본어 번역을 [Localizable.xcstrings](../weashion/weashion/Localizable.xcstrings)에 넣었다. 나머지 32개는 의도적인 영문 편집 요소(`WEASHION`, `FIG. %@`, *A little layering.* 등)와 형식 문자열이다. 위치 권한 문구는 [InfoPlist.xcstrings](../weashion/weashion/InfoPlist.xcstrings)에 있다.
- SwiftUI `Text`·`Button` 등은 `LocalizedStringKey`로 자동 현지화되고, 모델·서비스·문자열 매개변수는 [Localization.swift](../weashion/weashion/Models/Localization.swift)의 `L("…")`을 쓴다. `L()`은 설정에서 고정한 언어의 `.lproj` 번들을 직접 읽는다.
- 설정 → **Language.** 세그먼트(시스템 / 한국어 / English / 日本語). 선택 즉시 메인 지면을 다시 그리고(`.id(appLanguage)`), 설정 시트는 유지된다. 선택은 `UserDefaults`(`appLanguage`)에 남아 재실행 후에도 유지되며, "시스템"은 기기 언어를 따른다(지원하지 않는 기기 언어는 프로젝트 개발 언어인 영어로 떨어진다).
- 일본어에서 확인해 고친 것: 탭·헤더의 `피팅룸`은 `試着室`로 번역해 줄바꿈을 피했고, 옷차림 슬롯 열을 64pt로 넓혔으며, 툴바 텍스트 버튼은 [EditorialToolbarButton](../weashion/weashion/Views/EditorialStyle.swift)으로 바꿔 `閉じる`가 한 줄로 유지되도록 했다. 세그먼트 피커는 제목이 제자리에서 갱신되지 않아 언어와 함께 다시 만든다.
- 새 문자열 추가 절차: 코드에 한국어로 쓰고(`Text("…")` 또는 `L("…")`) 한 번 빌드한 뒤 `weashion/scripts/sync-localizable-strings.sh [DerivedData 경로]`를 실행하면 컴파일러가 추출한 키가 카탈로그에 들어온다. Xcode의 String Catalog 편집기에서 영어·일본어 칸을 채운다. 사라진 키는 삭제되지 않고 `stale`로 표시된다.
- 프로젝트 `knownRegions`에 `ko`, `ja`를 추가했다. `developmentRegion`은 `en`을 유지한다(카탈로그의 `sourceLanguage`는 `ko`).

## 2. 알고 있는 제약

- 마네킹에 입힐 수 있는 3D 의류는 코튼 반팔 메시 하나다. 다른 종류는 기록과 날씨 추천에만 쓰인다. 따라서 "앱을 열자마자 오늘 날씨에 맞는 추천 옷을 입은 내 캐릭터"는 아직 불가능하다.
- 옷차림 추천은 사용자 옷장에 해당 종류가 없으면 샘플 문구로 대체된다. 샘플은 사용자의 데이터가 아니라고 화면에 표시한다.
- 상품 이름·체형 이름 등 사용자가 입력한 데이터는 번역하지 않는다. 최초 실행 시 만들어지는 샘플 상품 이름과 기본 체형 이름은 그 시점의 언어로 저장된다.
- 상태 안내(`저장 완료` 등)는 생성 시점의 언어로 만들어지므로 언어를 바꾸면 기존 안내를 지운다.
- 카탈로그는 수동 번역이다. 전문 감수(특히 일본어 패션 용어: 身幅·着丈·わたり幅 등)와 긴 영문 문장의 레이아웃 재확인이 필요하다.
- 디스크 여유가 1GB 안팎이라 시뮬레이터 빌드 산출물은 작업마다 삭제했다. 테스트 재실행 전 공간을 확보해야 한다.

## 3. 장기 개선 후보 (2026-10-27 당시 기록)

현재 확정 순서는 위 최신 우선순위 표와 [디자인 문서 13절](editorial-design-direction.md#roadmap)을 따른다. 아래는 당시의 제품 확장·출시 후보이며 새로 모두 승인되거나 구현된 목록이 아니다.

1. **의류 종류별 3D 메시와 치수 계약** — 긴팔·니트·아우터·바지·신발의 기준 메시, 종류별 측정 항목(총장·어깨·가슴단면 외 밑위·허벅지단면·인심 등), 종류별 착장 계산 검증. 현재 `GarmentKind.supportsFitting`을 `true`로 바꾸는 것만으로는 부족하고, [GarmentDefinition](../weashion/weashion/Models/GarmentDefinition.swift)·드레이퍼가 종류별 접촉 밴드를 알아야 한다.
2. **겹쳐 입기** — 상의 위 아우터, 하의와의 경계. 레이어 순서에 따른 충돌 보정과 두께 누적이 필요하다.
3. **추천 착장을 바로 입은 표지** — 1·2가 끝나면 `ClosetRecommendation.look`의 각 슬롯을 마네킹에 적용한다. 앱 시작 시 즉시 보이려면 마지막 착장 결과(드레이프 정점) 캐시를 저장해 두고, 날씨 변화 시 백그라운드로 다시 계산한다.
4. **실제 WeatherKit 연결** — 앱 서명·WeatherKit 권한·위치 권한 흐름, 시간별 예보, 실패 시 샘플 표기 유지. `WeatherInfo.mood` 조건 판정을 `WeatherCondition` 열거형 기반으로 바꾸면 언어 의존이 사라진다.
5. **옷장 UX** — 종류별 필터, 보온·비 대응 요약 배지, "오늘 추천에 쓰인 옷" 표시, 샘플 슬롯에서 바로 상품 추가로 이동.
6. **타이포그래피 마무리** — 사이즈 노트의 고아 단어 줄바꿈, 영문·일문의 접근성 글씨 크기 레이아웃, iPad 가로.
7. **접근성 점검** — VoiceOver 순서와 레이블은 UI 테스트가 잡는 범위에서만 확인했다. 전환 모션의 동작 줄이기 분기와 색 대비는 테스트에 있다.
8. **출시 준비** — 앱 아이콘·스크린샷(세 언어), 개인정보 처리 설명(위치 사용 범위), App Store 설명 번역, `developmentRegion` 정책 결정(현재 미지원 언어는 영어로 떨어짐), 실기기 성능 측정.
