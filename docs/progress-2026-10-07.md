# WEASHION 진행 및 변경 기록

- 기준일: 2026-10-07
- 범위: 현재 신체·의류 구현의 정리, 외부 남녀 모델 경량화, Swift/RealityKit 표시 경로 전환
- 상태: 코드와 앱용 에셋 연결 완료. 앱 전체 빌드 및 새 모델의 실기기 착장은 미확인.

## 1. 현재 상태 요약

| 영역 | 현재 상태 | 이번 확인 범위 |
| --- | --- | --- |
| 앱 구성 | SwiftUI 화면, 신체 정보 모델, 위치·날씨 서비스, RealityKit 장면 존재 | 위치·날씨 기능은 이번 에셋 작업에서 별도 실행하지 않음 |
| 신체 표시 | 생성형 몸체 대신 남녀 외부 전신 메시 사용 | 원본·경량화·Swift 변형 결과 비교 |
| 체형 조절 | 키, 몸무게, 어깨너비, 세 부위 둘레, 인심, 팔·다리 굵기 연결 | 기본 체형의 실제 Swift 계산 확인 |
| 의류 준비 | 카탈로그, 티셔츠 생성, 외부 의류 JSON 로더, 부위별 피팅 | 기존 코드 연결 유지, 새 몸의 프로필 생성 확인 |

| 에셋 편집 | Blender 원본과 경량화 사본 별도 보관 | 원본 파일 보존 및 사본 재열기 확인 |
| 배포 준비 | iOS 소스 타입 검사 통과 | Xcode 기기 대상 문제로 앱 전체 빌드·설치 미완료 |

날씨 추천, 여러 겹 착장, 자유 포즈와 정밀 인체 복원까지 완료했다는 의미는 아니다. 제품의 장기 목표와 실제 구현은 [README](../README.md)에서 구분한다.

## 2. 진행 순서

1. 사람 모델의 편집용 원본과 앱용 포맷을 구분하고 Blender 원본 사용을 결정했다.
2. 제공된 남녀 Blender 파일을 자동 스크립트 실행을 차단한 상태로 읽어 메시 구조를 확인했다.
3. 원본을 덮어쓰지 않고 Blender Decimate의 Collapse 방식으로 각각 40,000삼각형 사본을 만들었다.
4. 저장된 사본을 다시 열어 정점·면 수를 확인하고 원본 파일 해시가 변하지 않았음을 확인했다.
5. 원본과 경량화 결과의 정면·측면·후면을 동일한 렌더 조건에서 비교했다.
6. 앱에서 정점을 직접 변형할 수 있도록 미터 단위 Y-up JSON으로 내보냈다.
7. Swift 에셋 로딩·체형 보정·의류 단면 및 충돌 밴드 생성 경로를 추가했다.
8. 기존 머리·귀·손발 세부 형상을 조립하던 표시 경로를 제거하고 새 전신 메시를 연결했다.
9. 단면 둘레 과대 계산과 겨드랑이 변형을 실제 계산·렌더 결과를 기준으로 수정했다.
10. 전체 iOS 소스 타입 검사와 실제 Swift 변형 코드 실행을 확인했다. 기기 설치는 하지 않았다.

## 3. 에셋 조사와 경량화 결과

### 3.1 원본 구조

두 파일 모두 메시 오브젝트 1개, 삼각형 면, 재질 1개로 구성되어 있었다. 리깅/Armature, 애니메이션 Action, Shape Key, 정점 그룹, UV 맵, 이미지 텍스처와 Modifier는 없었다.

원본 높이는 약 1.9m다. 여성은 팔을 벌린 자세, 남성은 팔을 내린 자세이며 속옷 형상은 별도 의류가 아니라 몸과 합쳐진 메시다. 이번 작업에서는 자세나 속옷 형상을 별도로 제거하지 않았다.

### 3.2 수치

| 항목 | 여성 | 남성 |
| --- | ---: | ---: |
| 원본 정점 | 109,554 | 110,708 |
| 원본 삼각형 | 219,104 | 221,428 |

| 경량화 파일 크기 | 1,102,265 bytes | 1,119,318 bytes |
| 경계 변: 전/후 | 0 / 0 | 0 / 0 |
| 비다양체 변: 전/후 | 0 / 0 | 0 / 0 |
| 샘플 표면 오차 최대 | 약 0.437mm | 약 0.686mm |

파일 크기 감소에는 메시 감량뿐 아니라 Blender 압축 저장도 포함된다. 파일 크기 감소율을 실행 성능 향상률로 해석하지 않는다.

표면 오차는 양쪽 메시의 정점에서 상대 메시의 가장 가까운 삼각형 표면까지 측정한 거리다. 모든 연속 표면 지점의 최대 오차를 증명한 값이나 양방향 Hausdorff 거리의 엄밀한 상한은 아니다. 비다양체 변이 없다는 결과 역시 자체 교차나 해부학적 품질까지 보장하지 않는다.

## 4. 새 신체 데이터 형식

### 4.1 좌표와 필드

Blender 좌표를 `(x, z, -y)`로 회전하고 발바닥 높이를 0으로 맞춘 뒤 몸통 기준으로 깊이 중심을 보정했다. 삼각형 인덱스의 순서는 유지한다.

| 필드 | 의미 |
| --- | --- |
| `version` | 현재 데이터 형식 버전 1 |
| `vertices` | 미터 단위 `[x, y, z]` 정점 배열 |
| `indices` | 삼각형당 3개의 정점 인덱스 |
| `regions` | 삼각형별 신체 영역 번호 |
| `armWeights` | 정점별 팔 변형 영향도, 0~1 |
| `armCenters` | 기준 모델 오른팔의 높이별 중심선 |
| `legCenters` | 기준 모델 오른다리의 높이별 중심선 |
| `landmarks` | 기준 신장, 인심, 엉덩이·허리·가슴·어깨 높이 및 어깨너비 |

영역 번호는 `0` 몸통, `1` 오른팔, `2` 왼팔, `3` 오른다리, `4` 왼다리다. 왼쪽 변형은 오른쪽 중심선을 좌우 반전해 사용하므로 비대칭 해부학을 정확히 복원하는 구조는 아니다.

### 4.2 기준점

| 기준 | 여성 | 남성 |
| --- | ---: | ---: |
| 인심 높이 / 원본 신장 | 0.465 | 0.448 |
| 엉덩이 높이 / 원본 신장 | 0.535 | 0.535 |
| 허리 높이 / 원본 신장 | 0.625 | 0.625 |
| 가슴 높이 / 원본 신장 | 0.735 | 0.735 |
| 어깨 높이 / 원본 신장 | 0.805 | 0.805 |
| 기준 어깨너비 | 0.410m | 0.490m |

기준점은 이 두 에셋을 연결하기 위한 근사값이다. 전문 신체 측정으로 검증한 값이나 다른 모델에 그대로 적용할 수 있는 자동 랜드마크 검출 결과가 아니다.

원본 팔 경계는 여성 `0.135 + max(어깨높이 - y, 0) * 0.25`, 남성 `0.190 + max(어깨높이 - y, 0) * 0.045`를 기준으로 정하고 3cm 범위에서 부드럽게 전환했다. 목 위에서는 팔 영향을 줄인다. 앱 로더에서 메시 이웃을 따라 팔 가중치를 추가로 12회 평활화한다.

### 5.2 실행 흐름

```text
UserBody + 남녀 선택
  -> MannequinMesh의 번들 JSON 로딩 및 캐시
  -> 키/인심/몸통/팔다리 변형
  -> 같은 정점에서 단면과 충돌 밴드 생성
  -> BodySurfaceMesh -> RealityKit 전신 메시
  -> 의류 프로필/충돌 밴드 -> GarmentController -> GarmentDraper
```

- 로더는 버전, 배열 길이, 정점 인덱스 범위, 유한값, 가중치 범위와 기준 높이·중심선의 순서를 검사한다.
- 높이는 발바닥·인심·어깨·정수리 기준으로 변환한다. 지나치게 긴 인심은 목표 어깨높이보다 최소 15cm 아래로 제한한다.
- 몸통 폭·깊이를 기준 단면에 맞춰 보정하고 가슴·허리·엉덩이를 최대 3회 재측정한다. 모든 입력에서 정밀 치수 수렴을 보장하는 제약 해결기는 아니다.
- 몸무게에 따른 굵기 계수는 70kg을 기준으로 제한된 범위에서 반영하며, 팔다리 굵기 입력과 곱해진다. 체중으로 전체 체적이나 지방 분포를 복원하지 않는다.
- 발 부근의 다리 굵기 영향은 줄여 발 전체가 다리 굵기와 같은 비율로 부풀지 않게 한다.
- 팔 간격은 허리·엉덩이 단면의 여유를 기준으로 보정하고 어깨에 가까워질수록 보정량을 줄인다. 가슴 높이에서 강제로 틈을 만들지 않는다.
- 치수·남녀 선택이 바뀔 때 계산한다. 원본에 없는 관절 리그를 추가하거나 매 프레임 스키닝하는 구조가 아니다.

### 5.3 제거한 코드와 남긴 코드

별도 머리 표면, 귀, 손가락·엄지·발가락 장식, 손발톱을 만드는 표시 코드를 제거했다. 이 부분은 전신 에셋에 이미 포함되어 중복 생성할 필요가 없다.

기존 [BodySkeleton.swift](../weashion/weashion/Models/BodySkeleton.swift)와 생성형 몸체의 대부분은 삭제하지 않았다. 기존 유틸리티와 테스트가 의존하고 있어 현재 표시 경로에서 분리한 상태다. 새 에셋이 기존 23관절 리그나 dual-quaternion 스키닝으로 움직인다고 설명해서는 안 된다.

## 6. 의류 구현과 연결 상태

기존 의류 경로는 [GarmentDefinition.swift](../weashion/weashion/Models/GarmentDefinition.swift), [CottonTShirtTemplate.swift](../weashion/weashion/Models/CottonTShirtTemplate.swift), [GarmentFit.swift](../weashion/weashion/Models/GarmentFit.swift), [GarmentDraper.swift](../weashion/weashion/Services/GarmentDraper.swift), [GarmentRenderer.swift](../weashion/weashion/Views/GarmentRenderer.swift)로 나뉜다.

- 번들 카탈로그에서 샘플을 선택하며, 치수 기반 티셔츠 또는 준비된 의류 JSON을 사용한다.
- 신체의 단면과 의류의 기준 단면 차이를 이용해 몸통·어깨·소매를 배치한다.
- [ClothPhysics 패키지](../weashion/Packages/ClothPhysics/README.md)는 Swift에서 사용하는 C API와 Bullet 충돌 관련 코드를 포함한다.
- 현재 착장 계산은 볼록 충돌체를 이용한 정적 겹침 보정이다. 완전한 중력 기반 천, 주름, 봉제, 자기충돌 시뮬레이션으로 표현하지 않는다.
- 새 몸의 표시 정점과 충돌 밴드는 같은 변형 결과를 사용한다. 시각용으로 가져온 사람과 숨은 기존 생성형 몸체를 따로 두지 않는다.
- 신체 로딩 실패 시 이전 의류가 새 몸에 맞는 결과처럼 남지 않도록 표시를 정리한다.

새 에셋의 팔 자세와 표면은 기존 생성형 모델과 다르다. 이전 모델에서 확인한 티셔츠 95·110 착장 결과를 새 에셋의 착장 품질 근거로 재사용하지 않는다.

## 7. 구현 중 확인하고 수정한 문제

### 단면 둘레 과대 계산

불규칙한 삼각형과 팔 주변의 분리된 점을 단순 각도순으로 연결하면 단면이 여러 번 왕복해 여성 가슴둘레가 약 2.5m로 계산되는 문제가 있었다. 외부 에셋 경로에 볼록 외곽선 기반 단면을 사용하고 팔·몸통 분류 경계를 조정했다.

볼록 단면은 안쪽으로 파인 표면을 메우는 근사다. 계산 안정성과 의류 여유 판단에 유리하지만 실제 피부를 따라 잰 둘레와 동일하지 않다.

### 겨드랑이의 부풀음과 꺾임

초기 경계 분류와 가슴 높이의 팔 간격 보정이 겨드랑이 연결부까지 당겨 큰 변형을 만들었다. 다음을 적용했다.

- 모델별 팔·몸통 경계 재설정.
- 메시 인접 관계를 이용한 팔 변형 가중치 평활화.
- 팔 간격 보정 범위를 허리·엉덩이로 제한.
- 실제 Swift 계산 결과를 Blender로 다시 렌더해 앞·옆·뒤 비교.

최종 기본 체형에서 초기의 과도한 변형이 줄어든 것을 확인했다. 극단적인 모든 체형이나 다양한 의류의 외형을 검증한 것은 아니다.

## 8. 확인 결과와 해석 범위

### 8.1 실제 Swift 실행

실제 신체 로딩·변형 소스를 임시 macOS 실행 파일에서 구동했다. 의류 관련 타입은 실행에 필요한 최소 선언으로 연결했으며, 앱 전체나 의류 충돌 엔진을 실행한 검증은 아니다.

입력은 키 175cm, 몸무게 70kg, 어깨너비 45cm, 가슴 98cm, 허리 82cm, 엉덩이 98cm, 인심 82cm, 팔·다리 굵기 1이다.

| 결과 | 여성 | 남성 |
| --- | ---: | ---: |
| 생성 정점 / 삼각형 | 20,002 / 40,000 | 19,994 / 40,000 |
| 가슴둘레 | 약 98.000cm | 약 98.170cm |
| 허리둘레 | 약 82.000cm | 약 81.996cm |
| 엉덩이둘레 | 약 98.000cm | 약 98.000cm |
| 충돌 밴드 | 114 | 116 |
| 오른팔 단면 | 21 | 21 |

이는 코드가 사용하는 볼록 단면의 계산 결과다. 실제 인체 측정 정확도나 의류 실착 정확도를 나타내지 않는다. 로컬 계산 시간은 실행 환경에 따라 달랐으며 iPhone 성능 수치로 제시하지 않는다.

### 8.2 렌더 비교

- 원본과 경량화 사본을 동일한 조건으로 정면·측면·후면 비교했다.
- 최종 Swift 위치 데이터를 Blender 메시로 만들어 같은 세 방향에서 확인했다.
- 원본의 약 190cm 체형과 기본 입력의 175cm 보정 체형은 크기와 둘레가 달라 보이는 것이 정상이다.
- 이 비교는 Blender 렌더이며 iPhone의 RealityKit 화면 캡처가 아니다.

### 8.3 타입 검사와 빌드 제한

전체 앱 Swift 파일을 실제 iOS 26.1 SDK, Swift 5 모드, MainActor 기본 격리 및 프로젝트의 관련 upcoming feature 설정으로 직접 타입 검사했고 통과했다. 기존 ClothPhysics C 헤더를 노출하는 임시 모듈 맵을 사용했다.

실기기용 `xcodebuild`는 소스 컴파일 전에 대상 선택 단계에서 실패했다. 오류는 iOS 26.1 플랫폼이 설치되지 않았다고 안내했지만, 같은 Xcode의 `-showsdks`에는 iOS 26.1 SDK가 존재했다. SDK 파일 유무만으로 해결 원인을 단정하지 않았다.

따라서 다음은 완료했다고 주장하지 않는다.

- 앱 링크, 서명 및 최종 앱 번들 확인.
- Xcode를 통한 실기기 빌드·설치·실행.
- 새 남녀 모델에서 의류 착장 계산 완료 및 관통 검사.
- 모든 슬라이더 조합, 극단 체형, 성능·메모리·발열 확인.
- 기존 단위/UI 테스트 전체 재실행 및 새 에셋 전용 회귀 테스트.

## 9. 편집 및 재내보내기 시 주의

- 원본은 복구 기준으로 보존하고 경량화 사본 또는 별도 작업 사본에서 편집한다.
- Blender 사본을 바꾸어도 앱 JSON은 자동으로 갱신되지 않는다. 미터·Y-up 변환과 영역·가중치·기준점 데이터를 함께 다시 내보내야 한다.
- 정점 수나 면 순서를 변경하면 `indices`, `regions`, `armWeights`도 함께 다시 생성해야 한다. 이전 배열을 그대로 재사용하지 않는다.
- 모델의 자세·비율을 크게 바꾸면 기존 팔 경계식과 중심선·기준점을 다시 정해야 한다.
- 이번 처리와 미리보기 보조 스크립트는 임시 작업 파일로 실행했다. 저장소에 정식 재내보내기 도구나 빌드 단계로 등록한 상태는 아니다.
- 에셋의 수정·배포·상업적 이용 조건은 출시 전에 원본 제공 조건에 따라 확인해야 한다. 저장소의 코드 라이선스가 외부 에셋의 권리를 자동으로 정하는 것은 아니다.

## 10. 실기기 확인 순서

다음은 미실행 후속 항목이며 완료 체크리스트가 아니다.

1. Xcode의 iOS 26.1 플랫폼 및 기기 대상 인식 문제를 확인한다.
2. 앱을 빌드·설치하고 남녀 선택 시 새 전신 모델이 표시되는지 확인한다.
3. 먼저 의류 미착용 상태에서 회전·확대/축소와 정면·측면·후면을 확인한다.
4. 키·인심, 세 부위 둘레, 어깨너비, 팔·다리 굵기를 차례로 바꾸고 발바닥 위치·겨드랑이·골반·무릎 연결을 확인한다.
5. 티셔츠 95·110을 남녀 모델에 적용하고 소매 배치·어깨·가슴·허리의 겹침과 경고를 확인한다.
6. 연속 입력, 빠른 남녀/의류 전환에서 응답성, 이전 계산 취소, 잘못된 이전 의류 표시 여부를 확인한다.
