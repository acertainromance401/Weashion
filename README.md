### 핵심 가치

**ME** 나의 체형을 반영한 비교 기준 · **FASHION** 상품 치수별 착장 비교 · **WEATHER** 외출 환경을 함께 고려하는 보조 정보 · **FIT** 동일한 개인 마네킹에서 사이즈를 전환하며 비교

옷에 맞춰 몸을 바꾸는 것이 아니라, 설정한 몸을 유지한 채 옷의 치수와 사이즈를 바꾼다. 현재는 시각적 비교와 상상을 돕는 근사 미리보기이며, 구매 사이즈나 실제 착용 가능 여부를 확정하지 않는다.

### 사용자 경험

```text
남성/여성 기준 선택 → 키·몸무게 입력 → 개인 마네킹 확인·저장
→ 비교할 체형 하나를 활성화 → 상품 등록·사이즈별 치수 입력
→ 의상 자체 크기 변경 → 착장 계산
→ 한 마네킹에서 사이즈를 바꿔가며 착장·치수·여유·경고 비교
```

### 개발 우선순위

1. 개인 마네킹의 체형과 기준 치수 유지
2. 상품 실측 기준에 맞는 의상 크기 조절
3. 같은 체형에서 사이즈별 착장·여유 비교
4. 실제 제품·원단과의 차이 확인 및 피팅 품질 개선
5. 의상 종류 확장과 날씨·Outfit 경험 연계

- 남녀는 마름·보통·지방형·근육형 프리셋과 BMI 기반 시각적 분포 변화를 제공한다. 여성 골격의 기본·스트레이트·웨이브·내추럴 프리셋은 별도로 선택한다. 가슴·허리·엉덩이 자동 추정과 수동값을 구분하고 수동값을 보존한다. 체지방률·근육량 측정이나 의학적 체형 분류는 아니다.
- [BodyPreviewRenderer](weashion/weashion/Models/BodyPreviewRenderer.swift)는 actor에서 미리보기를 계산하고 기본 표면·부위 변위를 캐시한다. 최신 입력을 합치고 약 40ms 간격으로 처리를 제한한다. 실기기 FPS를 보장하는 수치는 아니다.
- 기존 [ParametricBody](weashion/weashion/Models/ParametricBody.swift)의 단면·충돌 유틸리티를 재사용하지만 [BodySkeleton](weashion/weashion/Models/BodySkeleton.swift)의 관절 리그가 외부 전신 메시를 구동하지는 않는다. 인체 스캔, 정확한 신체 복원, 자유 포즈·IK는 제공하지 않는다.

#### 여성 모델 체형 연결 · 2026-10-28

- 현재 남성 메시를 출발점으로 별도 제작한 [여성 Blender 모델](weashion/reference/female_from_male_candidate.blend)을 사용한다. 14,501정점·29,030삼각형, 기준 높이 1.60m이며 얼굴·유두 디테일은 추가하지 않았다. 제공받았던 [원본 Blend](Meshy_AI_Low_Poly_T_Pose_Figure_20261028_generate.blend)와 [이전 변환본](weashion/reference/female_mannequin.blend)은 보존한다.
- [제작·내보내기 스크립트](weashion/reference/build_female_from_male.py)가 최종 정점의 36개 부위 가중치·23개 기준점·팔다리 중심선과 골격 3종·가슴 크기 모프를 생성한다. Blender에서 기본 실행은 후보만 생성하고 `-- --publish`를 추가하면 여성 메시와 해시가 일치하는 모프 파일을 함께 교체한다. 직전 앱 여성 리소스는 [백업](weashion/reference/female_body_before_male_derived.zip)에 보관한다.
- 기존 사용자 저장값·체성분 프리셋·세부 조절 UI를 재사용한다. 프리셋 변경은 입력한 실측을 덮어쓰지 않는다. 가슴 크기·복부 등 세부 조절은 치수 보정 뒤 적용하므로 최종 표면의 둘레를 바꿀 수 있다. 여성 다리 중앙의 이동과 체성분에 따른 팔 여유를 보정해 확인된 사타구니·겨드랑이 겹침을 수정했다.
- 여성 기본형의 겨드랑이 뒤쪽 융기(광배근·대원근이 만나는 후액와 주름)를 국소적으로 줄였다. [수정 전후](weashion/reference/female_latissimus_comparison.png)는 같은 Swift 피팅 조건의 후면·후면 사선 비교다. 남성 기본형은 변경하지 않았다.
- 남녀 공통으로 `시각 조절 → 광배 크기`를 제공한다. 50~150%는 근육 부피 측정값이 아닌 기본형 대비 시각 조절값이며, 저장·초기화·미리보기·피팅에 함께 적용된다. [남녀 3단계 비교](weashion/reference/latissimus_controls.png)의 6개 사례에서 저장 왕복과 표면 일치를 확인했다. 여성은 교차가 없고 남성은 기존 기본형의 교차 6쌍을 늘리지 않았다. 다른 세부 조절처럼 최종 표면 둘레는 달라질 수 있다.
- 실제 Swift 변형 코드를 별도 실행해 기본형·골격·체성분·가슴 크기·150/180cm·세부 조절 12개 사례에서 미리보기와 피팅 정점 일치, 충돌 표면 일치를 확인했다. [기본형 렌더](weashion/reference/female_from_male_fitted.png), [골격 비교](weashion/reference/female_from_male_fitted_frames.png), [체성분 비교](weashion/reference/female_from_male_fitted_composition.png), [크기 조절 비교](weashion/reference/female_from_male_fitted_adjustments.png)는 당시 Swift 결과를 Blender로 렌더한 것이다. 이 사례들의 표면 교차는 없었으나 전체 입력 조합·실제 의류 드레이핑·실기기 화면을 검증한 것은 아니다. 당시 앱 빌드·설치는 수행하지 않았으며, 이후 시뮬레이터 검증은 아래 항목에 기록한다.

#### 여성 뒤겨드랑이·위팔 경계 개선 · 2026-10-29

- [여성 Blender 모델](weashion/reference/female_from_male_candidate.blend)의 양쪽 뒤겨드랑이에서 아래로 늘어진 연결부를 줄이고, 등 옆면과 위팔 뒤쪽 사이에 완만한 경계를 만들었다. 어깨와 팔을 절단하거나 벌리는 방식이 아니라 기존 연결 구조를 유지하는 국소 변형이다. 636개 정점에 최대 약 12.6mm의 변위를 적용했으며, 나머지 정점과 삼각형 연결·남성 리소스는 보존했다.
- 변경은 [제작 스크립트](weashion/reference/build_female_from_male.py)의 `refine_posterior_axilla`에 포함되어 재생성 시에도 유지된다. [앱 여성 메시](weashion/weashion/Resources/female_body_40k.json)와 [골격·가슴 모프](weashion/weashion/Resources/female_body_frame_presets.json)를 함께 게시했고, 저장된 Blender 정점과 앱 기준 정점의 일치 및 모프의 메시 해시 일치를 확인했다.
- [수정 전후 비교](weashion/reference/female_axilla_comparison.png)는 iOS 시뮬레이터에서 실제 `BodyPreviewRenderer`가 생성한 여성 기본형을 같은 조건으로 Blender에서 렌더한 것이다. 왼쪽은 수정 전, 오른쪽은 수정 후이며 위는 후면, 아래는 후면 사선이다. 비교 이미지에서만 목·허리·팔 아래를 잘라 표시하며 앱 메시 자체는 닫힌 전신이다.
- [회귀 테스트](weashion/weashionTests/FemaleMannequinTests.swift)는 좌우 후면 6개 표본에서 위팔 경계의 상대 깊이 7mm 초과·20mm 미만과 닫힌 단일 연결 메시를 검사한다. 기존 리소스에서는 6개 깊이 검사가 실패하고 수정 후 통과했다. 기본형·골격 3종·체성분 3종·150/180cm·광배 조절 양 끝·가슴/위팔 조절의 12개 사례에서 미리보기·피팅·충돌 정점 일치와 해부학 가중치 유효성도 확인했다.
- Xcode의 iOS 시뮬레이터 앱 빌드와 위 2개 회귀 테스트가 통과했다. Blender의 골격·가슴 모프 12개 조합, 실제 Swift 피팅 결과 9개 사례에서 자체 교차와 면 뒤집힘이 없었다. 전체 입력 조합·실기기 화면·실제 의류 드레이핑은 이번 검증 범위가 아니다.

여성 기준의 기본 치수·팔다리 굵기 배율 하한을 확장했다. 아래 상한값과 남성의 기존 범위는 유지한다.

- [BodyMeasurement](weashion/weashion/Models/BodyMeasurement.swift)의 `range(for:)`를 편집 슬라이더·측정 안내의 숫자 입력·최초 설정·자동 추정값 제한·체형 저장 검증에서 공통으로 사용한다. 세부 부위별 비율과 광배·가슴 등의 개별 시각 조절 범위는 변경하지 않았다.
- 직접 입력한 치수는 기준 체형을 바꿔도 보존한다. 여성 전용 확장 범위의 값을 유지한 채 남성으로 바꾸면 남성 범위 검증에서 저장을 거부하며, 임의로 값을 올리지 않는다.
- [범위 테스트](weashion/weashionTests/BodyMeasurementRangeTests.swift)는 정확한 하한·상한, 범위 밖 입력, 남성 범위 유지, 최초 설정의 기준별 검증을 확인한다. 각 여성 하한의 단독 적용 9개·전체 하한 동시 적용·140cm/35kg 조합의 11개 사례에서 미리보기·피팅·충돌 정점 일치와 유효한 해부학 가중치를 확인했다.
- [저장 테스트](weashion/weashionTests/FittingLibraryTests.swift)는 새 하한값을 포함한 초기 설정 임시 저장·체형 저장·재실행 복원과 범위를 벗어난 기준 변경의 거부를 확인한다. 해당 테스트와 기존 여성 모델 회귀 테스트를 포함해 iOS 시뮬레이터 빌드 및 20개 테스트가 통과했다.
- 이 수치는 편집 허용 범위이며 실측 정확도나 건강 기준을 뜻하지 않는다. 모든 극단치 조합의 형태 정확도·자체 교차·의류 드레이핑 및 실기기 화면까지 검증한 것은 아니다.

### 현재 착장 구현

3D 피팅은 기존 그레이 면 반팔과 **긴팔 → 후디 → 드레스 팬츠 → 진 → 봄버 → 스니커즈**의 7개 디자인을 지원하며, 디자인별 S·M·L 기준을 [의류 카탈로그](weashion/weashion/Resources/garments.json)에 저장한다. 상품 보관함의 **샘플 추가**에서 필요한 모델을 명시적으로 추가한다. 기존 사용자의 상품·선택 상태와 삭제한 샘플은 자동으로 덮어쓰거나 복원하지 않는다. **상의·하의·신발·아우터 각 한 개를 동시에 착장**하며, 같은 슬롯에서 상품·사이즈를 바꿔도 다른 슬롯은 유지한다. 후디는 상의, 봄버는 아우터 슬롯이다.

- [Meshy 원본](Meshy_AI_Gray_T_Shirt_1026125442_generate.blend)은 343,758정점·687,781삼각형으로 보존했다. 최종본은 안정적인 연결 구조에 원본의 주요 앞뒤 주름을 옮긴 **3,038정점·5,952삼각형 재구성 메시**다. 원본 토폴로지를 그대로 감량한 결과가 아니다.
- [편집용 Blender](weashion/Cotton_TShirt_Optimized.blend)와 [앱용 JSON](weashion/weashion/Resources/meshy_cotton_tshirt.json)을 분리한다. 앱에서 Blender/GLB 파일을 직접 읽어 자동 피팅하는 기능은 아니다.

- 총장은 현재 메시 상단부터 밑단까지, 어깨는 양쪽 봉제점 사이, 소매는 어깨 봉제점부터 바깥 소매 끝까지 적용한다. 소매 중심축을 측정 기준으로 사용하던 차이를 수정했다.
- 가슴·밑단·소매부리의 단면 입력은 펼친 옷의 폭이며 내부에서는 두 배의 둘레를 미터로 변환한다. M 가슴단면 54.5cm는 기준 가슴둘레 109cm다. 입체 착장 정면 폭이 54.5cm라는 뜻은 아니다.
- 사진에 없는 5 밑단단면·6 소매부리단면·7 암홀은 실측값으로 간주하지 않는다. 미입력 시 원본 비율을 사용하며 선택적으로 직접 입력할 수 있다. 암홀은 어깨와 겨드랑이 사이 깊이 조절이며 전체 봉제선 곡선 길이 측정은 아니다.

- [GarmentCategories](weashion/weashion/Models/GarmentCategories.swift)는 상의·바지·신발의 입력과 바인딩을 구분한다. 바지 단면은 둘레의 절반이며 cm로 입력한다. 신발은 외부 치수만 mm로 입력하며 내부 치수·브랜드 호수와 구분한다.
- [LowerGarmentFitter](weashion/weashion/Models/LowerGarmentFitter.swift)는 바지의 허리·엉덩이·밑위·인심·허벅지·밑단을 따로 변경한다. 바지 **총장 = 밑위 + 인심**으로 정의하고, 총장 입력 시 밑위를 유지해 인심과 양쪽 밑단을 변경한다. 인심·밑위 입력 시 총장도 연동한다. 이는 실제 옆선 곡선을 잰 아웃심이 아닌 편집용 근사이며, 저장 형식은 기존 밑위·인심을 그대로 사용한다. 밑위와 인심을 착용자 길이에 강제로 맞추지 않으므로 큰 옷의 남는 기장이나 작은 옷의 당김이 사라지지 않는다. 좌우 다리와 발은 실제 변형된 신체 표면에서 각각 계산한다.
- [GarmentSleeveBinding](weashion/weashion/Models/GarmentSleeveBinding.swift)은 긴팔·후디·봄버 원본의 좌우 소매 중심선을 별도로 보존한다. 어깨~소매 끝 직선을 소매 속 중심으로 오인하지 않으며, 원본의 앞뒤·주름과 몸통/팔 연결 가중치를 유지해 실제 팔·손 중심선에 배치한다. 소매부리가 손보다 좁고 소매가 손목을 넘는 경우에는 상품 메시의 원래 길이는 남기고 초기 배치를 손목 쪽으로 압축한 뒤 소매 끝 테두리를 고정한다. 형상 유지형 후디는 아래처럼 압축을 소매 전체에 분산하고 끝 테두리에도 제한된 접촉 보정을 허용한다. 손가락 단면 하나가 아닌 전체 손의 포락 단면으로 통과 가능성을 추정한다. 이는 정적 소매 걸림 근사이며, 손목보다도 좁은 소매의 무관통이나 실제 입고 벗는 과정을 보장하지 않는다.
- [WearableMeasurementsEditor](weashion/weashion/Views/WearableMeasurementsEditor.swift)는 바지·신발 전용 입력·미리보기·범위 검증을 제공한다. 상품 종류 변경 시 이전 사이즈는 보존하지만 다른 종류의 치수로 자동 변환하지 않는다. 긴팔·후디·봄버는 기존 상의 편집기를 사용하며 소매부리와 후드가 반팔 기본값으로 바뀌지 않도록 한다.
- 모든 상의 편집기에 **소매통(내부 배율 50–150%)**, 바지 편집기에 **바지통(50–150%, 기본 100%)**을 제공한다. 후디 이외 상의는 표시 범위와 내부 범위가 같고 기본은 100%다. 입력한 기준 치수에 추가 적용하는 공통 배율이며, 소매는 위팔·아래팔·소매 끝의 단면을 같은 배율로 변경해 기존 테이퍼를 유지하고 어깨 연결부는 기존 가중치로 부드럽게 연결한다. 바지는 허벅지부터 밑단까지 함께 조절하고 허리·엉덩이·기장은 유지한다. 상품별 사이즈 저장·재편집·미리보기·착장 캐시에 포함하며, 기존 저장 데이터에 배율이 없으면 기존 형상을 그대로 사용한다. 후디의 모자 고정 정책은 유지한다.
- 후디 M의 착용 기준은 사용자가 승인한 **내부 총장 65 / 어깨 58 / 가슴단면 56 / 소매 50cm / 소매통 80%**다. [GarmentSizeLabelCalibration](weashion/weashion/Models/GarmentSizing.swift)은 이를 화면에서 **70 / 52 / 58 / 60cm / 100%**로 표시하며, 편집값은 같은 비율의 역변환으로 저장·계산한다. 이는 샘플 기준의 숫자 보정이지 실측 단위를 바꾼 것이 아니다. 편집기·사이즈표·노트·비교·접근성 설명에 같은 변환을 사용한다. 기존 사용자 치수는 다시 쓰지 않으며, 수정하지 않은 샘플 치수만 현재 카탈로그로 갱신한다. 소매통의 내부 허용 범위는 그대로여서 후디의 표시 범위는 **62.5–187.5%**이고, 기존 내부 100% 기록은 125%로 표시되어 기존 착용 형태를 유지한다.
- 후디 S·M·L은 카탈로그의 `fittingMode: shapePreserving`으로 **형상 유지형 시각 보정**을 사용한다. 모자 본체는 높이·좌우·앞뒤 위치의 연속적인 가중치로 목/등 연결부·앞목 입구와 구분한다. 본체의 사이즈와 형상을 유지하고 어깨 높이 이동에 더해 뒤로 20mm 배치하며, 목/등 연결부는 부드럽게 변형·접촉 보정한다. 몸판의 앞뒤 중심은 실제 착용 높이의 신체 단면을 사용하며, 긴 밑단에는 다리 단면까지 반영한다. 소매는 원본과 신체 중심선을 각각 단일 3차 곡선으로 근사하고 한 팔의 회전을 어깨에서 연속 보간한다. 구간마다 단면을 급회전시키거나 휘어진 원본 중심선을 직선으로 오인하지 않는다. 손목 걸림 시 길이 압축은 소매 전체에 분산하며, 소매 끝을 강제로 고정하지 않고 제한된 접촉 보정을 허용한다. 원본 주름·소매통 20% 축소·정점/면 수는 그대로이고 다른 상품은 기존 천 계산을 유지한다.
- 후디 접촉 보정은 최대 12회·초기 배치 대비 최대 40mm이며, 모자 본체에는 보정량 0을 적용한다. 접촉 이동량만 이웃끼리 평활화하고 이미 배치된 변·인접 면 형상을 보호해 원본 주름을 지우지 않는다. 면의 뒤집힘과 초기 배치에서 접히지 않았던 연결부의 90도 초과 접힘은 보폭을 줄여 방지한다. 반복 처짐·원본 팔 자세의 굽힘·테더·96회 마무리 계산은 생략한다. 동적 주름이나 실제 원단 물성을 재현하는 방식은 아니며, 해결하지 못한 신체/안쪽 옷 겹침과 늘어남은 계속 측정·경고한다. 화면의 형상 유지형 안내와 착장 캐시 무효화도 유지한다.
- 후디의 어깨 소매가 둥글게 부푸는 외형은 초기 배치에서 소매 중심선 기준 단면을 최대 22% 줄여 보정한다. 몸통 바깥의 어깨~위팔에만 연속 가중치를 적용하고 소매 길이의 60% 지점까지 보정을 0으로 줄이므로 모자·몸통 중앙·아래팔·소매 끝 치수는 바꾸지 않는다. 사용자의 전체 소매통 배율은 그대로 유지하며 최종 접촉 보정과 겹침 경고도 생략하지 않는다.
- 승인된 후디 기준에서 하얗게 드러나던 어깨·위팔은 초기 배치의 신체 단면 기준 앞뒤 여유로 보정한다. 내부 소매통이 100%보다 좁아질 때만 연속적으로 적용해 기존 100% 이상의 배치는 바꾸지 않는다. 이미 여유 있는 표면에서는 보정을 줄이고, 앞뒤를 갑자기 나누거나 목 개구부를 임의로 메우지 않는다. 모자 본체의 고정 마스크는 유지하고 배치 단계의 모자/어깨 연결 가중치만 완만하게 전환한다. 원본 정점·삼각형과 Blender 파일은 바꾸지 않았다. 승인된 남성 175cm M은 최종 잔여 겹침 약 **0.83mm**, 새 날카로운 접힘 **5곳**으로 확인했으며, 네이티브 결과의 앞뒤 렌더에서 어깨의 흰 틈이 사라진 것을 확인했다. 다른 체형의 무관통을 보장하지 않으며, 남성 172cm의 표시 소매통 80/100/120%에서는 약 **7.67/5.78/10.83mm**의 잔여 겹침과 기존 경고를 그대로 남긴다. 이전 남성 172cm·여성 회귀 테스트는 입력 조건이 바뀌지 않도록 당시의 내부 M 치수 70/52/58/60cm·소매통 100%를 명시하고, 승인된 새 175cm 기준은 별도로 검증한다. 라벨·저장 복원, 승인 기준, 소매통 3단계, 기존 남녀 치수, 후드 유지의 집중 테스트 6개가 통과했다.
- 앞서 후디 전체의 굽힘 컴플라이언스를 4에서 0.5로 낮췄지만 실기기에서 과도한 처짐·구김이 계속되어 형상 유지형으로 전환했다. `softness: firm` 기본값은 남아 있으나 형상 유지형은 이 값으로 처짐/굽힘을 계산하지 않는다. 소재 수치만으로 모자의 원형이 고정되는 것은 아니다. 아래 기존 42사례·레이어·성능 수치와 비교 렌더는 소매통 축소 및 형상 유지형 전환 전 결과다.
- 이전 형상 유지형의 9개 수치 테스트는 변 길이·이동량 등을 검증했지만 자연스러운 외형을 보장하지 못했다. 후속 단계별 캡처에서 원래 매끈하던 5mm 이상 연결 변이 90도 넘게 접히는 현상을 확인했다. 172cm 남성 M의 소매통 80/100/120%에서 초기 배치 접힘은 262/251/333곳, 최종은 317/287/370곳이었다. 수정 후 **5개 집중 네이티브 테스트가 통과**했으며 초기 접힘은 6/6/1곳, 최종은 **5/4/1곳**으로 줄었다. 세 배율 모두 최종 접힘 15곳 미만과 변 길이 3배 미만을 유지하고, 배율 저장/재편집·S/M/L 모자 형상·취소/유효성·40mm 제한도 확인했다. 여성 기본 M은 초기/최종 접힘 2/2곳이었다. 기본 100%의 정면·후면·측면과 80/120% 실루엣을 실제 네이티브 출력으로 렌더해 함께 확인했다.
- 완전한 무관통을 보장하지는 않는다. 위 남성 80/100/120%의 전체 잔여 겹침은 각각 약 **2.43/0.20/10.65mm**, 여성 기본 M은 약 **1.99mm**였다. 남성 기본 100%의 표시 겹침은 0mm였고 목 뒤·허리의 피부 노출이 비교 렌더에서 사라졌다. 120%는 넓어진 소매부리가 손을 통과해 손 쪽까지 내려오며 그 부근 접촉이 남는다. 이 잔여값과 경고를 숨기거나 검증 기준을 완화하지 않는다. 이번 iOS 시뮬레이터의 172cm 남성 기본 M 비캐시 착장은 약 4.08초였으며, 실기기 시간이나 동일 조건의 속도 개선율을 의미하지 않는다.
- 스니커즈는 실제 좌우 뒤꿈치→발끝 방향으로 각각 회전하며, 발에 맞춰 자동 확대하거나 천처럼 늘리지 않는다. 발의 길이·너비는 이 방향의 포락 상자에서 측정한다. 기존 신체 편집의 Z방향 발 길이 보정은 바꾸지 않았으므로 편집 입력과 이 착장용 측정값 사이에 근사 차이가 있을 수 있다. 길이·너비 차이는 외형과 발의 비교일 뿐이다. 추정한 밑창 높이만큼 착용자의 표시 위치를 올려 밑창이 바닥 아래에 숨지 않게 하고, 미착용·다른 종류 전환·표시 실패 시 높이를 복원한다. 표시 메시의 신체 겹침도 표본 검사해 경고하지만, 강체 신발의 충돌 보정·내부 공간·실제 착화감 검증은 지원하지 않는다.
- [FittingLibrary](weashion/weashion/Models/FittingLibrary.swift)는 화면에서 편집 중인 상품과 실제 네 슬롯 착장을 구분한다. 기존 단일 선택 기록은 해당 슬롯으로 손실 없이 가져오며, 슬롯별 미착용·사이즈/상품 삭제는 다른 슬롯을 해제하지 않는다. 상품 보관함에서 입히면 그 상품의 슬롯만 교체하고, 피팅룸의 슬롯 행에서 편집 대상 변경·개별 해제가 가능하다.
- [GarmentController](weashion/weashion/Views/GarmentController.swift)는 신발→하의→상의→아우터 순으로 착장을 계산한다. 신발 외형과 앞서 계산한 안쪽 의류의 원래 패널 삼각형을 각각 독립된 정적 충돌 표면으로 넘긴다. 몸에 더 가까운 삼각형이 있다는 이유로 안쪽 옷의 표면을 무시하지 않는다. 안쪽 레이어는 신체 표면의 바깥 방향으로 실제 유한 삼각형과 교차하는 가장 바깥 면을 찾는다. 안감의 반대 법선이나 밑단의 무한 평면이 바깥 옷을 신체 안으로 밀어 넣지 않으며 원본 표시 메시도 바꾸지 않는다. 신체 법선 방향의 외피 근사이므로 방향상 놓친 접촉·개구부·표본 사이의 관통·옷 자체의 겹침은 남을 수 있다. 표시용 곡면 세분화·장식 테두리는 레이어 충돌에 포함하지 않는다. 안쪽 착장이 실패하면 바깥 레이어 계산도 중단하고 오류를 표시한다.
- 신발을 신으면 마네킹과 모든 의류를 밑창 높이만큼 함께 올린다. 계산은 맨발 좌표계에서 수행하고 마지막 표시 오프셋만 공유한다. 치수 편집의 독립 미리보기는 편집 상품 하나를 표시하며, 피팅룸에는 전체 착장을 반영한다.
- 계산 중에는 **마네킹 영역에만** 반투명 로딩 패널과 흐린 미완성 형상을 표시한다. 실제 준비·신체/안쪽 옷 보정·표시 단계와 현재 슬롯/완료 슬롯 수를 사용하며, 가짜 진행률이나 예상 시간은 표시하지 않는다. 다른 상품·치수로 바꾸면 이전 작업을 취소하고 최신 요청만 표시한다. **계산 취소**는 선택·치수를 유지하고 미완성 결과를 완료된 착장으로 공개하지 않는다. 취소 상태의 **다시 계산**으로 같은 착장을 재시도할 수 있다. 상품·슬롯·치수 편집은 로딩 패널 밖에서 계속 사용할 수 있다.
- 레이어 충돌 방향은 소매의 팔 중심선과 몸통 중심선을 참고해 계산한다. 겨드랑이에서 가까운 피부가 몸통↔팔로 바뀌어 잘못된 방향으로 밀리는 것을 줄이고, 안쪽 옷을 피하는 보정이 인접한 피부를 향하면 피부 접선 방향으로 제한한다. 화면용 곡면 보간이 새로 피부를 침범하면 더 안전한 선형 중점으로 제한한다. 실제 표시 메시의 모든 정점과 각 면의 일곱 표본을 추가 검사해 경고에 반영하며, 원래 정점·치수 보존만으로 화면의 무관통을 주장하지 않는다.

#### 착장과 비교

```text
상품 치수 → 의상 자체 크기 변형 → 고정된 마네킹에 배치
→ 정적 겹침 보정 → 입력 치수·착장 후 근사 치수·사이즈별 모습 비교
```

- [GarmentSizing](weashion/weashion/Models/GarmentSizing.swift)이 의상 크기를 먼저 변경한다. [GarmentEditorView](weashion/weashion/Views/GarmentEditorView.swift)는 치수 선택/입력과 적용 전 미리보기·취소·적용을 제공하며 마네킹 치수는 바꾸지 않는다.
- 피팅룸은 활성 체형 하나를 기준으로 선택 상품의 사이즈와 미착용 상태를 전환한다. 새 저장소에는 M이 선택된 샘플 상품을 한 번 제공하며, 이후에는 마지막 선택을 복원한다. 상품명·원본 URL·메모는 상품별로, 실측 치수·추정 소재·사이즈명은 각 상품의 사이즈별로 보관한다. 서로 다른 상품의 M은 별도 기록이다.
- [GarmentFit](weashion/weashion/Models/GarmentFit.swift)은 단면과 어깨·소매 배치를 보정한다. 현재 `sizing` 경로는 작은 옷의 목표 단면 둘레를 몸 크기까지 자동 확대하지 않지만, 이후 충돌 보정은 정점과 변 길이를 바꿀 수 있다. 최종 표면의 상품 치수 완전 보존을 보장하지 않는다.
- 입력 총장·어깨·가슴단면·소매길이, 가슴 여유, 어깨 차이, 착장 가슴둘레(볼록 단면 근사), 착장 총장(수직), 최대 표면 늘어남을 표시한다. 실제 원단 거동이나 모든 지점의 피부 간격을 계산한 값은 아니다.
- [GarmentDraper](weashion/weashion/Services/GarmentDraper.swift)는 actor에서 메시 준비·착장·정적 겹침 보정을 수행한다. 상의와 바지는 천 경로, 신발은 별도의 강체 경로를 사용한다. 패턴/치수·신체 식별자/리비전·기준점·안쪽 레이어의 패턴/치수/소재·계산기 버전으로 캐시하며 준비 메시와 결과에 각각 16MB의 메모리 캐시를 사용한다. 편집 대상만 바꾸면 이미 계산된 다른 슬롯의 모델을 재생성하지 않는다.
- 후디 등 메시를 읽고 치수를 배치한 초기 형상을 먼저 표시하며 **착장 계산 중** 상태를 유지한다. 이는 충돌 보정 완료나 착장 성공 판정이 아니다. 이후 최종 결과로 교체하고 겹침/늘어남 경고를 표시한다. 충돌 검색은 삼각형 BVH와 정점/면 표본별 최근접 후보를 사용한다. 최근접 후보는 검색의 초기 상한일 뿐 나머지 트리 검사를 생략하는 근사가 아니다. 일반 천 착장 모드에서는 72회 기본·최대 96회 최종 접촉 보정과 7개 면 표본을 유지하고, 최종 잔여 겹침 확인만 네 접촉 보정마다 묶어 수행한다. 형상 유지형 후디는 위에서 설명한 별도의 최대 12회 보정을 사용한다. 완전히 고정된 표본의 겹침만으로 반복을 계속하지 않으며, 두 연속 묶음의 최대 이동과 이동 가능한 표본의 겹침 변화가 각각 0.05mm 미만이면 정체된 보정을 끝낸다. 고정·정체된 표본을 포함한 실제 잔여 겹침과 경고는 그대로 남긴다.
- 겹침 계산은 정점뿐 아니라 삼각형의 중심·변 중점·분할 면 중심을 검사한다. 최종 접촉 보정에도 변 늘어남 제약을 교대로 적용해 접촉만 반복하면서 면이 폭발적으로 늘어나는 것을 막는다. 반복 제약이므로 면 전체의 무관통이나 자연스러운 형태를 보장하지 않는다. 표면 늘어남은 기준 길이 5mm 이상인 변의 최대 상대 증가율이며 실제 원단의 실측 신축률이 아니다.
- 레이어 착장에서는 개별 접촉 이동을 2mm로 제한하고, 이동 가능한 표본의 겹침 제곱합이 세 연속 묶음 동안 최선값 대비 0.1% 이상 개선되지 않으면 최선 상태로 돌아간다. 이 상태에서 접촉 밀어내기 없이 변 늘어남을 추가로 보정한다. 해결 불가능한 접촉을 위해 면을 무제한 늘리지 않으며, 실제 잔여 겹침을 경고한다. 긴팔 몸판의 레이어 방향·안쪽 소매 제외와 기존 피부/팔 충돌은 별도로 처리한다.
- 레이어의 마지막 변 길이 보정이 피부 관통을 되돌리는 경우에는 **최대 16회 피부 전용 마무리 보정**을 추가한다. 이동 가능한 피부 표본 1mm 이하를 목표로 하며, 한 번의 이동은 2mm로 제한하고 고정된 소매 끝은 임의로 움직이지 않는다. 이 단계는 옷끼리의 겹침을 해결하지 않으며 변 늘어남이 다시 증가할 수 있으므로 실제 늘어남·겹침 경고를 유지한다. 앞선 최종 접촉 96회와 합쳐 최대 112회이며, 전체 표면 무관통이나 원단 허용 신축률 이내를 보장하지 않는다.
- 메시 형식은 `vertices`, `indices`, `trims`와 종류별 `fitting`·`sizing`·선택적 `sleeves`, `trousers`, `footwear`다. 서로 다른 종류의 바인딩을 섞은 입력은 거부한다. 의류 입력 한도는 12,000정점·40,000삼각형·JSON 16MB이며 실시간 성능 보장은 아니다.

#### 확인 결과와 한계

- 변형 정점에서 총장 61·63·65cm, 어깨 51·53·55cm, 바깥 소매 18·19·20cm를 확인했다. 가슴단면은 51.982·54.481·55.981cm로 기준값 대비 최대 약 0.2mm 차이가 있었다. 실제 제품·실착 정확도를 검증한 결과는 아니다.
- 남성 기본 175cm/70kg의 실제 Swift·C++ 착장 계산과 S·M·L Blender 비교 렌더를 수행했다. 한 실행에서 샘플 잔여 겹침은 0mm였지만 최대 표면 늘어남은 약 78~98%로 컸다. 이 수치는 최종 소매 측정 보정 전의 관찰이며, 겨드랑이·연결부 보정과 핏 차이가 남아 있다.
- 면이라는 정보 외에 조직·두께·혼용률·방향별 신축률은 미확인이다. `maximumStrain: 0.05`는 경고 기준이지 실측 신축률이나 물리적 변형 제한이 아니다. 중력·동적 주름·봉제·천 자기충돌 시뮬레이션은 제공하지 않는다.
- 추가 종류의 기반 변경 후 기존 체형·저장·에디토리얼 회귀 51개와 다리·발 프로필 및 기존 반팔 회귀 7개가 iOS 시뮬레이터에서 통과했다. 다리와 발의 좌우 분리·발 길이·기준점 이동, 비대칭 부위 조절, 기존 남녀 반팔 S·M·L의 정적 계산을 포함한다. 당시 반팔 6개 사례의 잔여 겹침은 0mm, 95백분위 기반 늘어남 지표는 약 9.9~11.2%였다. 이 이전 지표를 현재의 최대 변 증가율과 혼동하지 않는다.
- 추가 6종은 남성 기본형 S·M·L과 마른·큰 체형·근육형 남성 및 여성 M의 42사례를 계산기 26의 실제 Swift/C++ 경로로 다시 실행했다. 크기·체형별 정점 차이와 여유 차이, 기준 길이 5mm 이상인 변의 3배 미만 길이 회귀를 확인했다. 같은 실행의 신체·의류 캡처로 [비교 렌더](weashion/reference/garment_validation/) 91개와 수치 자료를 갱신했다. 실제 평활화된 의류 표면을 사용하며 장식 테두리는 제외한다. 개별 상품의 계산 경로에는 레이어 전용 마무리 보정을 적용하지 않는다.
- 성능·슬롯 개편 후 긴팔·후디·봄버 기본 M의 샘플 겹침은 각각 약 0.73·0·1.04mm다. 이는 정점·일곱 면 표본의 수치이며 평활화된 면 전체의 무관통 판정이 아니다. 이전의 거대한 소매 돌출은 수정했지만, 모든 체형·사이즈가 이 결과를 만족하는 것은 아니다.
- 이전 슬롯 개편에서는 의류·저장 단위 테스트 36종과 기존 남녀 반팔 S·M·L 착장을 포함한 별도 회귀 1종이 통과했다. 레이어가 피부에 가려지지 않는지, 반대 방향 안감·열린 밑단 처리, 피부/레이어의 팔 제외 구분, 고정된 표본의 잔여 겹침 유지, 불가능한 접촉에서의 면 늘어남 억제도 검사했다. 당시 실제 UI 테스트 2종도 통과했다. 하나는 여섯 모델 착장 완료, 바지 허리단면 44.5cm·총장 96cm·신발 외부 길이 285mm 편집 후 재계산, 재실행 후 네 슬롯·치수 복원, 아우터 해제 후 세 슬롯 재실행 복원을 확인한다. 다른 하나는 소수 입력의 총장·밑위·인심 양방향 연동, 이진 부동소수점 오차 없는 표시, 총장 96cm·밑위 28cm·인심 68cm 저장 후 편집기 재열기를 확인한다. 실기기 설치·성능 검증은 아니다.
- 이번 로딩·충돌 개편의 네이티브 회귀는 분할 실행에서 서로 다른 72개 테스트가 통과했다. 실제 마네킹의 회색 반팔 팔 충돌, 표시 메시 피부 검사, 레이어 보정의 피부 우선 처리, 진행 중 취소·최신 선택 반영, 장면 상태와 저장 회귀를 포함한다. 한 번의 전체 72개 성공 실행을 뜻하지 않는다.
- 이번 UI 회귀 2종도 분할 실행에서 통과했다. 여섯 모델 착장과 치수 편집·재실행 복원에 더해, 마네킹 영역의 실제 단계·슬롯 로딩 표시, 네 슬롯 선택을 유지한 취소, 취소 상태 안내와 다시 계산 완료를 확인했다. 별도 총장·밑위·인심 소수 입력 연동 회귀도 통과했다. 취소/재시도 전환 시 접근성 트리를 교체해 화면과 VoiceOver·UI 테스트 상태가 함께 갱신되도록 했다. iOS 26.1 시뮬레이터 결과이며 실기기 검증은 아니다.
- iOS 26.1 시뮬레이터의 일반 Debug 빌드(C++ `-O2`, `-enableCodeCoverage NO`)에서 후디 초기 표시는 1초 미만, 캐시 없는 최종 계산은 약 9.43초, 캐시 재사용은 약 0.072ms였다. 후디·진·스니커즈·봄버 M의 네 슬롯 최초 계산은 **약 80.89초 → 51.90초(약 36% 단축)**였다. 팔/몸통 필터를 위한 BVH 하위 트리 제외와 레이 방향 역수 재사용은 접촉 표본을 줄이지 않는 정확 검색 최적화다. 커버리지 계측 빌드에서는 더 느리다. 초기 표시는 계산 완료가 아니고, 모든 체형·치수나 기기에서 같은 시간을 보장하지 않는다.
- 기존 회색 반팔의 팔 충돌 제외가 남성 피부 관통 약 16–22mm를 가리던 문제를 수정했다. 기존 남녀 S·M·L 6사례의 표시 메시 피부 표본은 0mm였고, 앱의 실제 남성·여성 기본 마네킹 M은 각각 약 1.66·0mm였다. 이 값은 정점·면 표본 결과이지 연속 면 전체의 무관통 인증이 아니다.
- **완전한 충돌 해결은 아니다.** 개별 상품 35개 천 사례 중 표시 메시 검사를 포함하면 15개는 3mm 초과 관통이 남았고 최댓값은 드레스 팬츠 L의 약 25.73mm였다. 소매 끝·손이나 긴 바지 밑단·발 등의 한계가 있으며 앱은 남은 겹침·과도한 당김·밑단 높이를 경고한다. 바닥·천 자기충돌·동적 쌓임을 풀지 않고, 원본의 작은 슬롯/개구부도 보존하므로 비교 렌더의 피부 노출을 무관통 증거로 해석하지 않는다. 신발 7사례에서도 표시 메시의 신체 관통 약 22.35–26.61mm가 검출되며 경고한다. 강체 신발을 자동 확대하거나 피부를 숨겨 해결한 것으로 만들지 않는다.
- 위 42사례는 개별 상품 착장이다. 별도 네 슬롯 M 조합의 **표시 메시 피부 관통 표본**은 진·후디·봄버 각각 약 **0.59·0.75·1.04mm**였다. 마지막 보정 전의 봄버 약 17.85mm를 줄였고, Blender의 독립 최근접/삼각형 교차 검사에서도 세 천 모델에 2mm 초과 피부 표본이 없었다. 전체 잔여 겹침 지표는 진 약 11.49mm·후디 0.83mm·봄버 62.20mm·신발 26.11mm로 남는다. 특히 옷끼리의 교차는 아직 해결되지 않았으며, 더 큰 봄버 L도 약 65.25mm로 단순 사이즈 변경만으로 해결되지 않았다. 표시 변의 최대 길이 비율은 진 1.45·후디 1.29·봄버 2.34배로 3배 미만이지만 실제 원단 물성 이내라는 뜻은 아니다. 실제 UI에서도 잔여 겹침·당김 경고를 유지한다.
- 샘플 겹침 0은 전체 면의 관통 없음이나 정확한 착용 판정이 아니다. 실제 제품 대조, 전체 극단치 조합, 여러 겹 착장, 상품 자동 수집·원격 배포와 실기기 화면·성능은 미확인 또는 후속 과제다. 이전 반팔 제작 당시 기록은 [진행 기록](docs/progress-2026-10-26.md)과 구분한다.

### 에디토리얼 화면 디자인

상세 방향과 반영 범위는 [UI/UX 및 모션 디자인 설계·구현 기록](docs/editorial-design-direction.md)에 정리했다. 해당 문서는 화면별 구성·디자인 토큰·모션 명세·실기기 확인 기준을 다루며, 구현한 부분과 아직 제안인 부분을 구분한다.

- 절제된 패션 잡지 톤을 밝은 에디토리얼로 정리했다. 소프트 화이트 `#FAF9F6`, 차콜 `#202B30`, 스톤 `#EAE7E0`, 중립 스튜디오 `#ECEDEA`를 바탕으로 버건디 `#9F3548`는 주요 행동과 선택에만 사용한다. 영문 디스플레이는 Bodoni Moda, 문장형 영문 헤드라인은 New York(시스템 세리프), 한글 디스플레이는 나눔명조, 기능 텍스트는 iOS 내장 Helvetica Neue에 한글 글리프용 Pretendard(OFL)를 캐스케이드로 묶어 사용한다. 상용 서체(Neue Haas Grotesk 등)는 번들하지 않는다. 레퍼런스의 브랜드 자산은 복제하지 않는다.
- 새 사용자는 남성/여성 기준을 직접 선택하고, 키·몸무게 입력 후 개인 마네킹을 확인·저장한다. 성별을 미리 선택하거나 날씨 권한·브랜드 소개를 먼저 요구하지 않는다. 완료 후 `오늘 / 피팅룸 / 내 체형`으로 이동한다. 브랜드 스토리는 설정에서 선택적으로 연다.
- 오늘 화면은 마네킹 뒤에 날씨별 하늘을 네 가지 판으로 시각화한다. 맑음은 푸른 하늘과 작은 해, 흐림은 해 없는 균일한 회색, 비는 **짙은 슬레이트 하늘에 제호와 러닝헤드가 종이색으로 반전되는 다크 커버**, 눈은 거의 흰 하늘과 드문드문 큰 눈송이다. 표지 캡션에 날씨 이름이 들어간다. 배경은 SwiftUI 기반의 정적 표현이며 동적 3D 기상 시뮬레이션이 아니다. WeatherKit 연결 전에는 샘플 날씨임을 표시하고, 개발 빌드의 설정 화면 맨 아래 "미리보기 날씨" 스위치(맑음/흐림/비/눈)로 네 판과 그에 따른 옷차림 추천을 비교할 수 있다(`-previewWeatherMood <clear|cloud|rain|snow>` 실행 인자로도 지정). 위치는 사용자 요청 시 연결하고, 실제 시간별 예보는 수신 후에만 표시한다.
- 외부 상품은 사이즈표를 수동 입력한다. URL은 원본 확인용 링크이며 상품 디자인·사진·치수를 자동 수집하지 않는다. 준비된 7개 기준 모델에 같은 종류의 치수를 적용하며 정확한 핏과 구매 사이즈를 보장하지 않는다.
- [FittingLibrary](weashion/weashion/Models/FittingLibrary.swift)와 [FittingRoom](weashion/weashion/Models/FittingRoom.swift)이 체형·상품·사이즈·선택 상태·최초 설정 초안을 앱의 Application Support 내부 `WEASHION/fitting-library.json`에 원자적으로 저장한다. 쓰기가 성공한 뒤 화면 상태와 저장 피드백을 갱신하며, 불러오기 실패 시 기존 파일을 덮어쓰지 않고 재시도를 안내한다.
- 기존 `UserDefaults`의 `editorialFittingSession` 또는 `primaryGarmentSizes`는 이전용으로만 읽고 원본 키를 남긴다. 저장된 기존 체형은 유지하고, 체형 정보가 없던 사용자만 최초 설정을 진행한다. 옛 사용자 지정 슬롯은 서로 다른 상품일 수 있으므로 각각 별도 상품으로 보존하며, 이름·URL이 같다고 합치지 않는다.
- 좁은 창은 세로 스크롤, 콘텐츠 폭 700pt 이상은 장면과 정보를 좌우 배치한다. 진입 화면과 상품 치수 화면도 같은 폭 기준을 사용하고, 접근성 글씨 크기에서는 세로 배치로 전환한다. 실기기에서 작은 화면·가로 회전·iPad 창 크기·키보드 및 큰 글씨의 실제 사용성을 확인해야 한다.
- 변경 화면과 기능 회귀는 사용자가 선택한 **시뮬레이터 범위**에서 검증한다. 과거 실기기 대상 iOS 컴파일(`generic/platform=iOS`·서명 제외)은 성공했지만 실제 설치·화면·성능·피팅 품질의 통과를 뜻하지 않는다. 사용자 승인 없이 실기기에 설치·실행하거나 실제 위치를 수집하지 않는다.
- 실제 날씨 연결은 위치 권한과 WeatherKit 사용이 가능한 앱 서명·개발자 설정이 필요하다. 0.15에서 프로젝트 entitlement를 연결하고 요청·실패·재시도·최신 응답 처리를 단위 검증했다. Apple Developer의 App ID capability·프로파일과 실기기 서버 수신은 확인하지 않았다. 미연결·최초 실패는 샘플, 갱신 실패는 마지막 수신값과 명시적 안내를 표시한다.

#### 이전 매거진 타이포그래피와 표지 구성 · 0.5

아래 0.5~0.9 구도·순서·수치는 당시 구현 이력이다. 현재 배치는 위 0.16과 [디자인 문서](docs/editorial-design-direction.md)의 최신 기준이 우선한다.

- 번들 서체를 도입했다. 영문 디스플레이(제호·숫자·사이즈 글자·폴리오)는 Bodoni Moda(가변, 광학 크기·굵기 축을 포인트 크기에 맞춰 적용), 문장형 영문 헤드라인은 New York 이탤릭(시스템 세리프), 한글 디스플레이는 나눔명조다. 기능 텍스트(본문·버튼·캡션·입력·오류)는 iOS 내장 Helvetica Neue를 1차 서체로 쓰고, 한글 글리프는 CoreText 캐스케이드로 Pretendard(가변 wght)가 그린다. 번들 서체는 모두 SIL Open Font License이며 원본 파일과 라이선스 전문을 [Resources/Fonts](weashion/weashion/Resources/Fonts)에 그대로 포함한다. 등록은 [EditorialFonts](weashion/weashion/Views/EditorialFonts.swift)가 실행 시 수행하고, 실패하면 시스템 서체로 대체한다. 기능 텍스트는 `editorialSans(_:weight:)`가 Dynamic Type 크기 범주를 UIFontMetrics로 환산해 시스템 텍스트 스타일과 같은 크기로 확대·축소한다.
- `오늘`은 표지에서 시작해 사용자 여정 순서로 내려간다: 표지(날씨 하늘 위 `WEASHION` 제호를 마네킹이 가리는 구도, 세로 러닝헤드, FIG. 캡션) → **날씨 지면**(표지 아래로 겹쳐 올라오는 기온 숫자, 오른쪽 좁은 열의 체감·강수·바람, 오른쪽 가장자리 밖으로 잘리는 하늘 사진판과 그 모서리를 덮는 굵은 고딕 선언문, 번호 크레딧 목록으로 들여쓴 옷차림 추천) → **현재 착장**(상품명 좌하단, 오른쪽 가장자리 밖으로 잘리는 버건디 사이즈 글자, 하나의 주요 CTA) → **잉크색 사이즈 지면**(세로로 세운 *Every size, a note.*, 사이즈 행, 보관함 링크 한 줄). 착장 계산 중에는 표지 캡션 위에 `M 사이즈 착장 계산 중`을 표시하고, 표시된 의류의 주의·실패는 CTA 아래 안내로 분리한다.
- `피팅룸`은 작은 영문 아이브로우와 굵은 고딕 선언문("옷은 바꾸고, 나의 기준은 그대로."), 상품명 행의 "상품 바꾸기 →" 링크, 48pt 레터폼 사이즈 선택(S·M·L)과 버건디 선택선, 왼쪽 가장자리까지 번지는 스튜디오 프레임과 그 오른쪽에 세로로 세운 *Fitting notes.*, 그 아래 하나의 얇은 도구막대(VIEW · 회전·확대·축소·초기화, 44pt)와 상태선, 큰 선택 사이즈 글자와 입력 CTA, Bodoni 측정 숫자 지면으로 구성한다. `내 체형`은 굵은 고딕 체형명, 92/56pt 키·몸무게 숫자, 오른쪽으로 번지는 초상 스튜디오와 왼쪽에 세운 *The body portrait.*, 오른쪽으로 들여쓴 Bodoni 수치 원장, 원장 끝의 "저장 체형 N개 →" 한 줄이다. 설정은 상단 헤더의 톱니 하나로 열고, 사용법 3단계와 면책 문단은 설정 화면에 둔다.
- 모션은 잡지형으로 바꿨다. 제목은 줄 단위로 자기 줄 상자 안에서 아래에서 올라오며 드러난다(720ms, 줄 간격 100ms, 감속 커브). 탭 전환은 이전 지면을 즉시 내리고 새 지면을 24pt 상승·페이드로 들여오며(500ms) 3D 장면을 겹치지 않는다. 표지 프레임은 1.04→1 배율·페이드로 자리 잡고(900ms), 섹션 구분선은 왼쪽에서 그어지며(500ms), 후속 지면은 스크롤 노출 시 24pt 상승·페이드로 등장한다. 선택선·배경 220ms, 저장·상태 160ms, 주요 CTA 0.99배·100ms 눌림은 유지한다. Reduce Motion·VoiceOver·접근성 글씨에서는 이동·배율·시차를 끄고 최종 상태를 즉시 보여준다.
- 안내는 카드·아이콘·측면 포인트 선이 없는 각주형이다. 얇은 가로 괘선 하나 아래 Bodoni 이탤릭 리드인(*Saved —*, *Attention —*, *Error —*, *In progress —*)이 문장으로 바로 이어지고 설명은 캡션으로 붙는다. 의미는 색이 아니라 리드인 단어가 전달하며 VoiceOver에는 한국어 톤 단어를 읽어 준다. 저장 안내는 스크롤 밖 상단에서 닫을 수 있고, 실제 쓰기 성공에만 성공 피드백 하나를 연결한다. 시트·편집 화면의 내비게이션 제목도 같은 서체를 쓴다. 최초 설정은 좁은 화면에서 기준 모델 선택을 먼저 보여주고 어두운 `You, first.` 지면을 그 아래에 둔다.
- **확인 범위:** 사용자 허가로 iOS 26.1 시뮬레이터에서 화면을 직접 렌더링해 표지·오늘·피팅룸·내 체형·최초 설정 스크린샷을 검토하며 레이아웃을 조정했다. 시뮬레이터에서 UI 테스트 3건(최초 설정→표지→피팅룸→내 체형 복원, 뷰어 조작·상태의 장면 밖 배치와 44pt 크기, 저장 안내 가시성)과 디자인 단위 테스트 15건(서체 등록·광학 크기 범위·라이선스 포함, 팔레트·대비, 모션 값, 상태 분류, 피드백 우선순위)이 통과했다. 실기기 대상 컴파일도 성공했다. 실기기의 실제 체감, 햅틱, 프레임 성능과 나머지 UI 테스트 실행은 확인하지 않았다.
- 신체 변형, 치수 변환, 드레이핑·충돌·소재·최신 요청 처리, 저장 형식과 ID는 변경하지 않았다.

#### 개인 체형과 상품 관리

- `내 체형 → 저장 체형`에서 생성·이름 변경·편집·복사·활성화·삭제를 제공한다. 추가 체형은 저장만 하거나 저장 후 바로 사용할 수 있다. 사용 중인 체형을 삭제하려면 먼저 다른 체형을 활성화한다. 성별 기준 변경은 공통 체형 편집에서 적용/취소하며 직접 입력한 치수를 기존 정책대로 보존한다.
- `오늘 / 피팅룸 → 상품 관리 → 상품 상세`에서 상품 정보, 사이즈별 치수 목록과 비교표를 보고 추가·수정·삭제·입혀보기를 한다. 같은 상품 안의 중복 사이즈명은 차단하며, 다른 상품은 같은 이름을 쓸 수 있다.
- 선택한 사이즈를 삭제하면 그 사이즈 선택만 해제하고, 선택 상품을 삭제하면 상품·사이즈 선택을 함께 해제한다. 체형과 다른 상품은 그대로 남는다. 재실행 시 삭제한 샘플을 자동으로 다시 만들지 않는다.
- 개인 마네킹은 완성된 3D 파일이 아니라 기준 모델과 치수·조절값을 저장해 복원한다. 계정·클라우드 동기화, 앱 삭제 후 복원 및 기기 간 이전은 제공하거나 보장하지 않는다.
- 모델이 사라진 이전 기록은 삭제하거나 다른 옷으로 대체하지 않고 표시 불가로 남긴다. 코튼 반팔 외에 6종의 종류별 치수·메시·착장 경로와 네 슬롯 동시 착장을 연결했다. 레이어링은 안쪽 패널을 고려하는 정적 근사이며 실제 원단의 겹쳐 입기·구매 적합성을 보증하지 않는다.

#### 옷장 데이터 모델과 다국어 · 0.7

- 상품에 **종류**(반팔 티셔츠·긴팔 상의·니트·아우터·긴바지·반바지·신발)와 **날씨 속성**(재질·두께·보온 1~5·비 대응·계절)을 기록한다. 재질·두께를 고르면 보온·비 대응·계절 제안값을 계산하고 사용자가 고친다([GarmentClimate](weashion/weashion/Models/GarmentClimate.swift)). 3D 착장을 지원하지 않는 종류는 치수 없이 사이즈명만 기록하며, 기존 저장 파일은 속성 없이도 그대로 읽는다.
- `오늘`의 옷차림 추천은 체감온도에서 목표 보온을 정하고 슬롯(상의·아우터·하의·신발)별로 **사용자 옷장**에서 고른다. 해당 종류의 옷이 없으면 일반 샘플을 보여주고 "보관함에 추가된 옷 없음 · 샘플 추천"이라고 표시한다. 추천은 아직 텍스트이며 마네킹이 추천 옷을 입지는 않는다.
- 한국어를 소스로 영어·일본어를 지원한다. 문자열은 [Localizable.xcstrings](weashion/weashion/Localizable.xcstrings)(579개 한국어 키 번역)와 [InfoPlist.xcstrings](weashion/weashion/InfoPlist.xcstrings)에 있고, SwiftUI 뷰 밖의 문자열은 [Localization.swift](weashion/weashion/Models/Localization.swift)의 `L("…")`로 읽는다. 설정의 **Language.** 세그먼트(시스템/한국어/English/日本語)로 앱 안에서 즉시 전환하며 선택은 재실행 후에도 유지된다. 새 문자열은 빌드 후 `weashion/scripts/sync-localizable-strings.sh`로 카탈로그에 동기화한 뒤 Xcode에서 번역한다.
- 확인 범위: 시뮬레이터에서 단위 테스트 20건(세 언어 표의 키·형식 지정자 일치, 고정 언어의 모델 문자열, 일본어 날씨 조건)과 UI 테스트 7건(앱 내 언어 전환·재실행 유지 포함)이 통과했고 실기기 컴파일이 성공했다. 번역은 수동 작업이라 전문 감수가 필요하며, 상세 현황과 남은 과제는 [2026-10-27 기록](docs/progress-2026-10-27.md)에 있다.

#### 연결되는 지면과 버건디 포인트 · 0.8

- 상품 추가는 **종류 → 재질·두께 → 날씨 제안** 순서로 필요한 정보를 펼친다. 보온·비 대응·계절은 제안 요약 아래에서 조정하고 URL·메모·기준 모델은 선택 정보로 묶었다. 기존 상품 수정은 재질과 날씨 정보를 처음부터 보여준다. 재질을 선택하지 않고 저장할 때는 코튼·보통 두께의 기본 기준임을 명시한다.
- 날씨 지면은 기온·측정값, 하늘판·선언문, 옷차림을 짧은 시간차로 연결한다. 사이즈를 바꾸면 직전 선택과 총장·어깨너비·가슴단면의 입력 차이를 부호 있는 cm로 표시하며, 실제 착장 결과와 혼동하지 않는다.
- 오늘 ↔ 피팅룸은 보이는 마네킹 장면의 **정지 이미지**를 다음 장면 위치로 연결한다. 두 3D 렌더러를 겹쳐 돌리지 않고 회전·확대·초점을 유지한다. 화면 밖 전환과 동작 줄이기에서는 기본 전환을 사용한다.
- 표지 제호와 마네킹 구도는 유지한다. 버건디는 주요 CTA·선택 사이즈·작은 번호·강수 숫자·세로 제목에 조금씩 더 쓰고, 본문과 대부분의 배경은 기존 잉크·종이색을 유지한다. 추가 문구도 한국어·영어·일본어로 제공한다.
- 확인 범위: 시뮬레이터 빌드, 관련 단위 테스트 22건, 옷 추가 단계의 UI 테스트 1건이 통과했다. 회전·확대 유지와 사이즈 차이 표시는 별도 여정 테스트의 해당 구간에서 확인했고, 옷 추가 단계의 초기 실패는 식별자와 하단 저장 영역의 겹침을 수정한 뒤 독립 테스트로 확인했다. 실기기 모션·성능, 전체 UI 회귀, 기존 입력 필드 포커스 문제의 해결을 의미하지 않는다.

#### 인터랙션과 모션

- **0.16에서 승인된 디자인·모션을 개편하고 0.13의 전환 준비 구조는 유지했다.** 위 0.8의 정지 이미지 연결과 지면 전체 전환은 제거한 상태다. 장면 캡처·좌표 추적 없이 모든 메인 탭에서 헤더의 440ms 버건디 스윕과 개별 2D 제목 진입을 사용한다. 기능 실행은 애니메이션 완료를 기다리지 않는다.
- 오늘·피팅룸은 같은 데이터의 준비된 신체·착장·네이티브 geometry와 회전·확대·초점을 재사용한다. 내 체형은 별도 준비 상태·시점을 유지하며 주 메뉴의 네이티브 렌더 표면 하나를 공유한다. 신체 변형·법선·충돌 데이터 준비는 기존 actor에서 수행하고 비동기 메시 생성 후 부착한다. 최초 네이티브 geometry 생성·GPU 준비까지 모두 백그라운드화한 것은 아니다.
- 메뉴 선택은 즉시 반응하고 **실제 준비가 120ms 이상 걸릴 때만** 메뉴 위 작은 종이색 띠·다음 지면 이름·버건디 선을 표시한다. 준비 중 이전 지면은 조작하지 못하게 하되 주 메뉴의 연속 입력은 계속 받으며 최신 요청만 반영한다. 준비되면 즉시 예고를 제거하고 새 지면을 표시한다. 빠른 전환·의류 계산 완료·보조 선의 주기를 기다리는 인위적 지연은 없다. 동작 줄이기에서는 정적으로 표시하고 준비 실패는 명시적으로 알린다.
- 버튼·선택은 100ms 명도 변화와 0.97배 눌림을 사용한다. 사이즈·탭 선택면·상세 펼침은 약 220ms, 큰 사이즈 글자의 상하 교체는 280ms다. 선택 햅틱과 실제 저장 성공 피드백은 구분한다. 저장 안내는 상단의 작은 체크·제목·실제 변경 문구와 44pt 닫기로 정리하며 자동으로 숨기지 않는다.
- 표지 제호는 96pt(넓은 화면 164pt) 마스크 진입·800ms, 캡션은 160ms 시간차의 측면 진입을 사용한다. 주요 제목은 줄별 1.15em 마스크 리빌·640ms·80ms 간격이다. 탭 재진입 시 제목을 다시 연출하지만 입력값 갱신에는 재생하지 않는다. 제목은 VoiceOver·접근성 글씨·동작 줄이기에서 정적이다.
- 날씨 숫자·측정 행·하늘판·선언문 각 줄·옷차림, 체형 치수, 사이즈 노트와 보관함 도식은 **각 요소가 실제로 약 18% 보일 때** 한 번씩 리빌한다. 지면 일부만 보여도 아래 모든 모션이 먼저 끝나던 방식을 없앴다. 배경 시차는 표지 ±10pt, 하늘판 ±16pt이며 `.visualEffect`로 국소 처리한다. 스크롤 위치를 큰 화면 상태에 매 프레임 쓰거나 마네킹·메시·카메라를 장식 모션으로 바꾸지 않는다.
- 사이즈·기존 의류 물성·체형 계산 중에는 이전 의류를 숨기고 준비 상태를 표시한다. 날씨 추천용 재질·두께 메타데이터는 3D 재질 표현이나 재계산에 연결하지 않는다. 새 결과가 준비되면 교체하며, 과도한 신축·겹침 실패는 기존 경고를 유지한다. 사이즈 변경으로 마네킹의 몸·카메라를 재설정하거나 옷을 시각적으로 부풀리는 모션을 추가하지 않는다.
- 상품 치수 편집은 좁은 화면에서 시스템 시트, 넓은 화면에서 inspector 패널을 사용한다. 측면 패널에서는 본문의 한 마네킹에 유효한 입력을 임시 반영하며, 적용 전에는 저장하지 않는다. 취소하면 기존 치수로 돌아간다. 잘못된 입력은 적용 버튼을 비활성화하고 해당 항목으로 이동하는 안내를 제공한다.
- 시스템 `동작 줄이기`가 켜져 있으면 사용자 정의 모션의 이동·시차·보간 애니메이션을 끈다. 시트·패널 전환과 진행 표시는 시스템 동작을 따른다. 버튼·선택·오류 피드백은 정적으로 유지한다.
- 0.9 검증: 시뮬레이터 빌드와 관련 단위 테스트 23건·메인 여정 UI 테스트 1건이 통과했다. 탭 변경, 회전·확대 유지, 단일 렌더 표면, 연속 사이즈 선택의 최신 입력 차이를 확인했다. 실기기 프레임·햅틱·iPad·전체 UI 회귀는 별도 확인 대상이며 60fps나 무지연을 보장하지 않는다.
- 0.13 집중 검증: 관련 단위 28건·메인 UI 여정 1건 통과. 내부 카운터로 동일 요청 20회 재사용의 추가 신체·착장 계산·네이티브 geometry 생성 0회와 주 메뉴 표면 생성 1회를 확인했다. 빠른 준비·지연·최신 요청·취소·실패도 단위 검증했고 녹화·이미지에서 초기 표지 착장과 기존 지면을 확인했다. 실기기 탭 지연·프레임·메모리·발열·햅틱과 메모리 경고 해제 정책은 남아 있다. 상세는 [디자인 문서](docs/editorial-design-direction.md)와 [작업 현황](docs/progress-2026-10-27.md)에 기록했다.
- 0.15 후속 안정화: 메모리 경고 때 현재 장면을 보존하고 비활성 상태·분리된 네이티브 참조·계산 캐시를 해제한다. 입력칸 여백 터치의 포커스를 보강하고 좁은 화면 sheet/넓은 화면 inspector를 구분했다. 치수 도식 번호와 항목은 44pt 터치 영역·접근성 선택 상태로 연결하며 저장값·피팅 계산은 바꾸지 않는다. 고유 단위 55건·핵심 UI 여정 4건이 집중 실행에서 통과했고 최종 이미지를 확인했다. 실기기 사용은 사용자가 선택하지 않아 실제 성능·날씨 수신은 미검증이다.

## 1. 프로젝트 개요

이하 내용은 제품 기획과 목표 구조를 포함한다. 모든 기능의 구현 완료를 의미하지 않으며, 현재 구현 및 확인 범위는 문서 상단과 날짜별 진행 기록을 기준으로 한다.

### 1.1 프로젝트명

WEASHION

### 1.2 프로젝트명 의미

WEASHION은 **Weather + Fashion**에서 출발한 이름이다. 현재 중심 경험은 개인 마네킹에 상품 치수를 적용해 착장을 비교하는 것이며, 날씨는 외출 환경을 고려하는 보조 정보다.

### 1.3 프로젝트 목적

WEASHION은 상품 사이즈표만으로 상상하기 어려운 착장 차이를 개인 체형 위에서 비교하도록 돕는다.

- 신체 치수와 세부 조절로 개인 마네킹을 설정한다.
- 비교 중에는 몸을 유지하고 상품 사이즈와 의상 치수만 바꾼다.
- 동일 체형의 A/B 착장과 입력 치수·근사 여유·변형 경고를 함께 확인한다.
- 날씨와 Outfit 추천은 의상 선택을 보완하는 기능으로 연결한다.

현재 결과는 시각적 상상을 돕는 근사 미리보기다. 상품 실물·원단·실착과 대조하기 전에는 구매 사이즈나 실제 착용 가능 여부를 확정하지 않는다.

## 2. 핵심 컨셉

> 고정된 내 개인용 마네킹에 쇼핑몰에서 본 옷의 사이즈를 가상 피팅해서 내가 입으면 어떨지 상상해본다.

기본적인 서비스 흐름은 다음과 같다.

```text
사용자 신체 데이터 입력
→ 개인 마네킹과 기준 체형 설정
→ 준비된 의상의 상품 사이즈 선택 또는 실측 입력
→ 몸은 유지하고 옷의 크기 변경
→ 착장 및 정적 겹침 보정
→ 동일 체형의 A/B 실루엣·치수·여유·경고 비교
```

현재는 번들에 준비된 의상을 사용한다. 쇼핑몰에서 상품이나 3D 모델을 자동 수집하는 기능까지 구현한 것은 아니다.

## 3. 서비스의 핵심 구성 요소

핵심은 개인 마네킹과 상품 치수 기반 비교이며, 날씨와 추천·연출은 보조 또는 확장 요소다.

1. **Personal Avatar**
2. **Garment Size & Fit Comparison**
3. **Weather Analysis**
4. **Fashion Recommendation**
5. **Weather Visualization**

### 3.1 Personal Avatar

사용자의 신체 데이터를 기반으로 생성되는 개인화된 3D 캐릭터이다.

사용자의 사진을 이용하여 신체를 스캔하지 않는다. 사용자가 직접 입력한 수치 데이터를 기반으로 기본적인 신체 형태를 생성하고, 이후 사용자가 직접 캐릭터의 세부적인 신체 형태를 조절할 수 있도록 한다.

### 3.2 Garment Size & Fit Comparison

의상 자체의 치수를 먼저 변경하고 고정된 체형에 착장한다. 각 패널의 사이즈·치수는 독립적으로 조절하며, 입력 기준과 충돌 보정 후의 근사 결과를 분리한다. 현재 정적 보정과 미확인 원단 물성의 한계를 함께 표시한다.

### 3.3 Weather Analysis

사용자의 현재 위치를 기반으로 해당 지역의 날씨 정보를 가져온다. 현재 기온뿐 아니라 다음과 같은 환경 정보를 함께 활용한다.

- 현재 기온
- 최고 기온
- 최저 기온
- 체감온도
- 강수확률
- 강수량
- 습도
- 풍속
- 풍향
- 날씨 상태
- 일출 및 일몰

### 3.4 Fashion Recommendation

날씨 데이터를 기반으로 사용자가 외출할 때 적합한 의상을 결정한다. 기온, 체감온도, 강수확률, 강수량, 습도, 풍속, 시간대를 함께 고려하여 상의, 하의, 아우터, 신발 및 액세서리로 하나의 Outfit을 구성한다.

### 3.5 Weather Visualization

날씨를 3D 환경과 애니메이션으로 표현하는 확장 계획이다. 예를 들어 비·눈 환경을 구성할 수 있으나 현재 피팅의 필수 흐름이나 구현 완료 기능으로 보지 않는다.

## 5. 개인화 3D 캐릭터

### 5.1 기본 캐릭터 생성

사전에 제작된 기본 Human 3D Model에 사용자 데이터를 적용하여 개인화된 캐릭터를 생성한다.

```text
Base Human Model
→ 사용자 신체 데이터
→ Body Parameters
→ Mesh Deformation
→ Personalized Avatar
```

### 5.2 신체 데이터와 캐릭터의 관계

예를 들어 다음과 같은 사용자가 있다고 가정한다.

| 항목 | 값 |
| --- | --- |
| 키 | 175cm |
| 몸무게 | 75kg |
| 어깨 너비 | 46cm |
| 가슴 둘레 | 100cm |
| 허리 둘레 | 82cm |
| 다리 길이 | 82cm |

이 데이터를 Body Parameter로 변환하여 각 신체 부위에 적용한다. 목표는 단순히 키만 다른 캐릭터가 아니라 사용자의 전체적인 신체 비율을 반영하는 것이다.

## 8. 위치 기반 날씨 시스템

iOS에서는 Core Location으로 사용자의 위치를 확인하고 WeatherKit으로 해당 위치의 날씨를 가져온다.

- 위치는 사용자가 연결·새로고침을 눌렀을 때만 요청한다. 권한 거부·회수, 유효하지 않은 위치와 15초 위치 수신 제한을 처리하고 피팅 기능은 계속 사용할 수 있다.
- 새 날씨 요청·권한 회수 뒤에 도착한 오래된 응답이나 오류는 현재 결과를 덮어쓰지 않는다. 현재 날씨·시간별 예보·Apple Weather 출처는 함께 수신된 결과로 반영한다.
- [weashion.entitlements](weashion/weashion/weashion.entitlements)의 `com.apple.developer.weatherkit`를 Debug/Release 서명 설정에 연결했다. 실제 수신을 위해 Apple Developer에서 **me.weashion App ID의 WeatherKit capability**를 활성화하고 해당 권한이 포함된 provisioning profile로 서명해야 한다. 이 저장소 변경만으로 계정의 capability가 활성화되지는 않는다.

```text
Core Location
→ 사용자 위치
→ 지역 좌표
→ WeatherKit
→ Weather Data
```

## 14. 메인 화면

중심은 개인 마네킹과 의상이다. `마네킹 추가`로 동일 체형의 A/B를 좌우 비교하며, 패널별 의상 선택·치수 편집·회전·확대와 계산 지표를 사용한다. 체형 편집과 의상 편집을 분리해 옷에 맞춰 몸이 바뀌지 않게 한다.

날씨 정보와 추천은 보조 정보다. 화면의 주된 판독 대상은 의상 실루엣, 상품 입력 치수, 가슴 여유와 변형 경고이며 날씨 배경 연출이 아니다.

## 15. 사용자의 주요 행동

1. 자신의 신체 정보 입력
2. 개인 마네킹의 체형 조절
3. 비교할 체형 유지
4. 준비된 의상과 상품 사이즈 선택
5. 필요한 상품 치수 직접 입력
6. 동일 체형의 A/B 착장 비교
7. 입력 치수·착장 후 근사 치수·여유·경고 확인

날씨와 추천 확인은 이 과정의 보조 행동이다. 상품 자동 등록이나 Outfit 비교 이력 저장은 향후 확장 범위다.


```text

```

## 18. 개발 단계

아래는 현재 컨셉의 작업 순서이며 단계 전체의 완료를 의미하지 않는다.

### Phase 1. 개인 마네킹

신체 치수·세부 조절과 공통 비교 체형을 마련한다. 현재 남녀 메시, 부위 조절, 남성 시각적 체형 프리셋을 연결했으며 정확한 인체 복원과는 구분한다.

### Phase 2. 상품 치수와 비교

한 의상 디자인의 치수 의미를 명확히 하고 같은 체형에서 사이즈를 비교한다. 현재 그레이 S·M·L 샘플과 상품별 사이즈·직접 입력을 지원하며, A/B 패널 대신 활성 체형 하나에서 선택을 전환한다.

### Phase 3. 피팅 품질과 실물 대조

겨드랑이·연결부의 큰 변형을 줄이고 실물 의상·착용 사진·원단 정보와 대조한다. 계산 치수 일치, 충돌 샘플 결과, 실제 착용 적합성을 서로 다른 기준으로 확인한다. 실기기 품질·응답·발열 확인도 남아 있다.

### Phase 4. 의상 및 보조 경험 확장

치수 기준과 품질이 마련된 의상부터 종류를 늘린다. 상품 등록, 옷장, 여러 겹 착장과 날씨·Outfit 연계를 순차적으로 검토한다. 날씨 환경·애니메이션은 비교 경험을 방해하지 않는 후속 범위다.

## 19. 초기 MVP

핵심 흐름의 범위는 다음과 같다. 현재 연결된 기능이 실물·실기기 품질까지 확인됐다는 의미는 아니다.

1. 신체 치수 입력과 개인 마네킹 조절
2. 같은 몸을 유지하는 의상 편집
3. 준비된 티셔츠 한 디자인의 S·M·L
4. 기본 4개 치수와 선택 3개 치수 입력
5. 동일 체형 A/B 착장 비교
6. 상품 입력 치수와 착장 후 근사 지표 구분
7. 원단 미확인·큰 표면 변형·잔여 겹침 경고

핵심 사용자 흐름은 다음과 같다.

```text
내 신체 정보를 입력한다.
↓
내 개인 마네킹을 조절한다.
↓
몸을 유지하고 상품 사이즈와 치수를 선택한다.
↓
같은 몸에 서로 다른 사이즈를 입혀 비교한다.
↓
실루엣·입력값·근사 치수와 경고를 함께 보고 상상한다.
```

상품 자동 수집·임의 모델 자동 피팅·구매 사이즈 판정·여러 겹 착장·날씨 애니메이션은 핵심 MVP의 완료 조건에 포함하지 않는다.

## 20. 장기적인 확장 기능

### 개인 옷장

사용자가 실제로 보유한 의상을 등록하고, 날씨에 맞는 보유 의상 조합을 추천한다.

```text
My Wardrobe
↓
사용자 보유 의상
↓
Weather Analysis
↓
Available Outfit
↓

```

### 착장·사이즈 비교 확장

현재는 저장한 체형 중 하나를 활성화하고 한 마네킹에서 상품·사이즈를 전환한다. `새 체형 만들기`는 별도 체형 기록을 추가하는 동작이며 두 마네킹을 동시에 배치하지 않는다. 지원되는 상의·바지·신발 모델에 같은 종류의 샘플 또는 상품별 직접 입력 치수를 적용해 비교한다. 비교 결과는 화면상 착장과 계산된 핏 지표이며, 실물 원단의 신축률·착용감이나 브랜드 사이즈 정확도를 판정하지 않는다.

```text
같은 체형 + 착장 A                 같은 체형 + 착장 B
         좌우로 나란히 비교: 치수·실루엣·계산 지표
```

사용자 옷장에 있는 여러 상품과 Outfit 조합을 불러와 비교하는 기능은 향후 확장 개념이며, 현재 두 패널의 샘플 선택 기능과 구분한다.

### 상황별 추천

날씨뿐 아니라 사용 목적을 고려한다.

- 학교
- 출근
- 데이트
- 운동
- 여행
- 산책
- 공식적인 자리
- 캐주얼한 자리

### 시간대별 추천

하루 동안의 기온 변화를 고려하여 아침, 낮, 저녁, 밤의 복장 변화를 반영한다. 예를 들어 아침에는 외투가 필요하지만 낮에는 더울 수 있는 경우 이를 함께 안내한다.

## 21. 최종 서비스 정의

WEASHION은 신체 치수와 세부 조절로 만든 개인 마네킹에 상품의 사이즈·실측 치수를 적용하고, 같은 체형에서 서로 다른 착장을 비교하는 가상 피팅 앱이다. 옷에 맞춰 몸을 바꾸지 않으며, 상품 기준 치수와 착장 후 근사 결과를 구분한다.

현재는 준비된 한 의상의 정적 미리보기이며 실제 원단·제품·실착과의 일치는 확인하지 않았다. 날씨와 Outfit 추천은 외출 환경과 의상 선택을 보완하고, 정확한 구매 판정을 대신하지 않는다.

> **고정된 내 개인 마네킹에 상품 치수를 적용해, 내가 입으면 어떨지 비교하고 상상하는 서비스**
