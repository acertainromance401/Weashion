- 에셋 이력 기준일: 2026-10-07
- 범위: 현재 신체·의류 구현의 정리, 외부 남녀 모델 경량화, Swift/RealityKit 표시 경로 전환
- 상태: 코드와 앱용 에셋 연결 완료. 앱 전체 빌드 및 새 모델의 실기기 착장은 미확인.

> 이 문서는 2026-10-07 에셋 이력과 아래의 2026-10-26 화면 업데이트를 함께 담는다. 과거 메시 수·파란 샘플·확인 상태는 당시 기록으로 보존한다. 최신 제품 컨셉, 최종 메시 수, 그레이 S·M·L 치수와 확인 범위는 [2026-10-26 종합 기록](progress-2026-10-26.md)을 기준으로 한다.

## 2026-10-26 메인 화면 착장 비교 업데이트

이 절은 현재 워크트리의 화면·의류 피팅 구현을 기준으로 한 최신 기능 요약이다. 아래 에셋 수치와 작업 기록은 각 절에 적힌 당시 상태를 설명하며, 이후 변경된 화면 동작과 혼동하지 않는다.

### 제품 경험 및 구현 상태

- 메인 화면에서 `마네킹 추가`를 누르면 같은 `bodyData`와 마네킹 베이스를 사용하는 A/B 마네킹을 좌우로 표시한다. 두 마네킹은 별도의 RealityKit 장면과 카메라/회전/확대 상태를 갖는다.
- 두 패널의 의류 선택과 치수 상태는 분리되어 있다. 현재 샘플 카탈로그는 같은 티셔츠의 S/M/L이며, 기본 패널은 첫 번째와 두 번째 카탈로그 항목으로 시작한다. 따라서 기본 비교는 S 대 M이다.
- compact 화면에서는 사이즈 선택기를 메뉴형으로, 장면 조작 버튼을 작은 크기로 표시한다. 좌우 배치는 유지한다.
- 메시 의류는 `의상 치수` 화면에서 S/M/L 또는 직접 입력으로 조절할 수 있다. 총장·어깨너비·가슴단면·소매길이와 선택적 밑단단면·소매부리단면·암홀을 입력하며, 각 패널의 치수 편집은 독립적이다. 이 편집 UI는 현재 mesh 형식 의류에만 활성화된다.
- 착장 장면에는 의류 치수와 계산된 가슴 여유·어깨 차이·근사 착장 가슴둘레·수직 총장·최대 표면 늘어남을 표시한다. 계산 결과에 따라 겹침, 가슴 치수 부족, 큰 표면 변형 등의 안내도 제공한다.
- 이는 모델 기반의 시각 미리보기와 계산 지표다. 소재의 실제 신축률은 확인되지 않았고, 실물 제품 핏이나 착용 가능 여부·브랜드 사이즈 정확도를 검증한 결과가 아니다.

### 검증 범위

좌우 분할 UI를 추가한 이전 변경 시점에는 iOS Simulator 빌드가 성공했다. 이후 치수 입력 및 핏 요약 기능을 포함한 현재 워크트리 전체의 빌드·테스트 결과는 이 업데이트에서 확인하지 않았다. 앞선 테스트 실행은 완료 결과를 받지 못했으며, 실제 iPhone에서의 화면 잘림 여부도 확인되지 않았다. 따라서 문서의 기능 설명은 현재 소스 구조에 대한 것이며, 최신 전체 변경의 기기 검증 완료를 뜻하지 않는다.

제품 컨셉에서는 두 착장의 나란한 시각 비교를 현재 경험으로 다루되, 여러 상품·사용자 옷장·다양한 Outfit 조합 비교는 별도의 향후 확장으로 구분한다. 핏 결과를 실물 적합성 보증으로 표현하지 않는다.

## 2. 진행 순서

1. 사람 모델의 편집용 원본과 앱용 포맷을 구분하고 Blender 원본 사용을 결정했다.
2. 제공된 남녀 Blender 파일을 자동 스크립트 실행을 차단한 상태로 읽어 메시 구조를 확인했다.
3. 원본을 덮어쓰지 않고 Blender Decimate의 Collapse 방식으로 각각 40,000삼각형 사본을 만들었다.
4. 저장된 사본을 다시 열어 정점·면 수를 확인하고 원본 파일 해시가 변하지 않았음을 확인했다.
5. 원본과 경량화 결과의 정면·측면·후면을 동일한 렌더 조건에서 비교했다.
6. 앱에서 정점을 직접 변형할 수 있도록 미터 단위 Y-up JSON으로 내보냈다.
7. Swift 에셋 로딩·체형 보정·의류 단면 및 충돌 밴드 생성 경로를 추가했다.
8. 기존 머리·귀·손발 세부 형상을 조립하던 표시 경로를 제거하고 새 전신 메시를 연결했다.
9. 단면 둘레 과대 계산과 겨드랑이 변형을 실제 계산·렌더 결과를 기준으로 수정했다.
10. 전체 iOS 소스 타입 검사와 실제 Swift 변형 코드 실행을 확인했다. 기기 설치는 하지 않았다.

## 3. 에셋 조사와 경량화 결과

### 3.1 원본 구조

두 파일 모두 메시 오브젝트 1개, 삼각형 면, 재질 1개로 구성되어 있었다. 리깅/Armature, 애니메이션 Action, Shape Key, 정점 그룹, UV 맵, 이미지 텍스처와 Modifier는 없었다.

원본 높이는 약 1.9m다. 여성은 팔을 벌린 자세, 남성은 팔을 내린 자세이며 속옷 형상은 별도 의류가 아니라 몸과 합쳐진 메시다. 이번 작업에서는 자세나 속옷 형상을 별도로 제거하지 않았다.

## 4. 새 신체 데이터 형식

### 4.1 좌표와 필드

Blender 좌표를 `(x, z, -y)`로 회전하고 발바닥 높이를 0으로 맞춘 뒤 몸통 기준으로 깊이 중심을 보정했다. 삼각형 인덱스의 순서는 유지한다.

| 필드 | 의미 |
| --- | --- |
| `version` | 현재 데이터 형식 버전 1 |
| `vertices` | 미터 단위 `[x, y, z]` 정점 배열 |
| `indices` | 삼각형당 3개의 정점 인덱스 |
| `regions` | 삼각형별 신체 영역 번호 |
| `armWeights` | 정점별 팔 변형 영향도, 0~1 |
| `armCenters` | 기준 모델 오른팔의 높이별 중심선 |
| `legCenters` | 기준 모델 오른다리의 높이별 중심선 |
| `landmarks` | 기준 신장, 인심, 엉덩이·허리·가슴·어깨 높이 및 어깨너비 |

영역 번호는 `0` 몸통, `1` 오른팔, `2` 왼팔, `3` 오른다리, `4` 왼다리다. 왼쪽 변형은 오른쪽 중심선을 좌우 반전해 사용하므로 비대칭 해부학을 정확히 복원하는 구조는 아니다.

### 4.2 기준점

| 기준 | 여성 | 남성 |
| --- | ---: | ---: |
| 인심 높이 / 원본 신장 | 0.465 | 0.448 |
| 엉덩이 높이 / 원본 신장 | 0.535 | 0.535 |
| 허리 높이 / 원본 신장 | 0.625 | 0.625 |
| 가슴 높이 / 원본 신장 | 0.735 | 0.735 |
| 어깨 높이 / 원본 신장 | 0.805 | 0.805 |
| 기준 어깨너비 | 0.410m | 0.490m |

기준점은 이 두 에셋을 연결하기 위한 근사값이다. 전문 신체 측정으로 검증한 값이나 다른 모델에 그대로 적용할 수 있는 자동 랜드마크 검출 결과가 아니다.

원본 팔 경계는 여성 `0.135 + max(어깨높이 - y, 0) * 0.25`, 남성 `0.190 + max(어깨높이 - y, 0) * 0.045`를 기준으로 정하고 3cm 범위에서 부드럽게 전환했다. 목 위에서는 팔 영향을 줄인다. 앱 로더에서 메시 이웃을 따라 팔 가중치를 추가로 12회 평활화한다.

### 5.2 실행 흐름

```text
UserBody + 남녀 선택
  -> MannequinMesh의 번들 JSON 로딩 및 캐시
  -> 키/인심/몸통/팔다리 변형
  -> 같은 정점에서 단면과 충돌 밴드 생성
  -> BodySurfaceMesh -> RealityKit 전신 메시
  -> 의류 프로필/충돌 밴드 -> GarmentController -> GarmentDraper
```

- 로더는 버전, 배열 길이, 정점 인덱스 범위, 유한값, 가중치 범위와 기준 높이·중심선의 순서를 검사한다.
- 높이는 발바닥·인심·어깨·정수리 기준으로 변환한다. 지나치게 긴 인심은 목표 어깨높이보다 최소 15cm 아래로 제한한다.
- 몸통 폭·깊이를 기준 단면에 맞춰 보정하고 가슴·허리·엉덩이를 최대 3회 재측정한다. 모든 입력에서 정밀 치수 수렴을 보장하는 제약 해결기는 아니다.
- 몸무게에 따른 굵기 계수는 70kg을 기준으로 제한된 범위에서 반영하며, 팔다리 굵기 입력과 곱해진다. 체중으로 전체 체적이나 지방 분포를 복원하지 않는다.
- 발 부근의 다리 굵기 영향은 줄여 발 전체가 다리 굵기와 같은 비율로 부풀지 않게 한다.
- 팔 간격은 허리·엉덩이 단면의 여유를 기준으로 보정하고 어깨에 가까워질수록 보정량을 줄인다. 가슴 높이에서 강제로 틈을 만들지 않는다.
- 치수·남녀 선택이 바뀔 때 계산한다. 원본에 없는 관절 리그를 추가하거나 매 프레임 스키닝하는 구조가 아니다.

### 5.3 제거한 코드와 남긴 코드

별도 머리 표면, 귀, 손가락·엄지·발가락 장식, 손발톱을 만드는 표시 코드를 제거했다. 이 부분은 전신 에셋에 이미 포함되어 중복 생성할 필요가 없다.

기존 [BodySkeleton.swift](../weashion/weashion/Models/BodySkeleton.swift)와 생성형 몸체의 대부분은 삭제하지 않았다. 기존 유틸리티와 테스트가 의존하고 있어 현재 표시 경로에서 분리한 상태다. 새 에셋이 기존 23관절 리그나 dual-quaternion 스키닝으로 움직인다고 설명해서는 안 된다.

## 6. 의류 구현과 연결 상태

당시 의류 경로는 [GarmentDefinition.swift](../weashion/weashion/Models/GarmentDefinition.swift), 절차적 티셔츠 생성기(현재 삭제됨), [GarmentFit.swift](../weashion/weashion/Models/GarmentFit.swift), [GarmentDraper.swift](../weashion/weashion/Services/GarmentDraper.swift), [GarmentRenderer.swift](../weashion/weashion/Views/GarmentRenderer.swift)로 나뉘었다.

- 번들 카탈로그에서 샘플을 선택하며, 치수 기반 티셔츠 또는 준비된 의류 JSON을 사용한다.
- 신체의 단면과 의류의 기준 단면 차이를 이용해 몸통·어깨·소매를 배치한다.
- [ClothPhysics 패키지](../weashion/Packages/ClothPhysics/README.md)는 Swift에서 사용하는 C API와 Bullet 충돌 관련 코드를 포함한다.
- 현재 착장 계산은 볼록 충돌체를 이용한 정적 겹침 보정이다. 완전한 중력 기반 천, 주름, 봉제, 자기충돌 시뮬레이션으로 표현하지 않는다.
- 새 몸의 표시 정점과 충돌 밴드는 같은 변형 결과를 사용한다. 시각용으로 가져온 사람과 숨은 기존 생성형 몸체를 따로 두지 않는다.
- 신체 로딩 실패 시 이전 의류가 새 몸에 맞는 결과처럼 남지 않도록 표시를 정리한다.

새 에셋의 팔 자세와 표면은 기존 생성형 모델과 다르다. 이전 모델에서 확인한 티셔츠 95·110 착장 결과를 새 에셋의 착장 품질 근거로 재사용하지 않는다.

## 7. 구현 중 확인하고 수정한 문제

### 단면 둘레 과대 계산

불규칙한 삼각형과 팔 주변의 분리된 점을 단순 각도순으로 연결하면 단면이 여러 번 왕복해 여성 가슴둘레가 약 2.5m로 계산되는 문제가 있었다. 외부 에셋 경로에 볼록 외곽선 기반 단면을 사용하고 팔·몸통 분류 경계를 조정했다.

볼록 단면은 안쪽으로 파인 표면을 메우는 근사다. 계산 안정성과 의류 여유 판단에 유리하지만 실제 피부를 따라 잰 둘레와 동일하지 않다.

### 겨드랑이의 부풀음과 꺾임

초기 경계 분류와 가슴 높이의 팔 간격 보정이 겨드랑이 연결부까지 당겨 큰 변형을 만들었다. 다음을 적용했다.

- 모델별 팔·몸통 경계 재설정.
- 메시 인접 관계를 이용한 팔 변형 가중치 평활화.
- 팔 간격 보정 범위를 허리·엉덩이로 제한.
- 실제 Swift 계산 결과를 Blender로 다시 렌더해 앞·옆·뒤 비교.

최종 기본 체형에서 초기의 과도한 변형이 줄어든 것을 확인했다. 극단적인 모든 체형이나 다양한 의류의 외형을 검증한 것은 아니다.

## 8. 확인 결과와 해석 범위

### 8.2 렌더 비교

- 원본과 경량화 사본을 동일한 조건으로 정면·측면·후면 비교했다.
- 최종 Swift 위치 데이터를 Blender 메시로 만들어 같은 세 방향에서 확인했다.
- 원본의 약 190cm 체형과 기본 입력의 175cm 보정 체형은 크기와 둘레가 달라 보이는 것이 정상이다.
- 이 비교는 Blender 렌더이며 iPhone의 RealityKit 화면 캡처가 아니다.

### 8.3 타입 검사와 빌드 제한

전체 앱 Swift 파일을 실제 iOS 26.1 SDK, Swift 5 모드, MainActor 기본 격리 및 프로젝트의 관련 upcoming feature 설정으로 직접 타입 검사했고 통과했다. 기존 ClothPhysics C 헤더를 노출하는 임시 모듈 맵을 사용했다.

실기기용 `xcodebuild`는 소스 컴파일 전에 대상 선택 단계에서 실패했다. 오류는 iOS 26.1 플랫폼이 설치되지 않았다고 안내했지만, 같은 Xcode의 `-showsdks`에는 iOS 26.1 SDK가 존재했다. SDK 파일 유무만으로 해결 원인을 단정하지 않았다.

따라서 다음은 완료했다고 주장하지 않는다.

- 앱 링크, 서명 및 최종 앱 번들 확인.
- Xcode를 통한 실기기 빌드·설치·실행.
- 새 남녀 모델에서 의류 착장 계산 완료 및 관통 검사.
- 모든 슬라이더 조합, 극단 체형, 성능·메모리·발열 확인.
- 기존 단위/UI 테스트 전체 재실행 및 새 에셋 전용 회귀 테스트.

## 9. 편집 및 재내보내기 시 주의

- 원본은 복구 기준으로 보존하고 경량화 사본 또는 별도 작업 사본에서 편집한다.
- Blender 사본을 바꾸어도 앱 JSON은 자동으로 갱신되지 않는다. 미터·Y-up 변환과 영역·가중치·기준점 데이터를 함께 다시 내보내야 한다.

- 모델의 자세·비율을 크게 바꾸면 기존 팔 경계식과 중심선·기준점을 다시 정해야 한다.
- 이번 처리와 미리보기 보조 스크립트는 임시 작업 파일로 실행했다. 저장소에 정식 재내보내기 도구나 빌드 단계로 등록한 상태는 아니다.
- 에셋의 수정·배포·상업적 이용 조건은 출시 전에 원본 제공 조건에 따라 확인해야 한다. 저장소의 코드 라이선스가 외부 에셋의 권리를 자동으로 정하는 것은 아니다.

## 12. 후속 형상·자세 보정

### 적용 내용

- 남성: 원본의 골반·허리가 머리·가슴 중심선에서 옆으로 벗어나 보이는 부분을 높이별 수평 이동으로 교정했다. 팔에는 몸통 높이별 이동을 그대로 적용하지 않고 어깨 기준 이동을 사용해 손목을 보존했다.
- 공통: 머리 폭을 약 8% 줄이고 깊이는 남성 약 5% 증가, 여성 약 6% 감소시켰다. 얼굴의 국소 디테일을 약하게 평활화하고 목에서 부드럽게 이어지도록 턱 방향을 남성 약 3도 위쪽, 여성 약 5도 아래쪽으로 조정했다.
- 여성: 팔을 어깨 주변에서 최대 약 21도 내리고 다리 간격을 줄여 남성과 가까운 선 자세로 변경했다. 팔다리 두께나 성별에 따른 신체 특징을 같게 만드는 작업은 하지 않았다.
- 남성의 주먹과 여성의 펼친 손, 합쳐진 속옷은 유지했다. 자동 좌우 표면 대칭은 손목·가랑이 수축을 일으켜 최종 결과에 적용하지 않았다.
- 카메라와 Swift 소스는 변경하지 않았다. 같은 이름의 Blender 경량화 사본과 앱용 JSON을 갱신했으며 고밀도 원본은 보존했다.

### 재내보내기 주의

보정 사본에는 `WEASHION_Arm` 정점 그룹과 `weashion_regions`, `weashion_shoulder_width`, `weashion_style` 오브젝트 속성을 추가했다. 팔을 내린 뒤에는 최초 A 포즈용 위치 분류식을 다시 적용하면 안 되며, 이 가중치와 영역을 내보내고 중심선은 변경된 표면에서 다시 추출해야 한다. 앱은 내보낸 배열을 기존 JSON 형식으로 읽는다. 정점 그룹은 편집·내보내기용이며 관절 리그나 Shape Key가 아니다.

이번 후보 생성과 내보내기 역시 임시 Blender 작업 스크립트를 사용했다. 3.2절의 경량화 표면 오차는 형상 보정 전 측정치이며, 의도적으로 자세와 비율을 바꾼 현재 사본의 원본 대비 오차로 사용하지 않는다.

## 13. 얼굴 없는 단순 마네킹과 정면 대칭 재구성

### 형상 변경

- 이전 보정 후에도 남성이 정면에서 삐딱하게 보인다는 피드백에 따라, 일부 단면 중심의 수평 이동만으로 자세 보정을 완료했다고 보지 않고 전신 형상을 다시 다뤘다.
- 남성 몸통의 높이별 단면에서 가로축의 수평 회전을 추정해 교정했다. 기존 사본에서 추정된 회전은 약 0.34~3.21도였으며, 이는 단면 주축의 값이지 관절 회전의 실측치가 아니다.
- 남녀 모두 오른쪽 반신을 중앙선에서 반사하고 결합한 뒤 대칭을 유지하며 약 20,000삼각형으로 줄였다. 이전의 최근접 표면 투영 방식과 달리 한쪽 형상 자체를 복제하므로 손목·가랑이를 반복 투영으로 수축시키지 않는다.
- 기존 얼굴·귀 표면은 제거하고 목 둘레에 공통 비율의 매끈한 타원형 머리를 연결했다. 눈·코·입·귀 묘사는 없다. 몸통은 타원형 단면에 가깝게 정리하고 근육·배꼽·중앙 주름과 급격한 단면 굴곡을 완화했다. 손가락 자세와 합쳐진 속옷 윤곽은 남아 있다.
- 메시 연결이 바뀌었으므로 팔 가중치와 면별 부위 번호를 다시 저장하고 팔다리 중심선을 새 표면에서 추출했다. `WEASHION_Arm` 그룹 인덱스는 Blender 수정자 적용 후 최종 메시에서 다시 조회한다.

### Swift 중앙선 변형 수정

에셋 자체는 대칭이었지만 실제 `MannequinMesh.fitted(to:)` 결과를 반사 비교하자 남성 중앙선에서 최대 약 10.47mm의 차이가 발견됐다. `point.x < 0 ? -1 : 1`은 `x = 0`인 정점을 오른쪽 다리 중심선으로 처리해, 다리 간격·굵기 보정 시 중앙선도 오른쪽으로 이동시켰다.

중앙선은 `side = 0`, 좌우 정점은 각각 `-1`, `1`로 처리하도록 수정했다. 카메라나 성별별 화면 회전은 변경하지 않았다.

### 최종 데이터 및 확인 범위

| 항목 | 여성 | 남성 |
| --- | ---: | ---: |
| 정점 / 삼각형 | 9,998 / 19,992 | 9,986 / 20,000 |
| Blender 파일 크기 | 546,661 bytes | 572,948 bytes |
| 앱 JSON 크기 | 677,803 bytes | 685,105 bytes |
| 기본 체형 가슴둘레 | 약 98.000cm | 약 97.945cm |
| 기본 체형 허리둘레 | 약 82.000cm | 약 82.002cm |
| 기본 체형 엉덩이둘레 | 약 98.000cm | 약 98.000cm |
| 충돌 밴드 / 오른팔 단면 | 120 / 21 | 116 / 21 |
| Swift 변형 후 최대 좌우 반사 정점 오차 | 0mm | 약 0.002mm |

Blender 후보의 경계 변·비다양체 변은 모두 0이며, JSON 반올림 후와 Swift 변형 후의 퇴화 삼각형도 0이었다. 수정된 실제 Swift 변형 코드를 임시 macOS 실행 파일로 다시 컴파일하고 기본 175cm 체형의 로딩·변형·충돌 밴드 생성을 확인했다. 최종 위치 데이터를 같은 카메라 조건에서 정면·측면·후면으로 렌더링해 비교했다. 좌우 대칭은 자세 정렬을 확인하는 근거이며 정확한 해부학적 자세나 다른 모든 치수의 결과를 보장하지 않는다.

확인된 후보를 기존 Blender 사본과 앱 번들 JSON에 반영했다. 파일명의 `40k`는 연결 호환을 위해 유지했으며 현재 삼각형 수는 위 표를 따른다. 고밀도 Meshy 원본은 변경하지 않았다. 후보 생성·내보내기·렌더링 도구는 임시 작업 스크립트이며 저장소에 추가하지 않았다. 이전 절들의 수치는 각 시점의 이력이고, 현재 상태는 이 절을 기준으로 한다.

이번에도 앱 전체 빌드·실기기 설치·RealityKit 화면 확인·새 의류 착장은 수행하지 않았다. Swift 변형 결과를 Blender로 확인한 것과 실기기 앱 검증은 구분한다. 이번 후속 변경의 커밋·푸시는 수행하지 않았다.
